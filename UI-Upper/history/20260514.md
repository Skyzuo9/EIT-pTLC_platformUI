# 2026-05-14 修改记录

## Scheduler 并发模式 + PrepLock/GroupLock 互斥改造

1. **修改目标**：在 parallel 分支上将 Scheduler 从串行 `await _run_one()` 改为并发任务池 `create_task()` + `asyncio.wait(FIRST_COMPLETED)`，同时引入 PrepLock（全局 Expand FSM 串行化）和 GroupLock（组级流路互斥），实现多样品并发调度。
2. **核心改动**：
   - `scheduler.py`：`run_until_empty()` 从串行改为并发任务池；新增 `_active: dict[str, asyncio.Task]` 跟踪并发任务；新增 `_enqueue_evt: asyncio.Event` 入队唤醒机制（解决 asyncio.wait 无法感知新入队样品的 bug）；新增 `active_sample_ids()` 属性
   - `develop.py`：新增类级 `_prep_lock`（asyncio.Lock，全局1把）和 `_group_locks`（dict[int, asyncio.Lock]，每组1把）；Phase 1 持双锁（prep_lock + group_lock）执行 prep；Phase 3 持 group_lock 执行排液；Phase 2/4 无锁
   - `resource_manager.py`：`allocate()` 从抛 RuntimeError 改为 `asyncio.Condition` 等待释放通知；提取 `_try_allocate()` 内部方法；`release()` 调用 `notify_all()` 唤醒等待者
   - `queue.py`：移除 `active_develop_stage` 互锁检查（后因 Code Review 恢复）
   - `debug.py`：新增 PrepLock + GroupLock 占用检测提示
   - `state.py`：新增 `scheduler_active_stages: dict` 字段

## 并发调度失效根因修复：_enqueue_evt + GroupLock 错配

1. **修改目标**：修复用户实验中两个样品仍串行执行的 bug。
2. **根因分析**：
   - `_enqueue_evt`：`asyncio.wait(FIRST_COMPLETED)` 只监听 `_active` 中的任务，不监听队列。当 B 在 A 运行期间入队时，B 坐在 queue 里但 scheduler 被阻塞在 wait，无法感知新样品。
   - GroupLock 错配：Phase 1 中 `allocate()` 在锁内部执行，但锁基于偏好缸的组获取。当 RM 降级分配到不同组的缸时，持有的是错误组的锁，流路互斥保护失效。
3. **核心修复**：
   - `scheduler.py`：`enqueue()` 时 `_enqueue_evt.set()`；`run_until_empty()` 中创建 `enqueue_watcher` task 加入 wait set；watcher 完成即回顶部 drain 新样品
   - `develop.py`：将 `allocate()` 从锁内部移到外部，先确定实际缸号和组，再获取正确的组锁；降级分配时用 `translate_params({**params, "target_tank": allocated})` 重算 channels（含泵地址）

## CollectStage 类级互斥锁修复：并发收集流程报错

1. **修改目标**：修复多样品并发入队时收集流程全部报错的 bug（6个展开样品正常，3个仅收集样品全部出错）。
2. **根因分析**：PLC 收集工位是单实例状态机（一组 `collect_*` 变量），但 CollectStage 无并发互斥锁。3 个 CollectStage 实例同时驱动导致：(a) 参数互相覆盖——`collect_forward_instructions`/`collect_count` 只有一份；(b) Enable 信号打架——A 写 True 后 B 写 False 复位，PLC 状态机无法启动或被中途复位；(c) Done 标志竞争——一个阶段消费 Done 后清 Enable，其他阶段再也等不到 Done → 超时报错。DevelopStage 有 `_prep_lock` 保护而 CollectStage 无锁。
3. **核心改动**：`collect.py`：新增类级 `_collect_lock: asyncio.Lock = asyncio.Lock()`；`run()` 方法中 `start_stage` + `await_stage_done` 整体包裹在 `async with CollectStage._collect_lock:` 内；`translate_params` 和 channels 构建保持在锁外（纯计算，不需互斥）；新增 `import asyncio` 和 docstring 并发安全说明。
4. **实验结果**：语法验证通过；import 链路和 STAGE_REGISTRY 正常
5. **Code Review 结论**：6 维度审阅全部通过——asyncio.Lock 类级声明安全（Python 3.10+ 惰性绑定事件循环）、锁粒度正确、与 DevelopStage._prep_lock 完全对齐、无残留状态问题、闭包变量捕获正确
