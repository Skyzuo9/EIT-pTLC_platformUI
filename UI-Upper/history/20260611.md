# 2026-06-11 实验日志

## 修改目标
新增图像-板物理朝向归一化（新工位相机视角与旧工位相反），并重构样品取消逻辑——按第一性原理 + 奥卡姆剃刀撤销前一版本中"上位机代理操作 PLC FSM"的清理代码，将取消职责收敛为"上位机仅释放自身资源 + 用户人工 PLC HMI / Recovery Reset"。

## 核心改动
- **视觉视角归一化**：`VisionCfg` 新增 `image_plate_orientation`（rot0/rot90cw/rot180/rot270cw）/ `auto_rectify_tilt` / `rectify_min_angle_deg` 三字段，`_parse_vision` 校验取值集合；`config.example.yaml` 新工位默认 `rot180 + auto_rectify_tilt=true`；`tlc_analyze.process_pair` 已有形参直接接入。
- **vision_cfg 贯通**：`vision_service.py` 新增 `build_vision_from_cfg()` 工厂；`main.py`（stress/collect/pltc-terminal 三处）+ `ui/app.py` + `ui/sections/vision.py`（_on_analyze + _load_existing_analysis）共 6 处构造点统一调用 helper，删除 `getattr(..., 'rot0') if state.vision_cfg else 'rot0'` silent fallback；vcfg=None 时 fail-fast 抛错。
- **取消逻辑——撤销过度设计**：`stages/spotting.py / develop.py / collect.py` 删除前一版本 `try/except BaseException + 读 Step + 写 Enable=False + 10s 轮询`（违反 PLC 单写者契约且与硬件运动抢控制权），三个文件相对 HEAD 0 字节 diff。
- **取消逻辑——上位机本职**：`consumable_manager.py` 新增 `rollback_for_sample()`（TAKEN→AVAILABLE，幂等）；`task.py` `except CancelledError` 调用 rollback 并用 `asyncio.shield` 包裹避免取消传播打断。
- **NiceGUI dialog 修复**：`ui/sections/queue.py` 取消按钮覆盖 PENDING / WAITING / RUNNING 三态；`_cancel_sample` 改为 sync wrapper 返回 coroutine 由 NiceGUI 在事件 slot context 内 await（替代原 `asyncio.create_task` 丢失 slot 的踩坑实现）；dialog 文案重写明确"PC 仅释放资源 / PLC 侧用户人工 HMI/Reset"职责边界。
- **AGENTS.md**：Recipe Default Drift 表追加 vision 两行；新增 "Runtime Cancel Semantics" 小节明确 PC/PLC 职责划分与 asyncio.Lock 自动释放的语言保证。

## 已知问题
- DevelopStage Phase 2/3/4（展开等待 / 排液 / handoff）的取消语义仅文档化为"任硬件跑完 + finally 兜底 NEEDS_DRAIN + 用户人工处理"，未做代码级覆盖；若 Phase 3 排液中途取消，硬件阀门时序由 PLC 自跑，无 PC 干预。
- `rollback_for_sample` 仅恢复 staging slot，对 Step 30+ 期间硬件已物理消费但任务取消的极端场景，账本会与物理状态短暂背离（但硬件实际拿走板后正常路径会续走 on_*_done 关闭账本，仅在 cancel 卡在 Step 30+ 中间时有窗口）；用 Recovery Tab Handoff Orphan 流程兜底。
- 新工位 `rot180` 与 `auto_rectify_tilt=true` 是 example.yaml 默认；旧工位升级时若直接用 example 重建配置会改变图像分析行为，需按 AGENTS.md Default Drift 表显式回退到 `rot0`。
