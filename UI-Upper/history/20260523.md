# 20260523 实验记录

## 修改目标

P2-1：实现日志持久化功能，将 LogStore 的内存事件流异步落盘为 JSONL，预留未来 SQLite 迁移点。同步落地 impact 视角代码审阅发现的 W1/W2 两处修复。

## 核心改动

1. **新增 `core/log_persistence.py`**：`LogSink` Protocol + `JsonlFileSink` + `LogPersistence` 三层抽象。`enqueue()` 同步零阻塞（`asyncio.Queue.put_nowait`，队列满 log.warning 丢弃），后台单 writer task 按 `flush_interval=0.5s` / `batch_size=10` 触发，I/O 全部 `asyncio.to_thread()`。双轨存储：`data/samples/<id>/logs/run_<μs时间戳>.jsonl`（按 ENQUEUED 切分）+ `data/logs/by_date/YYYYMMDD.jsonl`（日期软索引）。无主事件兜底到 `data/samples/_system/logs/`。启动时一次扫描 `archive_old_by_date_files()` 把 mtime > N 天的 jsonl 压缩为 .jsonl.gz。

2. **改造 `core/log_store.py`**：`__init__(persistence=None)` + `attach_persistence()` + `append()` 末尾 `enqueue` 一行（外层 try/except 兜底，崩溃保护）。新增方法签名为 `Optional["LogPersistence"]`，传 `None` 表示解绑（W2 修复）。

3. **生命周期接入**：`ui/app.py` `_scheduler_background_task` 在 `state.sample_store` 初始化后启动 persistence、attach 到 LogStore；`finally` 中 `await persistence.stop()` → `state.log_persistence=None` → `state.log_store.attach_persistence(None)`。`main.py` 的三种终端模式（stress/collect/pltc-terminal）各自 try/finally 调 `_start_persistence` / `_stop_persistence` helper，UI 模式由 `_scheduler_background_task` 自启动（避免重复）。

4. **配置与默认**：`config.py` 新增 `LoggingPersistenceCfg`（enabled/flush_interval_sec/batch_size/archive_older_than_days）+ `_parse_logging` parser。`config.example.yaml` 增 `logging.persistence` 段。`AppState` 增 `log_persistence` 等 5 个字段。`run_ui` / `run_batch4` 透传持久化参数。

5. **W1 修复 — `_system` 兜底目录排除**：`SampleStore.list_samples()` 把 `_system` 加入排除集合（与既有 `debug` 同等待遇），防止 Vision Tab 下拉出现"假样品"。

6. **W2 修复 — LogStore 停服解绑**：`attach_persistence` 类型签名改为 `Optional["LogPersistence"]`；`ui/app.py` `finally` 在 `persistence.stop()` 后追加一行 `state.log_store.attach_persistence(None)`，防止后续独立 PLC 重连等路径写日志时塞向已停队列。

7. **占位脚本** `scripts/migrate_logs_to_db.py`：仅文档注释，列出未来 JSONL → SQLite 迁移路径（创建表 → 遍历 by_date/*.jsonl(.gz) → executemany INSERT → 实现 SqliteSink 替代 JsonlFileSink），main() 仅打印占位提示。

8. **`.gitignore`**：新增 `data/logs/` 与 `data/samples/_system/`，避免运行时日志污染版本库。

## 已知问题

- **未运行联调**：本轮仅静态校验，未启动 mock 服务跑通"样品入队 → JSONL 落盘 → by_date 内容一致"验证清单。下次启动时需检查：(a) `data/samples/<id>/logs/run_*.jsonl` 是否生成；(b) `data/logs/by_date/YYYYMMDD.jsonl` 是否包含同样品事件；(c) 进程异常退出最近 ≤0.5s 事件丢失窗口；(d) `enabled: false` 是否回到纯内存模式。
