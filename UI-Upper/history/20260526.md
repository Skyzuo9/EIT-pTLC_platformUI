## 修改目标

按 `UI-Upper/plans/database_ui_plan.md` 把数据库 UI 拓展计划 Phase 1~5 整体闭环，并解决之前若干 metadata 覆写、G-code 标定参数硬编码、SampleStore 路径越界、UI 全局页宽过窄等历史遗留隐患。本次提交在 `2026-05-25 已接入 SQLite 二级索引层` 基础上推进，覆盖：历史样品 Tab、样品对比 Dialog、JSONL 运行日志查询、Dashboard 统计卡片、数据生命周期管理（软删/硬删/RecipeTask 自动落库），以及 G-code 标定参数 config 化。

## 核心改动

1. **新增「历史样品」Tab（`ui/sections/history.py` ~857 行 / `ui/sections/compare.py` ~211 行）**
   - 主页面：左列筛选条（配方下拉 / 起止日期 / sample_id 子串 / 含已删除）+ 多选样品表格 + 操作栏（对比选中、软删/还原/硬删按钮）；右列单选时呈现 before/after/标注图三图 Tab + bands 表 + 运行日志区。
   - 顶层 `ui.row` 设 `h-[calc(100vh-200px)]`，左右两列各自 `overflow-y-auto` 独立滚动。
   - `compare.py` 入口 `open_compare_dialog(sample_ids)`：全屏 `ui.dialog().props("maximized")` + `ui.grid(columns=2)` 2~4 单元格，每格内置三图 Tab + 「全部切到标注图」按钮，DB 缺失走文字占位。
   - `pages.py` 在 Vision 与 Debug Tab 之间插入 `tab_history`。

2. **运行日志查询模块（`core/log_query.py` 新增 121 行）**
   - `load_sample_logs(sample_id, samples_root)` 直读 `<samples_root>/<sample_id>/logs/*.jsonl`，文件名升序等价于时间序，单样品封顶 5000 条；`asyncio.to_thread` 包裹 I/O 不阻塞事件循环。
   - `filter_logs(entries, event_filter, search_text)` + `list_unique_events()` 支持详情面板「运行日志」区的事件下拉 + 文本搜索 + 计数。
   - Schema 与 `core/log_persistence._entry_to_jsonl` 完全对齐（ts/sample_id/event/detail/extra），未来 SqliteSink 接入后只需替换数据源。

3. **Dashboard 统计卡片（`core/database.py` + `ui/sections/flow.py`）**
   - `DatabaseService.get_statistics()`：返回 `total_samples / today_samples / total_bands / top_recipe`，全部排除已软删样品（`deleted_at IS NOT NULL`），`today_samples` 用 `date('now', 'localtime')` 与 `created_at` 的 `date()` 匹配避免 UTC 偏移误判。
   - Flow Tab dashboard 视图顶部插入 4 张统计卡片（总样品/今日/总 Band/配方 Top1），`ui.timer(30.0, ...)` 全局节流；非 dashboard 视图 `_dash_cards.get("stats")` 为 None 自然 no-op。
   - 加载中以「—」占位（避免 0 被误读为真实数据），DB 未启用时顶部出现「数据库未启用」提示条。

4. **数据生命周期管理（`core/database.py` Phase 5 系列）**
   - Schema 演进：`samples` 表增 `deleted_at TEXT`，`start()` 中 `try/except` 幂等 `ALTER TABLE ADD COLUMN`（SQLite 无 IF NOT EXISTS）。
   - `list_samples(filter, *, include_deleted=False)`：默认过滤软删；新增 4 字段筛选（recipe_name 精配 / date_from / date_to / id_substring LIKE）。
   - `list_recipes_used()` / `get_statistics()` / `get_sample_disk_info()` / `soft_delete_sample()` / `restore_sample()` / `hard_delete_sample()` 全部加 `deleted_at IS NULL` 口径，避免 Dashboard 与 History Tab 显示口径漂移。
   - SQL 别名 `r` 不可在 WHERE 中使用（SQLite 执行顺序 FROM→WHERE→SELECT），`list_recipes_used` / `get_statistics` 内部 WHERE 重复 json_extract 表达式。

5. **RecipeTask 运行时自动落库（`core/task.py` Phase 5A）**
   - `RecipeTask.run()` 成功出口处调用 `sample_store.save_metadata({sample_id, recipe_name, completed_at, enabled_stages})`，触发 fire-and-forget DB upsert；不含 vision 阶段的 recipe（如 spotting-only）也能被历史样品 Tab 收录。
   - 异常路径 `try/except` 仅 log.warning，不阻塞主流程。

6. **`SampleStore.save_metadata` 改为读-改-写合并**
   - 老语义「后写者赢」会让 RecipeTask（写 recipe_name/completed_at/enabled_stages）和 Vision Tab（写 selected_bands/gcode_path）互相抹掉；改为先读旧 metadata.json，新字段叠加旧字段、`updated_at` 永远刷新、`created_at` 旧值优先。
   - 旧文件读取异常（OSError / JSONDecodeError）记录 warning 后回退覆写。

7. **`SampleStore.get_sample_dir()` 路径越界防御**
   - `(self._root / sample_id).resolve()` 后用 `relative_to(self._root.resolve())` 校验；包含 `..` 或绝对路径的非法 `sample_id` 抛 `ValueError`，避免被后续 `shutil.rmtree()`（硬删路径）越界删除。

8. **G-code 真机标定参数 config 化（新增 `gcode:` 配置段）**
   - `core/config.py` 新增 `GCodeCfg(origin_corner, plate_origin_x, plate_origin_y)` + `_parse_gcode`，`origin_corner` 仅允许 `lower-left / top-right / top-left / bottom-right`，非法值抛 `ValueError`。
   - `config.example.yaml` 增 `gcode:` 段；`main.py` `run_batch4` / `run_from_config` 透传；`ui/state.py` `AppState.gcode_cfg`；`ui/app.py` `run_ui()` 入口注入。
   - `core/gcode_generator.py` `GCodeGenerator.generate()` 增 `origin_corner` 形参并透传给 `tlc_to_gcode`。
   - `ui/sections/vision.py`（`_on_generate_gcode` / `_regenerate_gcode_preview`）+ `core/stages/scrape.py`（`_generate_gcode` / `_generate_gcode_for_band`）从 `state.gcode_cfg` 读取并透传，`gcode_cfg=None`（终端模式 / 极端场景）回退代码默认值。

9. **ScrapeStage `_generate_gcode` 安全契约收紧**
   - 删掉「失败时从 `VisionResult.x/y` 拼凑 4 行伪 G-code」的回退分支——在未经标定的坐标系下下发动作比安全占位危险。
   - 异常 / 无 AnalysisResult → 返回 `None` → 上层下发 `SAFE_PLACEHOLDER_GCODE`（`G0 Z10\nM2\n`），PLC Step 30 自动跳过实际刮取动作。

10. **DatabaseService 生命周期与 PLC 解耦**
    - `ui/app.py` 把 `SampleStore` + `DatabaseService` 启动从 `_scheduler_background_task` 提到 `@nicegui_app.on_startup`，停止挂到 `@nicegui_app.on_shutdown`。
    - 历史样品 Tab 在未连 PLC 状态下也能读取 DB 索引；模式仍由 `database.enabled` 总开关控制。

11. **UI 全局页宽 max-w-3xl(768px) → max-w-screen-2xl(1536px)**
    - `ui/app.py` 一处 className 改动；所有 Tab（Queue/Recipe/Flow/Vision/History/Debug/Recovery）同步拓宽，1920px 等宽屏不再压在中间。

12. **Vision Tab G-code 生成失败 UI 一致性**
    - `_on_generate_gcode` 异常路径补充：清空 `gcode_textarea` / `gcode_path_image` / `state.vision_gcode_text` / `state.vision_gcode_path`，避免用户看到上一次预览误以为可用。

13. **`develop_pump_translator.py` 泵速度调整**
    - `ASP_SPEED 1500 → 100` / `DISP_SPEED 500 → 100`：实机调参后保留更稳的吸/打液速度（与 Phase 5 联调期间观察一致）。
