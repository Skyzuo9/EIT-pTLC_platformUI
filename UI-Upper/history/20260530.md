# 20260530 实验记录

## 修改目标

落地 **耗材管理 v2（板级 DI 防呆 + 孔级账本双轨）** 全链路 + **PLC 协议 v2.3 耗材接口**，并把上位机长等待语义从「超时放弃」改为「提示间隔，继续等待」，让真机调试期 PLC 推进偏慢的样品不会被误判 ERROR。同时清扫 DONE 缸残留绑定、对齐泵翻译器命令终止符、补全 Debug Tab CODESYS 转义。

## 核心改动

1. **`core/consumable_manager.py`（+357 行）**：板数 8→12（A-L），孔数 48→72；新增板级 DI `_plate_present`（仅防呆）与孔级账本 `_rack`（实验员录入 + 决策消耗）双轨；新增 `mark_plate_loaded` / `mark_plate_emptied` / `mark_slot_loaded` / `mark_slot_used` 录入接口与 JSON write-through 持久化（`data/consumable_state.json`，原子替换）；新增 `ConsumablePlateMissingError`；`prepare_for_scrape/collect` 同时校验账本可用孔 + DI 在位，任一缺失即报错；`detect_inconsistencies()` 输出告警板号。
2. **`ui/sections/consumable.py`（新增 537 行）+ `pages.py` + `flow.py` + `recipe.py` + `state.py` + `app.py`**：新增 Consumable Tab（4 层 × 3 板位 + 暂存 A/B + 顶部告警条 + dialog 守卫）；Flow Tab Dashboard 新增耗材状态卡片（粉末/玻璃 progress bar + 暂存余量提示 + "查看详情" 按钮跳 Tab）；Recipe Tab 新增「耗材偏好」折叠区（粉末/玻璃 dropdown，"自动" 默认）；`AppState.consumable_manager` 注入；`ui/app.py @on_startup` 初始化 ConsumableManager 并加载持久化账本；`_periodic_refresh` 每 2s 从 PLC 读 `Consumable_Sensor` 同步 12 板 DI（不动账本）。
3. **`core/plc_client.py`（+97 行）+ `mock/plc_server.py`（+122 行）**：协议 v2.3 接口新增 5 个变量 `scrape_Fetch_Rack_Plate / scrape_Consume_Slot / collect_Fetch_Rack_Plate / collect_Consume_Slot / Consumable_Sensor[12]`；新增 `REQUIRED_CONSUMABLE_VARS` 启动期自检（缺失即 `log.error`）；Mock 同构声明 + 控制台 `consumable fill|clear|plate <N> on|off|status` 命令；Mock scrape/collect FSM 新增 Step 12（动作 A 搬板）/ Step 13（动作 B 取耗材）hook。
4. **PLC 长等待语义变更**：`await_stage_done` / `await_stage_step` / `await_drain_done` 的 `timeout` 改为「提示间隔」——超时仅 `log.warning` + UI 通知（走 `state._notification_queue` 复用 `_warn_long_wait` 辅助函数）后继续轮询，**不再抛 TimeoutError**；故障态（Step=90）触发兜底清理：`async with self._lock: await self._write(enable_name, False)` 让 PLC FSM 归零。
5. **`core/resource_manager.py`**：`sync_states()` 末尾扫描 DONE(99) 缸自动调 `release_tank()` 归 IDLE，兜底 PLC 上次运行残留绑定 / Phase 4 异常未释放路径；`TankStatus` 补 `BLOW_AIR=55 / CYLINDER=60 / ROBOT_PICKUP=65` 三个排液子步，与 Flow Tab `_TANK_STATUS_STYLE` 配色映射同步。
6. **`core/stages/develop.py`**：`STAGE_TIMEOUT = 600.0`（rinse + 上液多次泵操作实测可超 300s）。
7. **泵翻译器命令终止符 `$R` → `\r`**：`scripts/develop_pump_translator.py` / `scripts/pump_translator.py` / `scripts/sample_pump_translator.py` 全部把 DT 协议命令尾部从 CODESYS 转义符 `$R` 改为真实 ASCII 回车 `\r`（PLC 侧转义只在 STRING 字面量内生效，运行时拼接的字符串需用真实控制字符）。
8. **`ui/sections/debug.py`**：写入框 STRING 类型支持 CODESYS 转义解析：`$R→\r / $N→\n / $$→$ / $P→FF / $L→\n`，placeholder 改为 "BOOL: True/False | 数值: 直接输入 | STRING: $R=回车 $$=$"。
9. **`recipes/standard_pTLC.yaml` + `core/recipe.py`**：新增 `consumable_preference` 段（`powder_plate / bottle_plate`，null=自动），`RecipeTemplate` 字段同步 + `recipe_from_dict / recipe_to_dict` 透传。
10. **`tests/test_consumable_manager.py`（+587/-385 行）**：全量重写测试，覆盖板级 DI / 孔级账本 / 持久化 / 异常路径 / 取板失败回退。
11. **AGENTS.md**：`consumable_manager` Key Module 行更新到 v2 双轨语义（板级 DI + 孔级账本 + 持久化路径 + `detect_inconsistencies`）。

## 实验结果

- mock 全链路：Consumable Tab 渲染 12 板 × 6 孔 + 暂存 A/B 正常；`mark_plate_loaded(default=6 孔满)` → `prepare_for_scrape` 取板 → `on_collect_done` → 暂存翻 FILLED；JSON 落盘 `data/consumable_state.json` 重启后状态恢复。
- mock 控制台 `consumable fill/clear/plate 3 off/status` 切换 DI，`detect_inconsistencies` 顶部告警条按需出现/消失。
- mock scrape FSM 走 `10 → 12 → 13 → 20 → 30 → 40` 闭环，PC 决策值 `scrape_Fetch_Rack_Plate / Consume_Slot` 在 Step 12/13 hook 中正确读出。
- 长等待语义：mock 控制台手动卡 collect_Step 不推进，UI 每 N 秒弹「⏳ collect 工位已等待 60s」warning，样品保持 RUNNING 不被误标 ERROR。
- DONE 缸自动释放：mock 模拟 PLC 残留 Tank_State[3]=99（无样品绑定）→ 下一次 sync 周期内 RM 自动写 release_tank 归 IDLE。

## 已知问题

- Phase 4 决策接入 `prepare_for_scrape/collect` 仍未连到 ScrapeStage / CollectStage 真实下发路径（当前只完成 v2.3 PLC 变量声明 + UI 录入 + Mock FSM 演示，PC 决策侧只在 mock 控制台跑通）。
- 4 个 G-code 调用点的 17-kwargs 字段展开模板未做收敛（独立优化项）。
- 长等待语义改为不抛 Timeout 后，**单元测试 / 离线脚本** 路径下若 PLC 永远不推进会无限循环——后续需要在 `scripts/test_*.py` 类一次性脚本里显式提供取消机制（如 asyncio.timeout 上层包裹）。
