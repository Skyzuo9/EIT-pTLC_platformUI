# 2026-05-12 修改记录

## Web UI 手机端局域网访问调试

1. **问题现象**：`ui/app.py` 已配置 `host="0.0.0.0"`、`port=8080` 启动 NiceGUI，PC 本机 `localhost:8080` 可访问，但同一 WiFi 下的手机无法打开页面。
2. **初步排查**：放行防火墙入站规则 `New-NetFirewallRule -DisplayName "pTLC NiceGUI 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow`，并将 WLAN 网络类别由 Public 改为 Private，手机仍无法访问 `http://192.168.132.1:8080`。
3. **根因定位**：`Get-NetIPAddress` 显示 `192.168.132.1` 属于 PC 上的虚拟网卡（vEthernet / Hyper-V / VMware 之一），该网段为本机孤岛，手机不在同一子网自然路由不到；真正对外的是 WLAN 网卡从 iPhone 热点获得的 DHCP 地址 `172.20.10.3`。
4. **验证结果**：手机浏览器访问 `http://172.20.10.3:8080` 成功加载 pTLC Web UI，端到端联通。
5. **经验沉淀**：排查局域网访问问题必须先用 `Get-NetIPAddress -AddressFamily IPv4` 过滤掉 Loopback / vEthernet / VMware / VirtualBox / WSL 等虚拟网卡，取真实 WLAN 网卡的 DHCP IPv4 地址作为对外访问入口。

## 当前配置风险评估

- **风险 1：服务无鉴权公开暴露**。NiceGUI 监听 `0.0.0.0:8080` 且防火墙放行了任意来源（`Profile=Any`），任何与 PC 同网段设备都可直接访问、查看状态、触发 Queue 入队与 Debug Tab 受限写入；在实验室 WiFi / iPhone 热点场景风险可控，但切到公共 WiFi 或公司大网段会直接对外暴露控制面。建议长期改为：`Profile=Private` 或 `-RemoteAddress 172.20.10.0/28` 限定来源，并视需要在 UI 侧加一层登录。
- **风险 2：HTTP 明文传输**。UI 未启用 TLS，所有交互（含人工确认、Debug 写入请求）可被同网段抓包；当前小范围调试可接受，后期对外演示或接入现场网络前建议前置反向代理（Caddy/Nginx）启用 HTTPS。
- **风险 3：iPhone 热点依赖**。当前对外 IP 由 iPhone 热点动态分配（`172.20.10.x`），手机息屏/重连后 IP 可能变化，需要重新查 IP；生产环境建议接入固定 AP 并给 PC 配静态 IP 或路由器做 MAC 绑定。
- **风险 4：防火墙规则范围过宽**。已添加的规则 `Profile=Any` 对 Public 网络也生效，若 PC 接入咖啡厅等公网会暴露端口；建议改为 `Set-NetFirewallRule -DisplayName "pTLC NiceGUI 8080" -Profile Private` 收敛。
- **结论**：调试阶段可接受，继续使用当前配置即可；投产前建议按上述 4 条做一次加固。

## PLC 实机变量快照显示不全修复

1. **问题现象**：连接汇川 PLC 实机后，UI 变量实时快照仅显示 7/14 个变量，且 `datachange_notification` 回调全部失效；入队后调度器执行因缺少 `Action_ID`/`PC_Trigger` 等旧握手变量而报错；`_deferred_enqueue` 中 `ui.notify()` 触发 NiceGUI slot stack 为空 RuntimeError。
2. **根因分析**：
   - 汇川 PLC OPC UA 节点 `nodeid.Identifier` 为数字型（如 `ns=4;i=15`），原代码用 `var_name in str(name)` 子串匹配必然失败
   - `collection_step` 废弃变量名残留，实机 PLC 实际变量名为 `collect_Step`
   - `collect_Step`/`collect_count` PLC 声明为 `INT`（对应 Int16），NODE_TYPES 错误地声明为 Int32
   - 实机 PLC GVL 仅暴露 7 个变量到 OPC UA（共声明 14 个），PLC 侧 OPC UA 发布配置不完整
   - NiceGUI 后台 Task 中直接调用 `ui.notify()` 会触发上下文错误
3. **核心修复**：
   - `variable_monitor.py`：新增 `_node_name_map` 字典，订阅时注册 `id(node)→var_name` 映射，`datachange_notification` 回调直接查表替代 Identifier 子串匹配；新增 `auto_discover()` 自动扫描 GVL 全部变量并扩展订阅；订阅失败日志从 `debug` 提升至 `warning`
   - `plc_client.py`：删除废弃 `collection_step`；`collect_Step`/`collect_count` 类型 Int32→Int16；新增 `bOutput`/`bEnable`/`bErrorReset`/`bStepEnable` 四个实机变量
   - `queue.py`：`_deferred_enqueue` 中 `ui.notify()` 替换为 `_queue_notify()` 通知队列模式
   - `state.py`：新增 `_notification_queue` 属性
   - `debug.py`：timer 中新增消费 `state._notification_queue` 逻辑
   - `app.py`/`header.py`：`_poll_loop` 改为遍历 `polled.items()` 同步全部变量；`collection_step`→`collect_Step` 引用修正
   - `mock/plc_server.py`：同步删除 `collection_step`，类型 Int32→Int16，新增 b 前缀变量
4. **已知问题**：实机 GVL 仅 7 变量暴露到 OPC UA，PLC 侧需配置所有变量发布后 `CollectStage.start_stage()` 才能正常工作
5. **后续计划**：在 PLC 工程中为所有 GVL 变量启用 OPC UA 发布，重新编译下载后验证完整闭环
