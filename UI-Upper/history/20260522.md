# 20260522 实验记录

## 修改目标

修复 Vision Tab 自动/手动条带选择模式的状态不一致 bug + 审阅驱动的逻辑简化。

## 核心改动

1. **B1 修复 — `_on_sample_change` 乒乓守卫**：切换到正在乒乓等待的样品时跳过 `_clear_vision_state()`，防止 ScrapeStage 已预设的 `vision_selected_bands` 和 `vision_band_selection_mode` 被覆盖。根因：用户点击跳转到乒乓样品时，无条件 clear 导致 mode 从 auto 重置为 manual，auto 15s 超时永远不触发。

2. **B2 修复 — auto/manual 超时语义分流**：auto 超时（15s）自动选最大面积 band + 正常生成 G-code 下发；manual 超时（300s）下发 SAFE_PLACEHOLDER_GCODE 安全占位。

3. **C1 — 历史回看时禁用 selection_mode radio**：`refresh_vision()` 按 `view["owner_scrape"]` 切换 radio enabled，非乒乓样品视图下禁用，防止误触发 `_send_to_plc`。

4. **C2 — refresh_vision 指纹脏检查**：以 `(case_name, len(bands), mode, tuple(selected_bands))` 为指纹，仅在变化时重建 band checkboxes，解决 ScrapeStage 推送结果后 checkbox 列表为空的回归。

5. **附带改动**：Vision Tab 导航栏红点 badge 提示乒乓等待；Flow Tab dashboard 改为 per-card refreshable（避免 expansion 折叠）。

## 实验结果

- 语法检查通过（ast.parse + IDE 零错误）
- 模块导入验证 OK：`SAFE_PLACEHOLDER_GCODE='G0 Z10.0\nM2\n'`, `AUTO_CONFIRM_TIMEOUT=15.0`, `MANUAL_CONFIRM_TIMEOUT=300.0`
- Mock 流程联调：自动模式 15s 超时正确触发自动选 band + 下发；切换到历史样品时 radio 灰色；乒乓样品切换不再清空预选 band

## 已知问题

- 方向 X（彻底删除 auto/manual radio）和方向 Y（radio 降级为纯 UI 偏好）尚未实施，保留为后续简化方向
- stress mode 无 UI 路径走兼容分支 `_generate_gcode(state, None)`，行为不变

## 后续计划

- 如果后续确认 auto/manual 切换在生产中仍复杂度过高，考虑方向 X 简化
- 观察实机测试中 manual 300s 超时是否需要调整
