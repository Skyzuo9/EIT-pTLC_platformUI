# 20260531 实验记录

## 修改目标

修复 mock 多样品并发下出现的「`[RM] DONE 缸自动释放(含残留绑定)` warning + 后续展缸 `await_drain_done` 死等 300s+ + 系统总览工位卡片瞬时显示空闲」三联现象。第一性原理重新审视：用户指出昨天落地的「`sync_states()` DONE 缸兜底自释放」机制是用奥卡姆剃刀名义保留 race window + 兜底糊弄，调试时无法区分真异常与已知竞态，引入更多不确定性。本次按真正的奥卡姆剃刀重构——让正常路径不产生该竞态窗口，再让兜底专心处理真异常。

## 核心改动

1. **`core/stages/develop.py`**：`mark_handoff_pending(target_tank)` 调用从 Phase 4（`await_drain_done` 之后）**前移到 Phase 3 `trigger_drain` 之后、`await_drain_done` 之前**。Phase 4 仅保留 `pending_handoff_tank_id = target_tank` + `allocated_tank = None` + STEP_START/STEP_DONE 日志（`duration_ms=0`）。语义扩展：`handoff_pending` = "develop 阶段已结束，缸进入 handoff 流程"（旧语义 "等 RecipeTask 接管" 是其子集）。
2. **`core/resource_manager.py::_sync_states_locked`**：DONE 分支收敛为三段式——`handoff_pending=True` 跳过；`sample_id != None`（含归属 + 未 handoff）仅 `log.warning` **不再篡改 sample_id/state**；`sample_id = None`（孤儿缸）才走 `release_tank()` 归 IDLE。删除原 "DONE 缸自动释放(含残留绑定)" warning 路径与 sample_id 清空动作。docstring 同步从 "DONE 缸自动释放" 改为 "孤儿缸自动释放"。
3. **AGENTS.md**：`core/stages/develop.py` 行追加 `mark_handoff_pending` 前移说明（mock race window 根因 + 语义扩展）；`core/resource_manager.py` 行从「DONE 缸兜底自释放」改为「**仅清孤儿缸**」+ 设计原则「sync_states 是 PLC→PC 镜像同步机制，不应改写业务归属语义」+ 与 develop.py 的协作关系。

### 后补改动（mock 跑通后讨论的两个小问题）

4. **`ui/sections/flow.py::_render_develop_station`**：展缸格子渲染加 1 行 `handoff_pending` 优先判断——`handoff_pending=True` 期间显示浅绿底「等待接管」，与 `DONE` 的「完成」（深绿）和 `IDLE` 的「空闲」（灰）三色区分。物理事实：PLC 视角是"完成"（排液 FSM 完成 + 机器人取板完成），样品视角是"等待接管"（展缸资源还绑定样品等 RecipeTask 在 `_scrape_lock` 内 release）；UI 采样品视角避免歧义。
5. **`PLCsoftware/OPCUAtest/[reminder]drain_handoff_invariants.txt`**：新增 PLC 工程师阅读用的协议规约提醒文档（139 行），明确本次上位机改动对 PLC 工程方零侵入，但需要 PLC 工程师确认 v1.3 既有契约 3 条规约已实机落实：(1) `Drain_Done=TRUE` 必须在 `Tank_State=99` 已稳定后或同周期内置位；(2) PC 写 `Tank_State=0 + Drain_Enable=FALSE` 后 PLC 必须清 `Drain_Done=FALSE`；(3) `Tank_State` 写权按状态值分配（PLC 写正向推进、PC 写 0 释放）。文档同时附实机联调预期警报含义与排查方向。

## 故障链根因（第一性原理）

```
mock _drain_complete: 先写 Tank_State=99 → 再写 Drain_Done=TRUE（中间存在数十毫秒窗口）
   ↓
sync_states 周期扫描在该窗口命中：Tank_State=99 + handoff_pending=False + sample_id=Sx
   ↓ 旧实现「含残留绑定」分支触发 release_tank
   ├─ 写 Tank_State[i]=0
   ├─ 写 Drain_Enable[i]=FALSE   ← ★ 关键破坏
   └─ info.sample_id = None
   ↓
mock _tank_drain_fsm_loop 看到 Drain_Enable=FALSE → 清 Drain_Done=FALSE
   ↓
DevelopStage await_drain_done 永远等不到 Done → 进入 300s 长等待 warning
   ↓
UI 工位卡片读 info.sample_id=None → 显示"空闲"（但 PLC 实际仍在排液）
```

**结论**：`Tank_State=99 + handoff_pending=False` 不是异常，而是「PLC 已置 99、上位机还没标 handoff」的合法过渡态。把它当异常清扫等于让兜底机制篡改正常业务语义。前移 mark_handoff_pending 后该过渡态在源头消除；兜底机制收敛为只清孤儿缸，调试时所有 warning 都是真异常。
