## 耗材管理 Phase 3 v2.4 设计文档全面修订

### 修改目标

基于最新实现情况，全面更新 `UI-Upper/plans/consumable_phase3_plc_interface_plan.md`，覆盖 5 个设计变更点：传感器变量变更、机器人操作流程、粉末收集器跨工位管理、新增变量、样品-工位绑定复用。

### 核心变更

1. **传感器变量设计变更（section-3.1）**：`Consumable_Sensor ARRAY[1..12] OF BOOL` 改为 `IX11`/`IX12` 两个 BYTE 标量，补充完整位序映射表（12板），`REQUIRED_CONSUMABLE_VARS` 自检集合同步更新
2. **Collect FSM 新增 Step 50（section-3.2/3.3）**：动作E 归还粉末收集器到暂存A，新增 `RETURN_POWDER_TO_STAGING_A` ActionID，所有放回动作统一在 collect 工位的 Step 40-50 执行
3. **新增跨工位传递变量（section-3.1）**：`collect_Powder_Return_Slot : INT`（1-6=暂存A孔号），PC 在 scrape 完成后、collect 启动前写入，PLC Step 50 读取并执行放回
4. **粉末收集器跨工位生命周期管理（section-3.7 新增）**：物理流转路径 暂存A slot[N] -> scrape -> collect -> 暂存A slot[N]；PC 侧通过 `ConsumableManager.get_powder_return_slot()` 传递孔号
5. **样品-工位绑定机制复用讨论（section-3.8 新增）**：推荐 ConsumableManager._decisions 作为唯一绑定源（与 ResourceManager 同构），不引入新绑定抽象
6. **设计决策补充**：确认无需额外"取走耗材板"变量，`_Fetch_Rack_Plate=0` 已隐含"不取板"语义

### 设计总结

**变量清单（v2.4 最终版）**：

| 变量 | 类型 | 方向 | 语义 |
|------|------|------|------|
| scrape_Fetch_Rack_Plate | INT | PC->PLC | 0=不取板，1-12=取板N到暂存A |
| scrape_Consume_Slot | INT | PC->PLC | 1-6=从暂存A取该孔 |
| collect_Fetch_Rack_Plate | INT | PC->PLC | 0=不取板，1-12=取板N到暂存B |
| collect_Consume_Slot | INT | PC->PLC | 1-6=从暂存B取该孔 |
| collect_Powder_Return_Slot | INT | PC->PLC | v2.4: 1-6=粉末收集器归还暂存A孔号 |
| IX11 | BYTE | PLC->PC | 料库检测1-8（粉末板1-6+玻璃瓶板1-2） |
| IX12 | BYTE | PLC->PC | 料库检测9-12（玻璃瓶板3-6）+ 保留位 |

**FSM 步骤清单**：
- Scrape: Step 10(init) -> 12(搬板) -> 13(取耗材) -> 15/20(拍照) -> 30(刮取) -> 40(转移收集器) -> 80(cleanup)
- Collect: Step 10(init) -> 12(搬板) -> 13(取玻璃瓶) -> 20-29(接续) -> 30(收集) -> 40(归还玻璃瓶) -> **50(归还粉末收集器)** -> 80(cleanup)

**关键设计决策**：
- 无需额外"取走板"BOOL变量：`_Fetch_Rack_Plate` 值已编码取板决策
- 旧板处理属于机器人搬板动作的一部分，在 FETCH ActionID 实现中包含交换逻辑
- 耗材板生命周期终止于 collect 工位结束
- **耗材板驻留策略**：collect 结束后板不搬回料架，继续驻留在暂存工位等待下一个样品复用。Step 40/50 归还的是单个耗材（玻璃瓶/粉末收集器），不是整块板。设计中不存在 RETURN_PLATE_TO_RACK ActionID
- ConsumableManager._decisions 作为 scrape->collect 跨工位绑定的唯一权威源
