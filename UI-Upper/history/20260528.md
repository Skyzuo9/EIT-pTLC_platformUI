## 核心改动（Commit 2）

### 一、CNC GVL 变量类型对齐 LREAL→REAL

- `plc_client.py` + `mock/plc_server.py`：11 个 `g_*` 浮点变量（`g_sx/g_sy/g_cx/g_cy/g_safe_z/g_approach_z/g_pass_z/g_total_depth/g_plate_surface_z/g_scrape_feed/g_plunge_feed`）从 `VariantType.Double`（LREAL 64-bit）改为 `VariantType.Float`（REAL 32-bit），对齐实机 PLC 的 `REAL` 声明，消除 `BadTypeMismatch` / `BadNotWritable` 写入拒绝。

### 二、PLC 写入路径动态解析回退（修复“能读不能写”）

- `plc_client.py`：`send_recipe_params()` / `write_variable()` / `write_array()` 三处增加动态解析回退——NODE_TYPES 声明但 `_cache_nodes` 未命中时，走 `_resolve_node()` + `_dynamic_nodes` 缓存，与 `read_variable()` 的三级回退策略对称。

### 三、心跳容错降级（v1.6.1）

- `_heartbeat_loop` 对 `HEARTBEAT_NODE`（`collect_Step`）的 `KeyError`（PLC 工程未暴露该变量）做降级处理：自动切换到任意已缓存节点，仅打一次 WARNING。仅 OPC UA 网络层异常才计入失败计数触发重连，避免 PLC 变量集微小差异导致无意义重连循环。

### 四、`cnc_path_generator.py` 内联坐标变换 + `g_pass_z` 权责划分

- 移除 `sys.path.insert` + `from tlc_gcode import _flip_from_corner, to_machine` 动态导入依赖，改为模块内联 `_CORNER_FLIP` 查表 + `_to_machine()` 函数，消除 `__pycache__` 陈旧字节码风险。
- `ScrapeArrays.as_plc_dict()` 移除 `g_pass_z` 字段（12 字段→11 字段）——该值由 PLC Step 30 循环内按 `g_plate_surface_z + k * g_total_depth / g_pass_count` 递增计算，上位机写入会覆盖 PLC 运行时值导致竞争条件。

### 五、Develop 工位润洗/上液重复次数参数

- 新增 PLC 变量 `Expand_rinse_count` / `Expand_up_liquid_count`（INT16），由配方参数 `rinse_repeat_count` / `up_liquid_repeat_count`（默认 1）经 `develop_pump_translator` 翻译后写入。
- 涉及文件：`develop.py`（SCHEMA + translate_params + 参数传递）、`develop_pump_translator.py`（翻译逻辑）、`plc_client.py`（NODE_TYPES 声明）、`mock/plc_server.py`（同构）、5 个 recipe YAML（默认值补充）。

### 六、Debug Tab CNC 面板增强

- 新增 `feed_rate` / `plunge_rate` 输入框，`_cnc_build_gcode_cfg()` 以 `state.gcode_cfg`（config.yaml 真机标定参数）为基础覆盖表单工艺参数。
- 文档注释更新：12 个变量→11 个（`g_pass_z` 不下发）。
