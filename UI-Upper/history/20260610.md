# 2026-06-10 实验日志

## 修改目标
收集路径从「瓶口扫尾」局部区域改为覆盖刮取全 bbox，解决粉末残留问题；同时修复 task.py 并行异常路径下展缸泄漏风险。

## 核心改动
- **收集路径全覆盖**：`cnc_path_generator.py` 收集路径 X 方向改为 `[x_min - 铣刀半径, x_max + 铣刀半径]`（全刮取区域 + 铣刀半径余量）；Y 方向新增 `collect_expand_ratio` 参数（[1.0, 2.0]），按 bbox 中心对称膨胀；三条路径策略（zigzag/boustrophedon/contour）均新增 `reverse_x` 参数，收集路径使用 `reverse_x=True`（右→左反向遍历）；`keep_ratio` 收集固定为 1.0（不受刮取 keep_ratio 影响）。
- **config.yaml**：新增 `gcode.collect_expand_ratio` 字段（默认 1.0）；`num_passes` 默认值从 3 恢复为 1（与 AGENTS.md Recipe Default Drift v2 一致）。
- **task.py 异常路径修复**：`before_photo` 失败时 cancel develop_task 后，补充收集 `pending_handoff_tank_id` 的逻辑（与成功路径对称），避免展缸资源泄漏；`develop_task` 本身抛出异常时同样补充 handoff 收集。PLC 写安全注释：PLCClient._lock 串行化所有 OPC UA 写，BeforePhoto 与 Develop 写不同变量无冲突。
- **sample_pump_translator**：吸液速度 ASP_SPEED 从 100 提升至 250。
- **visualize_cnc_path.py**：收集路径可视化矩形与实际 `collect_bbox` 计算逻辑同步，列数使用 `_compute_coverage_columns` 推导值而非 `boustrophedon_columns`。

## 实验结果
- 6 个文件 commit 成功（0ddaf3e），+116/-40。
- 收集路径逻辑变更：X 方向从 bottle_x_offset_mm 局部扫尾扩展为全刮取区域覆盖；Y 方向可通过 collect_expand_ratio 配置放大（默认 1.0 不放大）。

## 已知问题
- `collect_expand_ratio` 未经真机验证，>1.0 的放大效果需实测确认粉末收集覆盖率。
- `reverse_x=True` 收集方向（右→左）与刮取方向（左→右）相反，真机需确认 CNC 运动无干涉。
- task.py 异常路径修复基于代码审阅，未经真实 E-Stop/develop 故障场景端到端验证。
