# 2026-06-03 实验日志

## 修改目标

耗材协议 v2.5 动作码落地 + 大恒相机实机接入 + MJPEG 同源代理（解决浏览器 6 连接限制）+ 液位摄像头按需启停。

## 核心改动

### 1. 耗材协议 v2.5 动作码（`consumable_manager.py` / `plc_client.py` / `mock/plc_server.py`）

- `prepare_for_scrape/collect` 返回类型从 `tuple[int, int]` 升级为 `PrepareDecision(op, fetch_rack_plate, old_plate_slot, consume_slot)`
- 三条动作路径：`OP_NONE`（暂存复用）/ `OP_PUT_NEW`（暂存空，仅放新板）/ `OP_SWAP`（暂存耗尽，先取旧板回架再放新板）
- `NODE_TYPES` + `REQUIRED_CONSUMABLE_VARS` 新增 4 个 Int16 变量 `<stage>_Plate_Op` + `<stage>_Old_Plate_Slot`
- Mock Step 12 hook 按 `Plate_Op` CASE 分支仿真，`test_consumable_manager` 增加 SWAP 测试用例
- 设计依据：暂存区无传感器，PC 账本是唯一裁决方，PLC 哑执行不推理

### 2. Spotting v2 Step 7 回抽释压（`sample_pump_translator_v2.py` / `stages/spotting.py`）

- 7 步空气驱动策略：Step 7 在点样后回抽 ~1mL，释放点样器/公共腔正压，防滴液
- `build_dispense_array` 新增 `retract_volume_ml` 参数（默认 1.0mL）
- `calc_v2_volume_budget` 增加 `step7_retract_ml` 预算字段

### 3. DahengCameraService 实机接入（`camera_service.py` / `config.py` / `main.py`）

- `DahengCameraService.capture()` 调用 `scripts/daheng_capture.capture()` 经 `run_in_executor` 异步化
- `config.yaml` 新增 `camera.daheng` 段（IP/曝光/增益/像素格式/触发模式/ROI），`CameraCfg.daheng` 深合并默认值
- `main.py` 传入 `params=cfg.camera.daheng` 构造 `DahengCameraService`

### 4. MJPEG 同源代理 + 8 路网格预览（`ui/app.py` / `tank_vision_dialog.py` / `debug.py`）

- `ui/app.py` 新增 Starlette 路由 `/wl_proxy/{path:path}` 透传香橙派 MJPEG，上位机做 HTTP 代理，彻底解决浏览器 HTTP/1.1 的 6-connection 限制
- `tank_vision_dialog.py` MJPEG URL 从直连香橙派改为 `/wl_proxy/ch/{id}`（同源），Dialog 放大到 `90vw/max-width:1300px`
- 新增 `_build_grid_preview_dialog` 函数：单 HTTP 连接承载 8 路画面网格预览
- Debug Tab 新增"📺 网格预览 (8路)"按钮
- `ui/app.py` 增加 SIGINT 看门狗：3 秒后 `os._exit` 强制退出（uvicorn graceful shutdown 在有活跃 MJPEG 流时会挂起）

### 5. ResourceManager 液位摄像头按需启停（`resource_manager.py` / `water_level_client.py` / `state.py`）

- `ResourceManager.set_water_level_client()` / `set_stream_channels()` 注入接口
- `_sync_active_channels()` 在 `allocate/release/manual_release` 后 fire-and-forget 下发活跃通道列表到香橙派
- `water_level_client.py` 新增 `set_detect_mode` / `set_active_channels` MQTT 命令
- `state.py` 新增 `water_level_active_channels` / `water_level_stream_channels` / `water_level_max_active` 字段

### 6. Debug Tab `_safe_notify` 修复（`debug.py`）

- 自定义变量刷新回调中 4 处 `ui.notify()` 替换为 `_safe_notify()`，避免后台任务触发 `slot stack is empty` 错误

## 实验结果

- `test_consumable_manager` 全部用例（PUT_NEW / NONE / SWAP / exhausted / blocked / offline / concurrent）通过
- `test_sample_v2.py` 7 步体积预算验证通过
- MJPEG 代理在 8 路并发场景下稳定（单连接承载，不受浏览器并发限制）

## 已知问题

- `DahengCameraService` 实机采图依赖 `scripts/daheng_capture.py`（尚未正式纳入版本控制，需确认 SDK 授权状态）
- MJPEG 代理 `httpx.AsyncClient` 在长时间（>10min）连续流下可能出现内存积累，需观察生产稳定性
- SIGINT 看门狗 3 秒强制退出是 workaround，uvicorn/Starlette 的 MJPEG 流清理机制有待根本修复
