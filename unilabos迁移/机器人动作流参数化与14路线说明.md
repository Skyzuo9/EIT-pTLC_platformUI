# 机器人动作流参数化与 14 条业务路线说明

> 状态：2026-06-20 软件实现完成；离线解析与软件闭环通过；Modbus TCP 全量现场路线未执行。

## 设计

本轮采用四层最小抽象：

1. PointRegistry：唯一具体点位准入层；原始点和显式 base_point + offset 派生点均检查 validated 与 move_j/move_l 许可。
2. PointSet / StationRegistry：将 tool_id、tank_id、rack_id、slot_id 显式映射为角色点集合，运行时不拼接点名。
3. RobotPlanCatalog：模板只引用 home、ready、approach、target 等角色。
4. RoutePlanner / RouteExecutor：编排机器人流、PLC 写动作、PLC 真状态等待和相机动作，持有业务资源并失败即停。

运行入口使用 robot_flows_v2.yaml；robot_flows_v1_baseline.yaml 仅是冻结对照，不参与 runtime。测试模板 test.gripper 与生产模板分开。当前现场执行限定 ModbusRobotTransport；TCP-IP-V4 本轮没有真机结论。

## 14 条路线

| # | route_id | 参数 |
|---:|---|---|
| 1 | plate.feed-to-spotting | 无 |
| 2 | plate.spotting-to-scrape | 无 |
| 3 | plate.scrape-to-tank | tank_id=1..8 |
| 4 | plate.tank-to-scrape | tank_id=1..8 |
| 5 | plate.scrape-to-waste | 无 |
| 6 | consumable.bottle-group-rack-to-staging-b | rack_id=bottle, slot_id=1..6 |
| 7 | consumable.collector-group-rack-to-staging-a | rack_id=collector, slot_id=1..6 |
| 8 | consumable.bottle-group-staging-b-to-rack | rack_id=bottle, slot_id=1..6 |
| 9 | consumable.collector-group-staging-a-to-rack | rack_id=collector, slot_id=1..6 |
| 10 | consumable.collector-staging-a-to-scrape | rack_id=collector, slot_id=1..6 |
| 11 | consumable.collector-scrape-to-collect | 无 |
| 12 | consumable.bottle-staging-b-to-collect | rack_id=bottle, slot_id=1..6 |
| 13 | consumable.collector-collect-to-staging-a | slot_id=1..6 |
| 14 | consumable.bottle-collect-to-staging-b | rack_id=bottle, slot_id=1..6 |

工具位 1～3 共用 tool.pick/tool.put；slot 1 差异通过 PointSet 扩展步骤插入。展缸 1～4 属于 tank-a，显式经过 P75/P84 并从 P59 接近；5～8 属于 tank-b，从 P3 接近。仓库、暂存和槽位均为显式 selector。

升降机及拍照/收集夹持交接均拆为机器人 enter、PLC 动作、真实 PLC 状态等待、机器人 exit。相机动作只记录原始结果，不修正轨迹。

## 安全与日志

- RobotActionService RLock 保证动作流整段互斥。
- 需要跨 PLC/相机步骤持续夹持或占位的路线使用 transaction 级机器人锁，但锁窗口仅从首段机器人动作流开始到末段机器人动作流结束；前置 PLC 等待和末段后的确认不占机器人。业务资源由 RobotBusinessResourceLedger 持有到事务结束。
- 任一步失败立即停止；不重试、不回原点、不清警、不执行后续步骤。
- PLC 条件由 PLCClient 实际读取；主机编排禁止固定 wait 冒充到位。
- PLC 写动作拒绝陈旧 TRUE，并执行写后读回校验。
- 日志包含业务参数、资源、PointSet、最终点位、机器人步骤、主机步骤、flow/host SHA-256、结果和失败原因。

## 验证状态

软件已通过：六条工具流等价、slot 1 差异、非法/缺失/未验证/错误运动类型拒绝、8 展缸分组、14 路线 68 组合法参数解析、PLC 映射完整性、资源持有、互斥、真实条件轮询、相机原始结果和失败即停。

现场待确认：

- 14 条路线尚未在真实 PLC + 机器人 + 相机组合环境执行。
- 旧 PLC XML 未包含“上样点样允许取硅胶板 / 上样点样取硅胶板完成”，须核对现场当前工程；缺失时 runtime 会明确失败。
- 旧 Lua 的 SpeedFactor 不在当前 Modbus 语义接口中；已保留各段 acc/vel/cp，速度仍需逐段验收。
- 派生接近点的软件许可通过不等同于本轮全路线真机复验。
