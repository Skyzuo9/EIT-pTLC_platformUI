# 机器人动作流与 14 路线现场验收指导

> 当前结论：离线解析和软件闭环通过；以下真机项均未在本轮执行，勾选前不得写“现场通过”。

## 一、前置条件

- 只保留一个上位机进程和一个 Modbus TCP 客户端；关闭 Modbus Poll、其他测试脚本和 TCP-IP-V4 控制端。
- 上位机是 Modbus TCP client/master，机器人是 server/slave，现场使用 word-swap。
- 机器人急停、碰撞、报警必须人工处理；程序不得自动清警或自动 Enable。
- PLC 当前工程必须能浏览 robot_host_actions.json 中全部节点。
- 特别确认“上样点样允许取硅胶板”和“上样点样取硅胶板完成”；旧 PLC XML 没有这两个节点。
- 确认 DO1=0 锁紧、DO1=1 松开；取工具=lock，放工具=release。

## 三、工具小闭环

依次执行，不允许并行终端：

    python UI-Upper/scripts/robot_flow_acceptance.py --config UI-Upper/config.example.yaml run-flow tool.pick --tool-id 1 --confirm-flow
    python UI-Upper/scripts/robot_flow_acceptance.py --config UI-Upper/config.example.yaml run-flow tool.put --tool-id 1 --confirm-flow

slot 1 通过后再测 2、3。逐项记录：

- [ ] 入口/出口均为 home。
- [ ] 点位顺序、move_j/move_l、acc/vel/cp 与冻结基线一致。
- [ ] slot 1 放工具有额外 DO6 准备动作；slot 2/3 没有。
- [ ] 取工具 DO1=0 锁紧；放工具 DO1=1 松开。
- [ ] 制造一步失败后，后续步骤未执行，未自动回原点、重试、清警。

## 五、PLC/相机组合路线

通过 UI-Upper/core/robot_route_runtime.py 的 execute_route 调用，必须保留事件日志。每条路线先空载，再带料，按 1～14 动作清单逐条执行。

每条检查：

- [ ] 业务资源从 route_start 持有到 route_done/route_failed。
- [ ] 机器人 enter 后，PLC 条件未到时机器人保持夹持/占位，其他路线不能取得机器人。
- [ ] PLC 条件来自真实节点变化，不是固定延时。
- [ ] PLC 写动作在陈旧 TRUE 时拒绝，写后读回一致。
- [ ] 相机返回真实文件路径、大小和 sample_id；结果未修改机器人点位。
- [ ] 失败日志含 route、host step、robot step、PointSet、配置 SHA-256 和原因。
- [ ] 不自动重试、不自动回原点、不自动清警、不继续后续步骤。
