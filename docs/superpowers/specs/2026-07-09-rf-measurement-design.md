# Rf 测量方案（拍照刮板视觉 + 展开监控触发） — 设计稿

日期: 2026-07-09
分支: codex/ui-upper-next
相关记忆: `water-level-detection-upper-migration`, `water-level-calibration-ui`, `photoscrape-vision-frame-consistency`

## 0. 一句话结论（第一性原理）

**不需要 QR，不需要标定板，不需要任何 px→mm 标定。** Rf 是两段距离的**比值**，只要把这两段距离**都在同一台（scrape）相机、同一套板坐标系里**测出来，尺度自然约掉。展开监控相机只做**阈值触发**，不做任何测量。

**坐标系用「板检测归一化」而非裸像素**：每次运行先用现有板检测（最大暗矩形）在图中定位整块板 → 建立**以板为基准的坐标系（板宽/板高的比例）**。位置都以"占板的比例"表达 ⇒ 相机日后**平移/变焦/微调**只要仍正对拍全板，归一化坐标不变，`D_f` 无需重标（裸像素则会随相机动而失效）。这直接吸收你"拍摄位置以后可能调整"的顾虑。

## 1. 背景与目标

TLC 板需要给出每个斑点的 **Rf 值**:

```
Rf = 斑点迁移距离 / 溶剂前沿迁移距离 = D_s / D_f
   D_s = 原点(点样基线) → 斑点中心
   D_f = 原点            → 溶剂前沿(展开停止时的位置)
```

目标: 上位机自动算出每块板每个斑点的 Rf，供后续实验记录/分析。

**难点（用户实测约束）**:
- **两台相机、视野不重叠**: 展开监控相机（develop cam）在展开过程中只能看到板子**靠近前沿的一小片顶部窗口**（物理跨度 ~15cm × ~10cm），**看不到点样原点**，也拍不全整块板。拍照刮板相机（scrape cam）在展开结束**之后**才看到板面，**能拍全整块板**（原点基线 + 斑点都在），但**看不到展开结束瞬间的前沿**（前沿此时已挥发/不可见）。
- 因此 D_s（斑点）只有 scrape cam 能测，D_f（前沿）的**发生**只有 develop cam 能实时观察 → 天然被劈成两台相机。

## 2. 关键领域事实（决定设计）

1. **Rf 是无量纲比值**。若两段距离在同一图像、同一尺度下测量，mm/px 在分子分母同时出现 → **约掉**。跨相机才需要共同物理单位（mm）；同相机像素即可。
2. **停止规则 = 液位/前沿检测算法输出的百分比阈值**（现上位机侧 `waterlevel_detector` 的 `percent`，见记忆 `water-level-detection-upper-migration`）。阈值触发 ⇒ 前沿到达一个**由 ROI + 阈值固定的可重复位置** ⇒ **`D_f` 是每通道一个常量**，不随单次运行变化。
3. **机器人放板重复精度 ≤1mm**，且 scrape 站放板走固定点位、相机固定 ⇒ scrape cam 成像几何**逐板一致**，一次性测得的 `D_f_px` 可迁移到每次运行。
4. **scrape cam 已有一把物理尺子**（[vision_quality.py:465](../../../eit_ptlc/controller/vision_quality.py#L465) `mm_per_px = plate_size_cm*10 / bbox_w`）——若日后想报**绝对**迁移距离（mm）随时可用，但 **Rf 本身用不到它**。
5. **现状缺口**: [vision_quality.py](../../../eit_ptlc/controller/vision_quality.py) 只做「板检测(最大暗矩形)+ 旋转/透视 + 亮度/清晰度质量 + 板宽 mm/px 中心偏移」，**没有 origin 基线检测，没有 spot 检测**。⇒ `D_s` 是**全新视觉工作**（但见下 6/7 两点，风险已大幅降低）。
6. **成像 = UV 254nm + F254 板**（绿色荧光底 + UV 吸收物淬灭成**暗斑/暗线**，见真机图）。⇒ 斑点是**暗打亮底**的高对比目标，`cv2` 阈值/blob 足以分割，非"淡斑"难题。
7. **原点由点样工位伺服轴决定**：样品点在板上的位置是**伺服受控的已知物理量**，且样品点**固定在板坐标系里**（不随放板漂移）。⇒ 原点**不必视觉检测**：以伺服已知的板坐标常量，经**每次运行的板检测**投影到当前图即得原点位置；视觉找基线仅作**可选复核**。最差可纯测量给定。

## 3. 架构：两台相机、职责完全分离

| 相机 | 在 Rf 中的角色 | 拍全板? | 是否测量距离 |
|---|---|---|---|
| **develop（监控）** | percent-阈值 **触发器**（现有算法不动） | 否（仅顶部窗口） | **否** — 永不测距 |
| **scrape（拍照刮板）** | 测 `D_s`（每次运行）+ `D_f`（一次性/通道） | **是** | 是 — 全部度量都在这里 |

**关键**: `D_f` 在 **scrape 站**测得，不在 develop 相机。develop 相机视野窄、拍不全板都**不影响** Rf，因为它从不测量，只负责说「现在到阈值了」。

## 4. 数据流与公式

```
develop cam ──percent≥阈值──▶ 触发拉板（现有停止逻辑，零改动）
                                     │
一次性/通道标定:  标记前沿的标定板 ──▶ scrape cam ──▶ 板检测→ D_f（原点→前沿, 板归一化, 存盘）
                                     │
每次运行:        展开后板面        ──▶ scrape cam ──▶ 板检测→ D_s（原点→各斑点, 板归一化）
                                     │
                                     ▼
                          Rf = D_s / D_f   （同板归一化系, 尺度约掉）
```

- 每次先**板检测**建立板归一化坐标系；原点 = 伺服常量 `origin_frac`（§5.1），作两段距离的公共零点。
- `D_f` 与 `D_s` 同在板归一化系 → 不需要 mm，不需要板宽尺子，且**抗相机平移/变焦**。
- （可选）若要**绝对 mm**: 用 §2.4 的板宽 `mm_per_px` 把任一距离转 mm，仍无 QR。

## 5. 组件设计

### 5.1 origin 原点定位（scrape 侧，**低风险**——伺服已知量）

原点**不靠视觉检测**，而是伺服受控的**已知板坐标常量**。

- 输入: 每次运行的板检测结果（板 bbox/四角，复用现有 [vision_quality.py](../../../eit_ptlc/controller/vision_quality.py) 板检测）建立**板归一化坐标系**。
- 核心: 点样工位伺服把样品点在**板坐标系里固定位置**（如"距点样边 X，展开方向轴 = origin_frac"）。该 `origin_frac` 是一次性给定常量（伺服位置换算/一次实测）。
- 输出: 把 `origin_frac` 经**本次板检测**投影 → 当前图中原点轴向位置。**对放板漂移免疫**（原点锁在板上，板检测逐次重定位）。
- 可选复核: 板底暗基线（真机图可见）用作 sanity check，不作主依据。

### 5.2 spot 检测（scrape 侧，**新**，主风险）

分割斑点、给出各斑点中心在**板归一化坐标**（展开方向轴）上的位置 `spot_axis[i]`。

- 手段: UV 图上斑点=**暗打亮底**，阈值/blob/contour（`cv2.findContours` 已在库内使用）+ 形态学；按展开方向轴投影取中心。
- 输出: `D_s[i] = spot_axis[i] − origin_axis`（同一板归一化系，无量纲）。
- **风险（本方案唯一实质工作）**: 拖尾、板纹理、斑点重叠、低浓度弱斑。UV 高对比已降低难度，但仍建议先做 §5.5 可行性验证。

### 5.3 `D_f` 一次性标定流程（每通道一次）

目的: 测出「阈值触发时前沿到原点」的固定距离 `D_f_px`。

步骤（一次性，人工）:
1. 备一块**有可见原点基线**的标定板。
2. 在目标通道**同条件**展开（同 ROI/阈值/相机）。
3. develop cam percent 命中阈值 → 触发 → 拉板。
4. **立即在湿态标记前沿线**（铅笔，此刻前沿可见）。
5. 送到 scrape 站（同固定点位）→ scrape cam 拍全板。
6. 板检测建系 → 原点用 `origin_frac`、前沿标记视觉定位 → `D_f = front_axis − origin_axis`（板归一化），按通道存盘。

- **优点**: 自动吸收检测延迟与 percent→位置映射的所有系统性，因为你测的是「该阈值实际产生的前沿」。
- 若多通道 `D_f` 实测相近 → 可退化为**一个全局常量**（用 2~3 块板验证是否一致）。

### 5.4 Rf 组装与存储

- 每次 scrape 运行: 算 `Rf[i] = D_s[i] / D_f`，随斑点结果落盘（沿用 photoscrape summary 契约的存放层）。
- 存储: `D_f`（每通道或全局，板归一化）+ `origin_frac` 进一处配置真源（拟 `config/` 下，与 scrape 视觉参数同层；具体键名待定 §待办）。

### 5.5 spot 检测可行性验证（前置 spike，强烈建议）

在写实现前，用**真实已显影 UV 板图**离线验证 §5.2 能否稳定分割斑点（拖尾/重叠/弱斑）。origin（§5.1）已降级为伺服常量、标定问题已消除 ⇒ spike 只需盯 **spot 分割** 一件事。**注意**：验证图须在**相机位置锁定后**采，因归一化虽抗相机平移/变焦，但 spike 要确认的是分割鲁棒性。

## 6. 误差预算

- `D_s` 完全免疫放板/相机漂移：原点(伺服常量)与斑点都锁在**板归一化系**，逐次板检测重定位。
- `D_f` 残留误差只来自「前沿在板坐标里的逐次抖动」：放板 ≤1mm 使前沿(槽/液面参考)相对板移动 ≤1mm。前沿travel ~40mm 时 1mm ≈ 2.5% → `Rf` 误差 ~±0.012。
- TLC 真实复现性本就 ±0.02~0.05 ⇒ **预算内**。
- 阈值触发 → 前沿位置有小方差（检测延迟/percent 映射），已被 §5.3 的**实测**吸收进 `D_f` 常量。
- 板检测精度直接进入两段距离；现有板检测已服役，spike 顺带核其归一化一致性。

## 7. 假设与风险

| 假设 | 依据 | 若不成立 |
|---|---|---|
| percent 阈值 → 前沿位置逐次可重复 | 停止规则 = 固定阈值 + 固定 ROI | `D_f` 变每次运行量 → 需 develop 侧**逐次前沿度量**（届时用**场景内共面已知长度**测 mm/px，仍非 QR；见 §9） |
| 放板 ≤1mm | 用户确认 | 板归一化 + 伺服原点已**对放板免疫**（原点/斑点均锁在板上）；残留仅前沿在板坐标的小抖动 |
| scrape cam 能稳定分割 **spots** | **待验证（§5.5）**；UV 暗斑高对比已利好 | 唯一实质风险，可能需调 UV/曝光、改分割参数 |
| origin_frac 伺服常量准确 | 点样伺服受控 | 复核用板底暗基线；最差纯实测给定 |
| 相机正对拍全板（可平移/变焦） | 板归一化坐标 | 若变斜 → 靠现有去旋转/透视归一化兜底（记忆 `photoscrape-vision-frame-consistency`）；**相机位置须先锁定再做 §5.3 标定** |

## 8. 范围与分期

- **Phase 0（前置 spike）**: §5.5 **spot 分割**可行性——相机锁定后的真 UV 板图离线验证。**Gate**: 不过则先调成像/参数，不进 Phase 1。
- **Phase 1**: 板归一化建系 + §5.1 origin(伺服常量投影) + §5.2 spot 检测 + `D_s` 输出（scrape 侧，含离线测试）。
- **Phase 2**: §5.3 `D_f` 一次性标定流程 + 存储（每通道/全局）。
- **Phase 3**: §5.4 Rf 组装 + 落盘 + 前端展示（沿用 photoscrape summary 契约）。
- 每期各自 spec→plan→实现，离线优先，真机验证后推进。

## 9. 被否决的方案（及理由）

1. **生成 QR 脚本 → px→mm 标定（用户原始诉求）**: 否决。Rf 是比值，同相机像素即可约掉尺度；QR 仅提供 scale，还需另配原点锚才算距离（1+2 不完整）。且打印机缩放引入尺度误差、需刚性平贴、需共面。
2. **购买标定板（棋盘/ChArUco）**: 否决。固定单相机 1mm 级需求下过设计；大棋盘塞不进 develop 顶部窄窗口；不能编码通道身份；花钱等货。
3. **用场景螺栓直径当尺子（用户改进案）**: 比 QR 更 Occam，但仍被本方案否决（因根本不需要 develop 侧 mm）。**技术雷区**（见照片: 螺栓在**抬高的展缸盖金属框**上）: 与板面**不共面** → 景深致 mm/px 系统性偏差；小特征 + 金属高光 → 定位噪声。若将来真需 develop 侧 mm，应测**共面**大跨度已知长度而非螺栓。
4. **develop 侧引入 mm/px（QR 或场景测量）逐次测前沿**: 暂不做。仅当 §7 的「阈值可重复」假设被真机推翻、需要逐次前沿 QA 时才启用；届时用场景共面测量，非 QR。
5. **物理标记前沿让 scrape 一图同测（消灭双相机融合）**: 否决为**常规主路径**。自动标记前沿机构复杂，且 develop 监控相机为液位 percent 本就存在，复用它做触发比加机构省。（但 §5.3 的**一次性**标定正是用了「人工标前沿」这一手，仅一次，可接受。）
