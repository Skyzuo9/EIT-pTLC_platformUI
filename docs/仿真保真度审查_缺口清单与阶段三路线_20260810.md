## 0. 结论摘要

从第一性原理审视, 仿真沙盒的目标是 **"动作经真实执行链路跑在虚拟 PLC 上, 让流程逻辑 / 耗时 / 物料账本联动可信"**。
按这个标准逐层核对后的结论:

- **可信的部分**: 有 flat Target 的 7 根轴 (4X/3Y/5Z/7Y/8Y/9X/10Z) 按 vel_max 连续运动; 地轨 11Y; 注射泵
  逐真实 DT 指令积分 (全沙盒保真度最高的一环); 机械臂 20Hz 插值 + 真实 IK。
- **不可信的部分**: FeedLift/点样 6X 轴永远不动; 全部 PLC 内部工序 (除展缸排液外) 立即 DONE;
  全部传感器位恒 0; 气缸自动档永不动; 物料账本全空且无写入口; 报警互锁全旁路; 部分环节不吃时间倍率。
- **直接后果**: `上样-上料` 这类依赖 FeedLift 与物料的流程, **在沙盒里无论怎么设状态都跑不通**
  (用户 2026-08-09 截图的报错就是该缺口的第一个可见症状)。

修复路线 = 本文第 4 节 (阶段③ A~F), 已随总体实施计划批准。

## 1. 截图报错的完整因果链

报错: `[沙盒] feed 板仓换算张数 180 超出量程 0~30 张, 疑为标定失准或机构异常`

```
sampling_load (config/operation/01_sampling/sampling_load.yaml:33-36)
  → run_script feedlift_load_cycle
    → feedlift.feed_clear (code 13)   → 沙盒 L2 派发器无条件 DONE, 轴不动
    → feedlift.feed_raise (code 11)   → 同上, 1Z 仍停在 0.0
    → feedlift.probe_stack (reconcile=true)
      → sim_stack.py:657  z_mm = read_feedlift_pos(1) = 0.0
      → controller/feedlift_count.py:262-277
          raw = (z_empty 512.127 − 0.0) / pitch 2.85 = 179.69 → count = 180
      → feedlift_count.py:462-467  180 > capacity 30 → ok=False
      → sim_stack.py:659-660  raise ValueError("[沙盒] feed 板仓换算张数 180 超出量程…")
```

四个叠加成因:

1. **沙盒 FeedLift 轴永远不动**: 1Z/2Z 的行程烧在 PLC 里, 没有 flat Target 节点
   (`config/plc_nodes.yaml:261-264` 只有 SearchLow/HighTarget 搜索边界), 行为层阶段③刻意留空
   (`mock/sim_axes.py:58` 原文: "FeedLift/Develop/Collect/StagingA 的轴行程烧在 PLC 里, 无 flat Target, 留给阶段③")。
2. **虚拟 PLC 的 L2 派发器无条件成功**: `mock/plc_server.py:278-279` 对任何未注入的动作码一律
   `term = DONE`, 不看动作码语义 / 前置门 / 传感器; 段号是 1..5 的假拍 (`:286-289`)。
3. **轴初值 0.0 是物理不可能位**: feed 仓合法读数区间是 426.627~512.127 mm (30 张 ~ 空仓);
   `reset_home` 把 11 根轴全部写 0 (`runtime/sim_stack.py:244-257`); adopt 则照搬真机快照
   (截图里 2Z=488.0 来自真机实时位, 1Z=0.0 说明真机该轴未动过)。
4. **误导性文案的巧合**: 残差 0.3063 恰好低于 RESIDUAL_LIMIT 0.4 (`feedlift_count.py:32`),
   "判定 1: 读数不可信" 没拦住, 报出的是更吓人的 "判定 2: 标定失准或机构异常" —— 真因是轴根本没动。

**改状态也救不了**: 即使把 1Z 手动摆到 426.627 (=30 张), 流程后半段
`feedlift_load_cycle.yaml:51-54` 还有一次 `probe_stack(z_prev=p0, expect_taken=1)` —— 轴不动
⇒ 位移差 0 ⇒ taken=0 ≠ 1 ⇒ 判定 3 报 "空吸" 停机。这条流程被 FeedLift 缺口锁死。

## 3. 为什么修 (第一性原理)

仿真模块的存在意义是三件事, 每个缺口都至少伤其一:

1. **流程逻辑可推演** —— 用户要能在沙盒里 "设一个状态, 看流程会怎么走"。B1/B6/C1~C5/D1~D3
   使得大半流程走不到第二步, 错误分支永不出现, 推演无从谈起。
2. **耗时可参考** —— E1/E4/F4 让沙盒时长与真机脱钩, 甚至方向相反 (排液更慢)。
3. **账本联动可信** —— 物料页 / 3D 内容物可视化的驱动源都是账本; D1~D4 让沙盒里这条链是死的。

修复原则 (随总体计划已定): **宁缺毋假** —— 行为以从 CODESYS 提取的 ST 为据, 提取不到的显式标注,
不编造; 段号 / 互锁 / 错误码 / 时序常量落成机器可读 spec, 带 CODESYS 锚点与漂移看门狗。

## 5. 显式接受的近似与不做项

以下各项**刻意不修**, 依据一并记录, 防止后来者误当缺陷:

1. **CNC 刮取黑盒计时** (不复刻 SoftMotion 插补): PLC_CNC 在工程里只有声明无 ST 实现体
   (2026-08-10 经 codesys MCP 实测); 折线长度/进给即可精确估时 (与 2026-07-26 实测口径一致:
   6408mm@800 ≈ 8min)。毫米级路径保真对 "流程/耗时/账本" 三目标零增量。
2. **毫米级抖动/重捕获不主动复刻**: 光电抖动重捕获 (2.0mm×2) 的代码路径保留, 触发靠测试注入
   (`server._eit_feedlift_flicker`), 常规运行不随机抖。
3. **料库 12 路检测恒 0** (C6): 真机该 12 路 2026-07-26 实测与物理零耦合 (未供电), 沙盒复刻真机
   而非复刻愿望。
4. **HMI position 数组缺口**: Sampling 31/61 的 7Y 目标、6X 清洗位存在 HMI 示教数组里, OPC 不可读
   —— 沙盒该步不动轴只走段号+DONE, spec 里显式标注, 不编造值。
5. **机械臂动力学** (F1): 线性插值 + 名义速度保留, 轨迹规划/碰撞不做。
6. **沙盒不装调度器** (F3): 隔离铁律; /api/sim/scheduler/snapshot 的 404 由前端注释降级承接。
7. **进料传感器/Alarm 位简并映射**: 真机 A11 门里的 "上料进料传感器" 与 "Alarm.0" 上位机读不到
   (无 OPC 节点), 沙盒将其简并映射为 "仓内有板" (count>0), spec 标注。
