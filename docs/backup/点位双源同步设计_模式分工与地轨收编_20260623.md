## 0. 一句话

**自动模式只读 PC 拥有的运行值(单写者=PC)，HMI 完全不参与控制；HMI 只在手动模式示教，其 `position[]` 是 PC 真源的「工作副本/快照」。** PC↔HMI 之间靠**显式、手动、单向**的 push / pull / diff 三个操作对账，把「双源偏差」从隐患变成可见、可控、可对账。

---

## 1. 根因与单一真源(30 秒)

- 代差 = 同一个被示教的值**存了两份**(PC `points.yaml` 一份、PLC `HMI_*.position[]` 一份)，谁改了对方不知道。
- 唯一干净的解法不是「同步两份」，而是**指定唯一真源 + 其余只读**。
- 本设计指定：**PC `points/` = 唯一权威真源(canonical)**；PLC `position[]` = 它的**工作副本(working copy)**，仅供手动示教时在现场临时编辑。
- 传输事实(决定一切)：**PC 与 HMI 从不直连**，两者只读写同一批 PLC 变量。所以「同步给 HMI」物理上只能是「PC 写某 PLC 变量 → HMI 读它」。

---

## 2. 核心模型 —— 按模式分工

| 模式 | 运行值载体 | 唯一写者 | HMI 角色 |
|---|---|---|---|
| **自动 (auto)** | PC 拥有的运行节点(连续轴 flat `*_Target`；地轨 `Rail_Pos_Target[]`，见 §5) | **只有 PC** | **完全不参与控制** |
| **手动示教 (manual)** | `HMI_*.position[slot]` | HMI(现场 jog/手轮教) | **唯一主场** |

> 这把 path-T 与「手段 B 快照」各归其位：**path-T 管自动**(flat、PC 单写、HMI 出局)；**手段 B 快照管手动**(position[] 工作副本 + 显式同步)。二者不再冲突。

### 承重墙规则(违反即代差复发)
> **自动模式只读 PC 拥有的运行节点，永不读 `position[]`。`position[]` 与自动链路彻底解耦。**

红利：
- 自动正确性**不依赖**手动示教副本是否最新——即使 `position[]` 是陈旧快照，自动跑的是 PC 在运行时下发的真源值。
- HMI 现有 `position[]` 画面**一行不用改**(免去 path-T §4 的逐元件重绑)；`position[]` retain → 断电不丢、PC 不在线现场也看得到能教。

---

## 3. 三个操作 = git 的 push / pull / status

权威方向恒定：**PC = 真源；`position[]` = 工作副本**。

| 操作 | 语义 | 方向 | 安全性 |
|---|---|---|---|
| **下发快照 (push)** | 把 PC 真源值写进 `position[]`，让现场从当前真值起教 | PC → HMI | **安全**(只覆盖工作副本) |
| **回收示教 (pull / commit)** | 把现场教出的值收回 PC 真源 | HMI → PC | **危险**：会改写权威真源 → **必须先过 diff + 二次确认 + 限位校验** 才落盘 |
| **偏差检查 (diff / status)** | 逐点算 `\|PC.value − position[slot]\|`，列出超阈点 | 只读对照 | 安全；pull 前的强制前置 |

**diff 的映射现在就有**：连续点表已记 `hmi_node`/`hmi_slot`([config/points/plc/spotting.yaml:11](../eit_ptlc/config/points/plc/spotting.yaml#L11))，地轨记 `node`/`slot`([config/points/plc/rail.yaml:12](../eit_ptlc/config/points/plc/rail.yaml#L12))。PC key ↔ HMI 槽位对应是现成的，**偏差检查不欠 PLC，今天就能实现**。

### 不可能三角(避免绕进去)
**HMI 还想教 + PC 还想存自己一份 + 两者永不偏** —— 三者不可兼得。同步只能**单向**；本模型靠「显式手动一次性」保证任一时刻只有一个方向在写，从而既保留 HMI 手动示教、又把偏差变成可对账，而非靠纪律硬扛。

## 4. 适用域(别让模型漏到不该去的轴)

| 轴类 | 是否进「快照/push/pull/diff」 | 原因 |
|---|---|---|
| **离散示教点**：地轨 11Y(6 位)、点样 6X/7Y(若非逐带)、拍照 8Y、上样 5Z、清洗位 | **进** | 有固定槽，可快照、可对账、可现场教 |
| **仿射轴**：上样 4X / 3Y | **不进** | 逐孔值是 3 点标定**算**出来的，无固定槽可快照，HMI 也教不了 48 孔。能快照的只有**标定锚点**，归 `calibration.yaml`，不进本机制 |

补充(D2.1 已拍板 2026-06-23：单值存储 + 编排逐带)：6X/7Y 多带**不改存储**——存的永远是「教出来的基准点」(单值)，多带由 **operation 栏目编排**(循环写 value+偏移再触发)处理，**不另设多条存储方案**。推论:自动运行时 flat 值可能按带加偏移 → 多带运行时 `position[]` 快照(=基准) ≠ 运行瞬时值。这是对的(基准归手动、逐带偏移归自动)；**diff 须标注比的是基准值，逐带偏移不算故障/代差**，别让现场误判。仿射轴的逐孔值同理「是算的」——即便为 PLC 调用方便在 PC 侧存了逐孔值，那也是 calibration 解算出的**缓存**，非手教值，故仿射轴连教都在 PC(jog 采锚点解算)，不进本机制。

## 5. 地轨 11Y 收编方案(重点 —— 经 MCP 直读工程核实，成本远小于此前预估)

### 5.1 现状(2026-07-01 MCP 复核，纠正旧文档的过时记载)
- **`Rail_L2` 派发器已在当前 PLC 工程内**，不再「内嵌于 legacy 机器人 POU」。`plc_rail.yaml` 顶部「仍内嵌/sim mock」注释**已过时，应更正**。
- 自动模式读取地轨坐标**仅一处**，且当前工程已改为读 PC 真源：
  `地轨轴11YDATE.fAbsTarget := Rail_Pos_Target[Rail_Target_Position];`
- PC 经 `rail.move(Rail_Target_Position=1..6)` 下发**位码**([config/actions/06_rail/plc_rail.yaml:9](../eit_ptlc/config/actions/06_rail/plc_rail.yaml#L9))；全流程 `02_transfer/*` 大量调用(位 1上样/2拍照/3收集/4工具/5展开/6仓库)。
- 坐标真值现存 HMI 槽 `position[1..6]`(retain，HMI 手轮/按钮教)；PC `rail.yaml` 只存**绑定**(轴/位码/限位/标签)，**不存 value**([config/points/plc/rail.yaml](../eit_ptlc/config/points/plc/rail.yaml))。

**违反点**：运行值(坐标)归 HMI，自动读它 → HMI 在自动环里。这是用户最在意、要根治的耦合。

### 5.2 收编 = 一行 PLC 改 + PC 接管位表(索引召回与语义全保留)
**目标态**：把唯一读点的数据源从 HMI 槽换成 PC 拥有的位表数组。

1. **PLC**：声明 PC 可写的 `Rail_Pos_Target : ARRAY[1..6] OF LREAL`(`Host_Computer` GVL，导出符号供 OPC)。把 [Now.xml:4760](../eit_ptlc/plc/Now.xml#L4760) 改一行：
   `fAbsTarget := Rail_Pos_Target[Rail_Target_Position];`(仍按位码索引，**索引召回/「位2=拍照」语义不变**)。
2. **上位机**：`rail.yaml` 6 条加 `value`(站点坐标真值落 PC)；新增对 `Rail_Pos_Target[]` 的 flat 推送(连接后/运行前回推，复用 §3 push)。
3. **HMI**：`position[1..6]` 降为**手动示教工作副本**；自动不再读它。push/pull/diff 在 `rail.yaml.value ↔ position[1..6]` 间对账。

**为什么便宜**(对照旧「最后批次」叙事)：
- 自动只有**单一读点**，不是「legacy POU 到处读」——改动收敛到一行。
- **不必**逐位建 flat 节点 + 改多处 step + 镜像 ActPos；只需一个 6 元数组 + 一行引用。
- 索引召回模型、可读语义、retain 工作副本**全部保留**。
- 对账无需 ActPos 镜像：diff 比的是 PC.value vs position[slot] 两个**存储值**，地轨示教在 HMI 手轮完成，PC 侧不需要地轨实际位。

### 5.3 轻量过渡(若暂不动 PLC)
保持 [Now.xml:4760](../eit_ptlc/plc/Now.xml#L4760) 读 `position[idx]` 不变，但**翻转 position[1..6] 的所有权为 PC**：PC 在每次自动运行前 push `rail.yaml.value → position[1..6]`，HMI 教只当工作副本、经 pull 回收。
- 优点：零 PLC 改动，立刻让自动跑 PC 真源。
- 代价：自动仍**读** `position[]`，依赖「运行前必 push」纪律；漏 push 则读到陈旧/手教值。**不如 §5.2 immune**。
- 取舍：作为 §5.2 上真机前的**临时态**可接受；目标态仍是 §5.2。

### 5.4 双源同步的 PLC 中转(避开 struct 直访 —— push/pull 怎么真正发生)
**问题**：HMI 教的 `HMI_地轨轴11Y.position[1..6]` 在真机上是**单 ExtensionObject struct(length81)**，OPC **逐成员读写不可行**(这正是否决「PC 直写 position[]」路径 P 的根因：KeyError / 整 struct RMW 竞争)。所以 PC **不能直接读/写**这个槽来做 push/pull。

**破局原理**：struct 成员，**PLC 自己在 ST 里随便读写(内部访问无 OPC 限制)；只有 PC 经 OPC 碰不了**。⇒ **让 PLC 当桥，OPC 只暴露 flat 数组**。这正是 `*_ActPos` 镜像已用的套路，复用即可。

**形态(D-E 已拍板 2026-06-23)**：push/pull **两侧(PC + HMI)都有需求** → 定义**专用同步 POU `Rail_Sync`**(非 L2 动作，是同步工具)+ 一套**双方都能驱动的请求/应答邮箱协议**。**本阶段锁变量 + 协议；HMI 按钮后续推进**(照此协议接线)。原理可推广到 5Z/清洗等仍 HMI 示教的 struct 离散位。

### 5.4.1 守恒不变式(协议设计的硬约束)
- **PUSH**(`Target→position[]`)= **纯 PLC 内存拷贝**，POU 独立完成，**任一侧触发都行**。
- **PULL**(把现场教值收成真源)= 要写 `points.yaml` **+** 重算 `Rail_Pos_Target` → **只有 PC 能写**(PLC 写不了 yaml；更不能让 PLC 写 `Target`，否则 `Target` 多出第二写者，单写者破)。
- 所以 **HMI 触发 PULL = "请 PC 提交"**；真正"写真源 + 复核(diff/限位/确认)"恒落 PC。POU 对 PULL 只当**邮箱**把请求亮给 PC。

### 5.4.2 变量契约(`Host_Computer` GVL，全 OPC 友好)
| 变量 | 类型 | 写者 | 含义 |
|---|---|---|---|
| `Rail_Pos_Target[1..6]` | LREAL | **仅 PC** | 真源运行值(自动派发器读；PUSH 源) |
| `Rail_Pos_HMI[1..6]` | LREAL | **仅 PLC**(每扫描镜像 position[]) | HMI 教值只读镜像(diff/PULL 读)，PC 不碰 struct |
| `Rail_Sync_Req` | INT | PC 或 HMI | 0 空闲 / 1 PUSH / 2 PULL |
| `Rail_Sync_Ack` | INT | PLC(PULL 完成段由 PC) | 0 空闲 / 1 完成 / 2 待 PC 提交 / 3 拒绝(限位) |
| `Rail_Sync_Src` | INT | 请求方 | 1=PC / 2=HMI(审计 + 防误触) |

### 5.4.3 `Rail_Sync` POU 行为(每扫描)
1. **常开镜像**：`Rail_Pos_HMI[i] := HMI_地轨轴11Y.position[i]`(i=1..6)。
2. `CASE Rail_Sync_Req`：
   - **1 PUSH**：`HMI_地轨轴11Y.position[i] := Rail_Pos_Target[i]`(i=1..6) → `Ack:=1; Req:=0`。(PLC 写自己 struct，无 OPC 问题；PLC 独立完成)
   - **2 PULL**：`Ack:=2`(待 PC 提交)。PC 轮询见 `Req==2` → 读 `Rail_Pos_HMI[]` → 限位校验(失败 `Ack:=3`)→ diff + 确认 → 写 `points.yaml` + 重算 `Rail_Pos_Target` → `Req:=0; Ack:=1`。

> 另需：派发器改读 `Rail_Pos_Target[Rail_Target_Position]`(=§5.2 那一行，自动运行值)；2026-07-01 MCP 复核已确认当前工程内完成。

### 5.4.4 数据流小结
- **自动**：PC 写 `Rail_Target_Position` + 部署写 `Rail_Pos_Target[]` → 派发器读 target → 移动。HMI 不参与。
- **diff**：PC 读 `Rail_Pos_HMI[]` vs `rail.yaml.value` → 逐点偏差，**零 struct 访问**。
- **PULL(任一侧发起)**：现场教 position[] → 常开镜像进 `Rail_Pos_HMI[]` → (HMI 发起则置 `Req:=2` 请 PC) → PC 校验/确认 → 写真源。
- **PUSH(任一侧发起)**：PC 写 `Rail_Pos_Target[]` → 置 `Req:=1` → POU 拷进 position[] → HMI 面板显示 PC 真值(防面板与自动实际值不一致而误导)。

> **复核/确认两端都有(D-C 已定 2026-06-24)**：PC 屏与 HMI 面板**都**能做 diff 复核 + 二次确认。两端各从**自己已能直接拿到的数据**算 diff，无需新增 PLC 变量——
> - **PC 侧**：读 `Rail_Pos_HMI[]`(镜像) vs `rail.yaml.value` → 逐点偏差(OPC，零 struct 访问)。
> - **HMI 侧**：HMI 是 InoProShop/CODESYS 工程内可视化，可直接引用 `Rail_Pos_Target[i]` 与 `HMI_地轨轴11Y.position[i]` → 在可视化表达式里算 `position[i] - Rail_Pos_Target[i]` 并回显(亦无 OPC)。
> - **偏差阈值 = 0.1 mm(初值，可调)**：|diff| ≥ 0.1 mm 的点标记为"需确认"(3000 mm 行程的 ~0.003%，刻意取紧)。**真源落 `rail.yaml` 的 `sync.diff_threshold_mm`(canonical)**，PC 侧 `diff_sync` 读它(优先级：显式入参 > yaml > 内置 DEFAULT)；HMI 可视化暂硬编码 0.1 mm 并注释"以 rail.yaml 为准"(HMI 读不了 yaml，此处轻微重复)。注意：此阈值是"是否算有效差异/是否提请确认"的**软注意阈值**，与 PULL 的**硬限位拒绝**(0..3000 越界 → `Ack:=3`)是两回事。
> - **二次确认形态 = 按工位(D-C 已定)**：diff 仍**逐点**展示(D-D),但确认动作是**整工位一次提交**(地轨 6 位码为一个工位),覆盖 D-D 旧"pull 默认逐点"。

## 5.5 首次种子值（收编后第一次跑自动前必做 —— 2026-07-01 MCP 复核后仍适用）

**问题**：收编已把自动派发器改读 `Rail_Pos_Target[]`，但 6 站点坐标真值**从未搬进 PC**——`rail.yaml` 的 6 个 `value` 全是 `0.0` 占位（[rail.yaml:23-28](../eit_ptlc/config/points/plc/rail.yaml#L23)），真值仍只活在 HMI `position[1..6]`(retain)。**PC 连接后 PUSH/自动会把 `Rail_Pos_Target[]` 写成 0 → 地轨 6 工位全去原点（安全隐患）。**

**为什么没自动搬**：本设计的承重墙就是"HMI→PC 永不静默自动拷贝"（§3 不可能三角）。把现场教值收成真源 = PULL = 危险写真源，**必须显式、经复核**。所以种子值是**一次性手动 PULL**，不是漏做的自动化。

**怎么做（PC 独立可完成，不依赖 HMI 按钮）**：`Rail_Sync` POU 每扫描无条件把 `position[1..6]` 镜像进 `Rail_Pos_HMI[]`，该 POU 与 `PLC_MainPRG` 调用已由 MCP 确认；所以真机下载后：
1. 上位机点位页地轨工位同步面板 → **`diff`** 预览（`pull_sync(confirm=false)` / `diff_sync`，读 `Rail_Pos_HMI[]` 对照 `value`，此刻 6 行差 = 现场教值 − 0）。
2. 核对教值合理（限位内）→ **`pull`(confirm=true)**：`pull_sync` 写 6 个教值进 `rail.yaml.value` 并重算下发 `Rail_Pos_Target[]`（[points_service.py:792](../eit_ptlc/controller/points_service.py#L792)）。
3. 此后 `rail.yaml.value` 成真源（git 管，可回退），自动跑 PC 真值。
