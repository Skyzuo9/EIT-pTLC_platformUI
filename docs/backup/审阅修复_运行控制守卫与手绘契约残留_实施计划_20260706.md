## 0. 修改原则（第一性原理）

1. **守卫贴在动作上，不贴在按钮上**：不变量必须在"发生不可逆动作"的那一处强制，而不是散在若干 UI 按钮的 `:disabled` 上——UI 状态会因异步/竞态与真实动作失步。
2. **一个契约只有一个数**：前后端/多层若共享一个阈值（如手绘最小点数），它必须在所有层取同一值；round‑1 只对齐了三层、漏了第四层就是本轮 T1.2 的根。
3. **改机制、不加特例**：能在"谓词/单一判定处"收口的（如 `is_knob_var`、失败码哨兵），就不在各调用点分别打补丁。
4. **动硬件的改动求最小爆炸半径**：以"全量离线测试保持绿 + 新增针对性回归"为闸门。
5. **不为未观测输入写代码（YAGNI），但已观测/已文档化的语义漂移必须收口**：纯假设项显式推迟，只留注释/监控。

## 3. Tier 1 — 上机前必修

### T1.1 修 #1：`launch()`/`启动` 绕过 `activeElsewhere` 守卫（run/edit 解耦被击穿）

**根因**：守卫散在工具条——`run()/step()/stepInto()`（`DebugDock.vue:121‑123`）各自 `if (activeElsewhere.value) return`，按钮各带 `:disabled`。但真正的起跑动作 `launch()`（`:107`）与 `启动` 按钮（`:193`）**没有**这层守卫。竞态窗口：本页空闲时点"运行"（守卫通过）→ `begin()` 是 async（`await loadKnobs()`）→ 面板打开——此间别处 `operation_start` 到达 → `activeElsewhere` 翻真、工具条禁用，**但已打开的面板 `启动` 仍可点** → `launch()→debug.start(本流程)` 起跑竞争 run，且 `start()` 同步清空在跑 run 的 `hitl/logs/snapshot`。

**修法**（守卫落到动作处 + 按钮禁用；一处 token 级 + 一处属性）：
```js
// eit_ptlc/web/src/components/editor/DebugDock.vue
function launch() {
  if (activeElsewhere.value) return          // ← 新增: 面板打开后归属被夺走时兜底拦截 (@keyup.enter 也走此处)
  inputForm.open = false
  debug.start(editor.current.name, collectInputs(), sys.mode, inputForm.modeRun, inputForm.startAid, collectOverrides())
}
```
```html
<!-- 模板 :193 -->
<button class="tb save" :disabled="activeElsewhere" @click="launch">启动</button>
```
> `begin()` 的直接起跑 else‑分支由 `run()/step()` 前置守卫覆盖；`launch()` 的新守卫覆盖"面板已开后归属变化"的竞态窗口与 `@keyup.enter`。二者合起来堵住全部起跑入口。
> 可选深化（低优先）：把"禁止在归属别处时起跑/续跑"抽成 `DebugDock` 内一个 `guardActive()` 单一闸，`run/step/stepInto/launch` 统一走它，杜绝将来再漏一个入口。

**测试**：`utils/runControl.js` 已有纯函数 `isRunActiveElsewhere`；补一条 DebugDock 交互/单测断言"`activeElsewhere` 为真时 `launch()` 不调 `debug.start`"（可用现有前端测试范式；若无 DOM 测试，至少在 `runControl` 层加注释锚点 + 手测清单一条）。

**不变量**：浏览别的流程绝不终结/劫持在跑的 run（[[run-vs-edit-decoupling]]）。

### T1.2 修 #2：3 点手绘在生产 contour 策略下静默退化成外接矩形

**根因**：契约的"最小点数"这**一个数**分裂在四层。round‑1（上一轮 #8）把前端 `_ready()`、`_require_polygon`、`sketch_path.polygon_to_contour_cm`（`:222` 的 `if len(poly) < 3: raise`）都对齐到 **3**，却漏了真正的消费者——未改动的 `cnc_path._load_band_geometry`（`cnc_path.py:492`）：
```python
if contour_arr.shape[0] < 4:
    contour_arr = None      # 点太少 → contour 策略回落 bbox 蛇形
```
生产 `app.yaml:174` 是 `path_strategy: contour`，故 3 点三角形 → `contour_arr=None` → 刮取**外接矩形**而非三角形。`sketch_path` docstring 却宣称"扫描线对任意多边形(≥3 点)鲁棒"——自相矛盾，且**静默**（无报错、仅 WYSIWYG 预览的青线泄露真相）。

**修法（收敛到一个数）**——二选一，先做投石验证再定：
- **首选（深化，保能力、兑现 docstring）**：验证 `cnc_path` 扫描线（`_split_contour_to_top_bot`/scanline）对 3 顶点简单多边形是否真鲁棒。若是 → 把守卫从 `< 4` 降到 `< 3`（三角形＝合法闭合多边形），**并加一条契约回归**：contour 策略下 3 点手绘产出的路径 XY 跨度贴合三角形而非其 bbox。
- **退化（全层对齐到 4，最小爆炸半径、不动共享 cnc_path）**：若扫描线确不支持 3 点 → 把 `polygon_to_contour_cm`、前端 `_ready()`、`_require_polygon` 的下限升到 **4**，改 docstring，并把 `test_triangle_three_points_is_accepted` 改为**断言显式拒绝**（422/ValueError），而非现在断言"接受且 400 点"（该测试正掩盖了本 bug——它用默认 boustrophedon 且只查点数）。

> 判据：生产策略是 contour，故本条要么让三角形"真按 contour 刮"，要么"明确拒绝"，**杜绝静默退化 bbox**。推荐首选（三角形是合法区域，且预览已 WYSIWYG）。无论哪支，都**必须**新增一条 contour 策略下的形状回归。

**不变量**：所见即所跑；手绘接受集 = cnc_path 能忠实执行集。

## 4. Tier 2 — 尽快（正确性 / 健壮性）

### T2.1 修 #4：PALLAS 失败码哨兵过严 → 可恢复失败被升级为 run FAILED

**根因**：`_is_fail_code_sentinel`（`:318`）用 `int(text)`，`"111.0"`/`" 111 "` 等非规范渲染 → `ValueError` → 落空 → 抛 `PallasVisionResultError`。成功结果恒为逗号分隔≥2 浮点，故**单值**载荷本就不可能是合法成功——放宽到"数值相等"不会误伤。

**修法**（数值相等，不截断——避免把 111.9 误判为 111）：
```python
def _is_fail_code_sentinel(text: str, err_fail_code: int) -> bool:
    """整段是否恰为失败码的数值（容忍空白/小数渲染, 如 "111"/"111.0"/" 111 "）。
    成功结果恒为逗号分隔≥2数, 单值即不可能是合法成功; float() 天然拒逗号/多 token。"""
    try:
        return float(text.strip()) == float(err_fail_code)   # 111.0==111, 111.9≠111, "a,b"→ValueError
    except (TypeError, ValueError):
        return False
```
**测试**：`test_plate_offset_handshake_offline` 补 `"111.0"`/`" 111 "` → `valid=False`；`"111.9"` 与 `"222"`（≠默认码）仍抛错（不放松错误判定）。

### T2.3 修 #6：单原子动作运行的死跳转 + 全页锁

**根因**：`app.py:177` 单动作 `operation_start` 携 `operation=<动作 id>`（如 `robot.home`），与 VM 流程 `operation=<脚本名>`（`thread.py:102`）**同键异义**。`debug.operation` 无判别 → `jumpToRunning`（`:21`）跳 `/library/operation/robot.home` 死路由；且单动作期间 idle 流程页全被 `activeElsewhere` 锁、逃生跳转失效。

**设计判断**：单原子动作**确实**占用硬件，故锁流程页起跑是对的（别在 home 时起流程）——保留锁，只修跳转。

**修法**（源头携判别，前端按之分流）：
```python
# api/app.py:177 —— 单动作事件标注 atomic
emit({"type": "operation_start", "operation": name, "atomic": True, "run_id": rid, "label": label, "ts": t0})
```
```js
// stores/debug.js: ingest 的 operation_start 分支回灌
operationAtomic.value = !!event.atomic       // 新增 store 字段, 默认 false; VM 流程不带 atomic
```
```js
// DebugDock.vue
function jumpToRunning() {
  if (debug.operationAtomic) return          // 原子动作无编辑页 → 不跳转
  if (debug.operation) router.push(`/library/operation/${debug.operation}`)
}
```
```html
<button v-if="activeElsewhere" class="run-elsewhere" :class="{ 'no-jump': debug.operationAtomic }"
        @click="jumpToRunning">
  运行中: {{ debug.operation }}{{ debug.operationAtomic ? ' (原子动作)' : ' · 跳转 ▸' }}
</button>
```
> 零后端改动的退化方案：前端以"`operation` 含 `.` ⇒ 动作 id"启发式判别（`robot.home` 有点、`sampling_prepare` 无点）。**不推荐**（脆弱），仅作无法改 app.py 时的兜底。

**测试**：`test_vm_api`/前端：单动作 `operation_start(atomic:true)` → 跳转不触发 `router.push`。

```python
    return (vd.get("io") == "in" and isinstance(vd.get("ui"), dict)
            and isinstance(vd.get("name"), str) and bool(vd.get("name"))
            and isinstance(vd.get("type"), str))
```
