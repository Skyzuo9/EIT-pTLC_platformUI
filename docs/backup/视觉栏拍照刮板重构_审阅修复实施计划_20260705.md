## 0. 修改原则（奥卡姆剃刀）

1. **按根因合并**：15 条 finding 真正独立的根因只有少数几个，一处修法覆盖一类。
2. **改机制、不加特例**：优先修底层不变量（如 VM "失败动作不得污染 assign 目标"），而非在编排里层层打补丁。
3. **不为未观测的输入写代码**（YAGNI）：纯假设/纯潜在的项显式**推迟**，只留监控或注释。
4. **动硬件的改动求最小爆炸半径**：VM 级根因改动一律以"全量离线测试保持绿"为闸门，必要时退化为局部方案。

## 3. Tier 1 — 上机前必修（两处硬件风险，改动极小）

### T1.1 修 #1：`cnc` 被污染 → 崩溃卡板 —— 改 VM 根因（一个 token）

根因：VM 在动作失败 `raise` 前**先把结果写进了 assign 目标**（`vm/thread.py:290` 写、`:293` 抛）；被拒动作的 `res.result` 默认是 `{}`（`action/models.py:74`），于是失败的重试 cnc_path 把好端端的 `cnc` 冲成 `{}`，而 try/catch 只是注释、`cand_valid` 仍 true。二者失步 → 下发喂空 dict → `{}["g_sx"]` `KeyError`（`vm/expr.py:143`）→ run() 只接 VmRaise/VmActionError/VmError/CancelledError（`:107-119`），KeyError 逃逸未捕获 → 无 operation_failed、`_finish` 不跑、`press_cylinder(true)` 永不释放。

```python
# eit_ptlc/operation/vm/thread.py  _op_call
self.last_result = res
if node.get("assign") and res.ok:          # ← 仅加 and res.ok
    self._write(frame, node["assign"]["var"], res.result)
self._emit_node_done(node, path, res.status.value, res.message, res.result)
if not res.ok:
    raise VmActionError(res)
```

"**失败动作不得污染它的 assign 目标**"是一条干净的 VM 不变量，一处修好整类问题：失败重试不再改 `cnc`，旧的有效 v1 保留、`cnc` 与 `cand_valid` 重新同步、下发跑 v1（正确）；初次视觉失败时 `cnc` 未置、`cand_valid=false` → 下发被守卫挡住（不变）。
`analyze` 动作恒返回 `res.ok=True`（DONE，内部 ok:false 由 result 承载），**不受影响**。

- **闸门**：跑全量离线测试保持 98 绿。
- **退化方案（若某测试依赖"读失败动作结果"）**：不动 VM，改编排——重试 try 里 `assign: {var: cnc_next}`，其后 `assign cnc = cnc_next`（仅成功才执行），手绘/重识别 2 处；`cnc_next` 加一个局部变量声明。零 VM 爆炸半径。

### T1.2 修 #2：归属守卫失效开门 → 误续跑 —— ingest 回填（2 行）

根因：`_apply` 已从事件回灌 runId/status/currentScript，独缺 `operation`；而 `operation_start` 事件本就带流程名（`vm/thread.py:98` emit `"operation": name`，runs.js 已在用）。

```js
// eit_ptlc/web/src/stores/debug.js  ingest()  —— 增一个分支
} else if (t === 'operation_start') {
  operation.value = event.operation || ''
}
```

补这一条后，刷新 / 多标签 / 他人屏幕上 `isRunActiveElsewhere` 不再因 `operation===''` 而 false-open；DebugDock 正确禁用起跑/步进并给跳转横幅。
