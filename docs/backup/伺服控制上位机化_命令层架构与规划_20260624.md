# 伺服控制上位机化 — 命令层架构与规划

> 文档定位: **架构规划 / 讨论稿**。与 PLC/HMI 协同的对齐基线; 定稿后再派生可粘贴的 `PLC交付_*` / `HMI交付_*`。

## 1. 背景与结论

起点是一个弱需求: 把伺服**运动速度**纳入上位机 action 参数。grilling 厘清后收敛为:

- 速度本身的**纯控制需求很弱** — 手动调速 HMI 已够 (操作员屏上改 `fVelocity`, 掉电不丢)。
- 速度真正有价值的是**可复现** — 把当时生效的速度记进 run 记录。
- 但速度不是独立问题, 它是**伺服命令的一个字段**。真正的大事是"伺服控制(jog / move-to-point / stop)上位机化", 速度搭车即可。
- 因此本规划的对象 = **伺服命令层上位机化**, 速度作为命令字段一并纳入。

**核心结论 (承重墙)**: 见 §3。开放伺服命令给上位机 = 给伺服命令源加"自动模式分支"(抄气缸模式门套路), **与地轨 L2 双向对账完全无关**, 两条线解耦。

## 2. 现状事实 (0624 快照分析, 带旧行号)

本节依据 2026-06-24 的 [eit_ptlc/plc/Now.xml](../../eit_ptlc/plc/Now.xml) 快照（不含 PLC_MainPRG 的 POU 子集）。这些行号只作历史定位；若要执行当前改造或验收，先用 MCP 直读 `.project` 复核对应 POU/GVL。

### 2.1 速度
- **定位速度 `fVelocity`: 11 轴全部走 `*DATE.fVelocity` 结构体字段, 无一硬编码** ([Now.xml:10673](../../eit_ptlc/plc/Now.xml#L10673) 等 11 处)。当前唯一写者 = HMI。
- `servoaxisdate` GVL 声明 `retain="true" persistent="true"` ([Now.xml:6994](../../eit_ptlc/plc/Now.xml#L6994)) → **HMI 改的速度掉电不丢**, 但只活在 PLC 保持区+触摸屏, 对上位机/版本库不可见。
- **加减速/JOG 速度 `fAcc`/`fDec`/`fJogVel`: 11 轴全部硬编码, 且按轴物理整定** (点样6X=5500/5500/50 [Now.xml:10772](../../eit_ptlc/plc/Now.xml#L10772); 上样4X=200/200/5 [Now.xml:10971](../../eit_ptlc/plc/Now.xml#L10971); 玻璃1Z=1000/1000/15 [Now.xml:10674](../../eit_ptlc/plc/Now.xml#L10674))。**不动。**

### 2.2 模式仲裁 (已存在)
- 全局 `xManualAuto` (FALSE=手动 / TRUE=自动)、`FB_Mode`(`xAutoMode`) ([Now.xml:5021](../../eit_ptlc/plc/Now.xml#L5021))。
- 气缸 FB 已用"按模式选命令源"写法 ([Now.xml:3749](../../eit_ptlc/plc/Now.xml#L3749)):
  ```
  IF xManualAuto THEN bEnableCmd1 := xAutoExtend;   // 自动 → 上位机源
  ELSE                bEnableCmd1 := xManualExtend;  // 手动 → HMI 源
  ```
- 伺服已有模式门: [Now.xml:494](../../eit_ptlc/plc/Now.xml#L494) `IF Mode<>1 ...` (非自动模式下伺服使能逻辑)。

### 2.3 上位机现有通道
- 上位机不直接碰 DATE 结构体, 只通过 `Host_Computer` GVL 节点说话 ([plc_nodes.yaml](../../eit_ptlc/config/plc_nodes.yaml))。
- 该表里**没有任何速度节点**, 也**没有伺服直接命令(jog/MoveAbs)节点**。
- 现有伺服运动 = **L2 动作步序内部触发** (`Sampling_L2_ActionCode` 等驱动步序设 `xMoveAbs`; 拍照如 [Now.xml:10308](../../eit_ptlc/plc/Now.xml#L10308))。位置真源走 `*_Target` (如 `Photo_8Y_Target` 已是活的真机模式)。

## 3. 承重墙边界 (本规划的判据)

"HMI 与上位机双写"分两类, 代价差一个数量级, **绝不能混**:

| | 命令仲裁 (Command) | 持久 set-point 对账 (Stored truth) |
|---|---|---|
| 是什么 | jog / move-to-point / stop / **运动速度** | 示教点位等持久真源 |
| 冲突本质 | "现在谁开这根轴", 时间互斥 | "两边记的值漂移了", 长期 |
| 解法 | **模式门** (`xManualAuto` 选命令源) | **地轨 L2 双向握手** (PUSH/PULL/Ack) |
| 代价 | 低, 气缸已验证 | 高, 地轨那套 |
| 同时写者 | **永不并发** (要么手动要么自动) | 会, 故需握手 |

**边界划定**: HMI 主**手动调试**, 上位机主**自动生产**, 设计上**永不并发抢轴**。
→ 本规划只动**命令层**, 不碰 L2。机器人之所以干净 = 永远自动单主; 伺服只多一个手动主, 而 `xManualAuto` 已能仲裁。

> 详见项目记忆 `command-vs-setpoint-boundary`。L2 现状: **保留为长期桥** (调试时上位机可能离线, 地轨移动依赖 HMI 记录点位); 删除触发条件 = "PC 离线靠 HMI 示教救援"需求消失。本规划不影响该决定。

> **2026-06-24 XML 快照补充（当前需 MCP 复核）**: 新增 `PLC_HandWheel_手轮` POU ([Now.xml:3504](../../eit_ptlc/plc/Now.xml#L3504)，`FB_HandWheel`+`HC_Counter`，门控 `MODE_State<>1` 即仅手动模式) —— 物理手轮脉冲驱动 3Y/4X/5Z/6X/7Y/8Y 等轴。它是**又一个手动侧写者**，**坚定落在承重墙手动侧**（与本规划要加的"上位机自动命令源"正交、靠 `xManualAuto` 仲裁、不并发），不是本规划要做的 PC 命令层 jog（仍未实现，规划有效）。另新增 `PLC_CNC` POU ([Now.xml:1156](../../eit_ptlc/plc/Now.xml#L1156)，`SMC_Interpolator`) 属刮板/拍照 CNC，与本伺服命令规划无关。

## 4. 范围: 做 / 不做

### 做
- **首批 5 轴**: 上样4X、上样3Y、点样6X、点样7Y、拍照8Y (已有 `*_Target`/`*_ActPos` 镜像模式, 命令源扩展边际成本最低)。
- 给这 5 轴的伺服命令加**自动模式命令源** (上位机可 move-to-point / jog / stop)。
- 命令携带**速度字段** (自动模式下上位机指定的运动速度)。
- **可复现记录**: run 记录里落"本次各轴实际生效速度"。

### 不做 (明确排除)
- ❌ 不碰地轨 L2 双向对账 (与命令层无关; L2 保留为长期桥)。
- ❌ 不改 `fAcc`/`fDec`/`fJogVel` (按轴物理整定, 硬编码保留)。
- ❌ 不动 HMI 手动调速路径 (操作员照旧屏上改; 手动模式下 HMI 源生效)。
- ❌ 首批不含 FeedLift(1Z/2Z)、刮板(9X/10Z)、地轨(11Y) — 验证 5 轴模式后再推广。

## 5. 实施方案 (草案, 含核心设计待决)

### 5.1 PLC 侧: 伺服命令的自动模式分支 (7-A 已锁定)
**结论 (0624 锁定): 采 (a) 直接命令通道, 经 `Host_Computer` 命令节点 + 模式门对 HMI 裸结构体源做 `SEL`。** 抄气缸 [Now.xml:3749](../../eit_ptlc/plc/Now.xml#L3749) 套路。

对 5 轴, 把 `FB_SERVOAXIS` 的命令输入从"单 HMI 源"改为"模式门选源":
```
xJogPos    := SEL(xAutoMode, 地轨轴11YDATE.xJogPos, Host.X_JogPos);   // 手动:HMI 裸结构体源 / 自动:PC Host 节点源
xMoveAbs   := SEL(xAutoMode, DATE.xMoveAbs,          Host.X_MoveAbs);
xStop      := SEL(xAutoMode, DATE.xStop,             Host.X_Stop);
fAbsTarget := SEL(xAutoMode, DATE.fAbsTarget,        Host.X_Target);  // 自动取上位机目标
fVelocity  := SEL(xAutoMode, DATE.fVelocity,         Host.X_Vel);     // 自动取上位机速度
```

**关键约束 (承重墙)**:
- HMI 源 = **沿用现有 `*DATE.*` 裸结构体字段** (HMI 经标签通讯如 `标签通讯_301_1.Application.servoaxisdate.地轨轴11YDATE.xJogPos` 照旧直写; 手动模式生效, **不动**)。
- PC 源 = **必须是 `Host_Computer` 节点**, **严禁 PC 直接写 `servoaxisdate` 裸结构体**。
- 现有 `*DATE.*` 字段天然成为"HMI/手动源", 无需额外造 HMI 侧中间变量; 只新增 PC 侧 Host 节点, PLC 在 FB 入口按 `xAutoMode` 选源。

> **为何否决"PC 直接写同一裸结构体变量"**: (1) 破坏 Host_Computer curated 契约边界, 与已否决的"PC 写 position[]"同一反模式; (2) HMI 与 PC 写同一物理 bit = 真竞争, 模式门无法仲裁 (SEL 需两个独立源); 约定式单写者无 PLC 侧防御, 比 `SEL` 脆弱。

### 5.2 Host_Computer 新节点 (按 7-A=(a) 定型)
PC 写命令源 (每轴): `X_JogPos`/`X_JogNeg`(Bool)、`X_MoveAbs`(Bool)、`X_Stop`(Bool)、`X_Target`(Double, 5 轴部分已有 `*_Target`)、`X_Vel`(Double)。
PLC 写镜像 (每轴, 只读): `X_ActPos`(Double, 部分已有)、`X_Vel_ActPos`(Double, 用于 L0 记录)。
> 命名沿用现有惯例 (如 `Sampling_4X_*`/`Photo_8Y_*`); 完整节点表待派生 `PLC交付_*` 时逐轴列。
> **速度记录 (L0) 最小集 = 仅 `X_Vel_ActPos` 只读镜像** (复刻 `*_ActPos` 模式), 零双写者, 不依赖命令源改造 → 作为 **P1 独立先落**。

### 5.3 上位机侧
- action/节点注册扩展 (已有 action→VM→executor 模式)。
- 伺服 jog/move-to-point action (参考机器人点动/运动到点的现有实现)。
- run 记录新增"生效速度"字段。

## 7. 待决项与风险

- **A. 命令通道形态** (§5.1): ✅ **已锁定 (0624)** = (a) 直接命令通道, 经 Host_Computer 命令节点 + 模式门对 HMI 裸结构体源做 SEL。否决 PC 直写裸结构体 (理由见 §5.1)。
- **B. 速度先做哪档**: 建议 P1 先做 L0 纯记录 (零风险拿到可复现), P2 再做命令下发。
- **C. 限位/速度钳制落在哪端**: 建议 **PLC 钳制** (防御纵深, 上位机给坏值不致撞轴); 上位机可加软上下限做 UX。
- **D. 速度上下限取值**: 各轴安全速度区间需 PLC/机械确认。
- **E. 模式切换瞬间的安全**: 自动↔手动切换时命令源跳变, 需确认不产生意外运动 (沿用气缸/现有伺服模式门的既有处理)。
- **F. 记录字段定义**: run 记录里"生效速度"按轴存还是按动作存; 单位 (mm/s)。
