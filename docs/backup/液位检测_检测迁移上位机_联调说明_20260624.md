# 液位检测 — 检测迁移上位机 联调说明 (2026-06-24)

## 1. 背景与动机

香橙派算力有限：8 路 1080p 同开时单进程串行 CV + GIL 把每路压到 ~1 FPS。而溶剂前沿监测**非时间敏感**（1–2s 一次足矣），且检测结果当前只用于监控显示（不进闭环）。

按边缘计算范式重排分工：**香橙派只抓帧，上位机定时拉帧 + 检测**。检测目标也从"绝对高度 cm"改为"**溶剂前沿到达 ROI 的百分比**"——8 缸结构相同、相机等高，百分比是无量纲相对量，无需 QR 绝对标定/scale_factor；用**面积占比**法（浸润像素/ROI 总像素），对前沿不纯平天然鲁棒（横向积分平均）。

## 2. 架构变化

```
迁移前:  香橙派 [抓帧 → 完整CV检测 → height_cm] --MQTT--> 上位机 [快照] → UI
迁移后:  香橙派 [抓帧, /frame 端点]  <--HTTP拉帧-- 上位机 [面积占比检测 → percent] → UI
                 (--no-detect)                    (WaterLevelDetectService, 2s)
```

- **香橙派**：`--no-detect` 开关，CAPTURE 通道只抓帧（保留 `latest_frame` 供 `/frame/ch{N}` 端点），不跑 CV、不上报 height_cm。算力释放，8 路不再卡。
- **上位机**：`WaterLevelDetectService` 每 2s 对活跃通道 HTTP 拉单帧 → `detect_level` 算 percent → 快照供 API/UI。**标定真源在上位机**（`config/water_level_calib.json`）。
- **设备在线**仍走香橙派 MQTT LWT；**视频流**仍经 `/api/water_level/stream/` 代理（`--no-detect` 下为原始帧）。

## 4. 部署与启动

### 4.1 标定迁移（现场为手动 ROI，零重标）

把香橙派上的 `water_level_config.json`（含各通道 `calibration` + `roi_manual`）拷到上位机：

```
香橙派:  ~/Desktop/work/water_level_config.json
   ↓ 拷贝
上位机:  <config 目录>/water_level_calib.json
```

加载器兼容香橙派嵌套格式，自动提取 `rotation_angle_deg` + `roi_bbox` + `flow_direction`。无 `roi_manual`（auto 模式）的通道 → 未标定，需在 UI 数值 ROI 补标。

### 4.2 香橙派：只抓帧模式

`run.sh` 启动命令追加 `--no-detect`（或经上位机 SSH 远程启动时注入）：

```bash
python3 water_level_8ch_compress_mqtt.py --tl_bl_cm 15.0 \
    --cameras /dev/camera1,...,/dev/camera8 \
    --broker 192.168.0.168 --no-detect
```

### 4.3 上位机：起 real app

`config/app.yaml` 的 `water_level` 段已含 `detect_interval: 2.0`；`calib_path` 留空则取 `config/water_level_calib.json`。

```
EIT_MODE=real  uvicorn eit_ptlc.runtime.bootstrap:app
```

起服务后 detect service 自动：读标定 → 激活已标定通道香橙派相机（MQTT `set_active_channels`）→ 每 2s 拉帧检测。

## 5. 验证清单

| # | 检查 | 预期 |
|---|------|------|
| 1 | `GET /api/water_level/snapshot` | `online=true`；`channels[ch].percent` 有值，`reachable=true` |
| 2 | 前端 8 路网格 | 各路显示百分比（非 `—.— %`），状态"检测中" |
| 3 | 单路调试页「采集参考图」 | 干板时采集；之后前沿推进 percent 随之上升 |
| 4 | 数值 ROI「应用 ROI」 | `config/water_level_calib.json` 该通道 `roi_bbox` 更新 |
| 5 | 参数滑块改动 | 即时写入并持久化；刷新页面「读取」回显新值 |
| 6 | 香橙派 CPU | 8 路同开不再满载（已不跑 CV） |

## 6. 回退方案

去掉香橙派启动的 `--no-detect` 即恢复香橙派本地检测（检测代码未删除）。上位机 detect service 仍并行拉帧检测，两者互不冲突；UI 显示以上位机 percent 为准。

## 7. 已知限制 / 后续

- **视频"调试面板"**：依赖香橙派 `process_frame` 的 debug 缓存，`--no-detect` 下为空（黑屏属正常）。上位机检测可视化叠加（ROI/前沿线/percent）为后续增强。
- **auto ROI 通道**：迁移后无 ROI，需 UI 数值补标（或后续移植 `detect_roi` 自动找板边）。
- **删香橙派旧检测死代码**：待真机验证占比算法（参考图差分 + 阈值）在真实硅胶板有效后再清理。
- **活跃通道**：当前默认"已标定通道"全检；`ResourceManager` 装配后可经 `svc.set_active_channels` 收窄为占用展缸。
