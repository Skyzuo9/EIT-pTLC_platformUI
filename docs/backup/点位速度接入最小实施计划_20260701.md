## 2. 最小实施顺序

### A. 4X 清洗位运行期闭环

1. 新增动作 `sampling.push_wash_target`：`kind: servo_target`，`targets: [sampling_4x_wash]`。
2. 在所有会调用 `sampling.clean` 的 operation 前插入该动作，至少覆盖：
   - `config/operation/01_sampling/sampling_prepare.yaml`
   - `config/operation/01_sampling/sampling_full.yaml`
   - `config/operation/01_sampling/sampling_cycle.yaml`
   - `config/operation/09_full/ptlc_full.yaml`
3. 保持 `sampling.clean` 本身参数不变，避免已有调用突然缺参。
4. 验证：配置自检、action registry 校验、`test_servo_target_offline.py`、`test_action_executor_offline.py` 中补一条 `sampling.push_wash_target` / clean 前置顺序用例。

退出标准：`Sampling_4X_WashTarget` 在 `sampling.clean` 触发前完成写入和回读确认；失败时不触发清洗 L2。

### B. 5Z 点位接入

1. 先用 MCP 在 PLC 工程内补 `Sampling_5Z_Target` / `Sampling_5Z_ActPos`，并明确 5Z 到底消费哪个旧槽位或目标态。
2. 修改对应 POU：5Z 执行 step 改读 `Sampling_5Z_Target`，无条件镜像 `Sampling_5Z_ActPos := ...fActPos`。
3. MCP 编译通过后，再把 `config/points/plc/sampling.yaml` 的 `sample_5z` 清 `pending`。
4. 点位页做一次种子：jog 到位、读 ActPos、存 value、push target。
5. 只有验收通过后，才把 5Z 放入生产 operation。

退出标准：`sample_5z` actpos/push 在 DEBUG 下可用，RUN 下写入拒绝，PLC step 真实读 flat target。

### C. 条带速度验收

1. 保持当前专用链路：`sampling.spot_band_layer` 的 `spot_speed_mm_s` / `dry_speed_mm_s` 只服务 action 62。
2. 在 operation 中显式保留默认值或工艺参数来源，避免 UI/脚本调用时速度参数缺省不透明。
3. 真机跑两组速度：低速安全值、高速但限位内值；观察 6X 液体扫线速度、吹干速度、A0 完成且 Q 查询空闲后进入 dry cycles。
4. 若需要其它轴速度参数化，另开小设计：先列“哪个 action 消费速度、PLC 是否已有通道、是否影响 HMI 手动速度”，不要直接做通用 speed 层。

退出标准：动作 62 在不同 `spot_speed_mm_s` / `dry_speed_mm_s` 下有可观察速度差异，且泵停/吹干时序不退化。

## 4. 不做事项

- 不再用 XML 导出判断 PLC 当前实现是否完成。
- 不让 PC 写 HMI `position[]` struct，不让 HMI 写 `*_Target` 真源。
- 不把 5Z pending 绕过保护强行下发。
- 不在本轮做“所有伺服轴通用速度控制”；条带速度先作为 Sampling action 62 的专用能力验收。
