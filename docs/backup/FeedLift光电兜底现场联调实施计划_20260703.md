# FeedLift 光电兜底现场联调实施计划

日期: 2026-07-03

## 1. 当前故障结论

现象:

```json
{
  "action": "feedlift.feed_raise",
  "status": "ERROR",
  "accepted": true,
  "error_code": 303,
  "message": "PLC L2 动作失败: station=FeedLift action=11 seq=8 state=ERROR error=303"
}
```

第一性原理判断:

- `accepted: true` 说明上位机已经完成 L2 请求派发，PLC 也接受了本次 action。它不是“上位机完全没打到 PLC”的错误。
- `error_code: 303` 是 FeedLift 光电兜底合同内定义的搜索 target 配置非法: `low >= high`。
- 当前 `eit_ptlc/config/points/plc/feedlift.yaml` 中 4 个搜索边界点位仍是初始值 `0.0`。因此 `feedlift.feed_raise` 在 Start 前实际预写的是:
  - `FeedLift_1Z_SearchLowTarget = 0.0`
  - `FeedLift_1Z_SearchHighTarget = 0.0`
- PLC 在 `A11_feed_raise` 进入动作前按合同拒绝 `low >= high`，所以快速返回 303 是预期保护动作。

结论: 当前首要问题不是继续改 PLC 程序，而是补齐 FeedLift 搜索窗口点位的现场种子值，并让上位机在 Start 前更早暴露非法窗口。

## 2. 奥卡姆边界

本轮先不改 PLC ST。

理由:

- PLC 已经能返回 FeedLift 专用错误码 303，说明 code 11 的 L2 分发和错误回传链路可达。
- 303 的语义已经足够具体，且与当前上位机点位初值完全吻合。
- 在没有真实 1Z/2Z 行程、光电边沿和安全边界数据前，继续改 PLC 只会把“未标定点位”误诊成“程序逻辑错误”。

只有在现场种子后仍出现以下情况，才进入 PLC 改动:

- 上位机写入并回读确认 `low < high`，但 PLC 仍报 303。
- action 明显朝错误方向 jog。
- 到达窗口边界后没有停机保护。
- 光电已稳定达到期望状态，但 PLC 仍报 304/305。

## 3. 现场种子步骤

### 3.1 前置确认

1. 确认当前下载到 PLC 的工程包含 FeedLift 光电兜底候选程序。
2. 确认 OPC UA 可读写以下 flat 节点:
   - `FeedLift_1Z_ActPos`
   - `FeedLift_2Z_ActPos`
   - `FeedLift_1Z_SearchLowTarget`
   - `FeedLift_1Z_SearchHighTarget`
   - `FeedLift_2Z_SearchLowTarget`
   - `FeedLift_2Z_SearchHighTarget`
3. 确认上位机已经加载最新动作配置，`feedlift.feed_raise` 带有 `preload_targets: [feedlift_1z_search_low, feedlift_1z_search_high]`。

### 3.2 采集 1Z 上料搜索窗口

目标: 给 `feedlift.feed_raise` 提供一个只用于有界 jog 的安全窗口，成功判据仍然是光电1稳定 TRUE。

步骤:

1. 在 DEBUG/手动模式下点动 1Z，观察 `FeedLift_1Z_ActPos`。
2. 找到一个安全低位作为 `feedlift_1z_search_low`。
3. 找到一个越过取料光电触发边沿、但仍在机械安全行程内的位置作为 `feedlift_1z_search_high`。
4. 确认 `feedlift_1z_search_low < feedlift_1z_search_high`。
5. 不要用 `0/0`、不要把不确定值写成同一个数。

### 3.3 采集 2Z 废料下料搜索窗口

目标: 给 `feedlift.unload_ready` 和 `feedlift.unload_bury` 提供 2Z 的保护窗口，避免光电漏检时继续走向零位。

步骤:

1. 在 DEBUG/手动模式下点动 2Z，观察 `FeedLift_2Z_ActPos`。
2. 找到一个不会造成撞机或继续危险下探的低位作为 `feedlift_2z_search_low`。
3. 找到一个覆盖废料放置/退出光电边沿的安全高位作为 `feedlift_2z_search_high`。
4. 确认 `feedlift_2z_search_low < feedlift_2z_search_high`。
5. 如果真实安全位置超过当前点位文件的 `limits: {max: 500.0}`，先扩大上位机点位 limits 到真实安全行程，不要为了通过校验而夹到 500。

### 3.4 写入点位

将现场采集值写入:

```yaml
plc_servo_target:
  - {key: feedlift_1z_search_low,  node: FeedLift_1Z_SearchLowTarget,  actpos: FeedLift_1Z_ActPos, label: "FeedLift 1Z 光电搜索下界", value: <1Z_LOW>,  limits: {min: <SAFE_MIN>, max: <SAFE_MAX>}}
  - {key: feedlift_1z_search_high, node: FeedLift_1Z_SearchHighTarget, actpos: FeedLift_1Z_ActPos, label: "FeedLift 1Z 光电搜索上界", value: <1Z_HIGH>, limits: {min: <SAFE_MIN>, max: <SAFE_MAX>}}
  - {key: feedlift_2z_search_low,  node: FeedLift_2Z_SearchLowTarget,  actpos: FeedLift_2Z_ActPos, label: "FeedLift 2Z 光电搜索下界", value: <2Z_LOW>,  limits: {min: <SAFE_MIN>, max: <SAFE_MAX>}}
  - {key: feedlift_2z_search_high, node: FeedLift_2Z_SearchHighTarget, actpos: FeedLift_2Z_ActPos, label: "FeedLift 2Z 光电搜索上界", value: <2Z_HIGH>, limits: {min: <SAFE_MIN>, max: <SAFE_MAX>}}
```

优先通过上位机点位页面保存；如果页面链路还不顺，直接编辑 `eit_ptlc/config/points/plc/feedlift.yaml` 后重启后端或触发配置热加载。

## 4. 验收顺序

不要一开始跑完整 operation。按下面顺序逐步放大:

1. 配置自检:

```powershell
E:\Anaconda\envs\platformupper\python.exe -m eit_ptlc.config.loader --check
```

2. 只跑 `feedlift.feed_raise`:
   - 期望不再出现 303。
   - 若无玻璃/前置传感器未满足，应得到 301。
   - 若窗口内没有稳定光电1，应得到 304。
   - 若成功找到并稳定确认光电1，应 DONE。

3. 再跑 `feedlift.feed_lower`:
   - 该动作不属于光电扫边兜底，只确认相对下降和完成反馈。

4. 再跑 `feedlift.unload_ready`:
   - 期望不再出现 303。
   - 若前置无料/传感器不满足，应得到 302。
   - 若窗口内无法稳定确认光电2 FALSE，应得到 305。

5. 最后跑 `feedlift.unload_bury`:
   - 重点观察光电2漏检时是否在 `feedlift_2z_search_low/high` 有界窗口内停住，而不是继续走向零位。

6. 单 action 全部通过后，再跑:
   - `feedlift_load_cycle`
   - `feedlift_unload_cycle`

## 5. 上位机最小补强

建议在现场种子同时加一个上位机 fail-fast 校验，避免以后再把 `0/0` 这类非法窗口下发到 PLC:

- 当 `preload_targets` 同时包含 `feedlift_1z_search_low` 和 `feedlift_1z_search_high` 时，Start 前检查 `low < high`。
- 当 `preload_targets` 同时包含 `feedlift_2z_search_low` 和 `feedlift_2z_search_high` 时，Start 前检查 `low < high`。
- 校验失败时，上位机直接返回 `REJECTED / INVALID_PARAM`，message 写明具体点位和值。
- PLC 的 303 继续保留，作为最终防线。

这一步只改上位机 Python 和离线测试，不改 PLC。

## 6. PLC 改动触发条件

当前不需要给 PLC 写新补丁。

如果完成第 3 节种子后仍然失败，再按错误码分流:

| 现象 | 优先处理 |
|---|---|
| 仍报 303 | 读回 PLC flat target，确认上位机写入值是否真到 PLC；若读回 `low < high` 仍 303，再读 PLC ST 判断是否变量接错 |
| 报 304 | 1Z 窗口没有覆盖光电1边沿，或光电1稳定时间/极性不符合实际 |
| 报 305 | 2Z 窗口没有覆盖光电2边沿，或光电2稳定时间/极性不符合实际 |
| 运动方向错误 | 进入 PLC ST 小补丁，修正 jog 方向或越界判据 |
| 到边界不停 | 进入 PLC ST 小补丁，修正停止/错误收敛分支 |

若触发 PLC 改动，由 Codex 生成独立 Markdown 补丁说明，用户复制粘贴到 InoProShop；不通过当前中文 MCP 写入链路直接改 ST。

## 7. 完成标准

本需求完成应同时满足:

- `feedlift.feed_raise` 在有效窗口下不再报 303。
- `feedlift.unload_ready` 和 `feedlift.unload_bury` 在有效窗口下不再报 303。
- 光电未达成时，PLC 返回 304/305，而不是无界继续运动。
- 光电达成且稳定时，动作返回 DONE。
- 上位机配置中 4 个 FeedLift 搜索边界点位都有现场种子值，且 `low < high`。
- 上位机 fail-fast 能在非法窗口时阻止 Start，并给出明确错误信息。
