## 0. 背景与范围

总目标：完善「点位页面」接入，支撑真机测试需求 2（真空泵 / 地轨）与需求 3（机器人 + 运动到点）。真空泵已通；本文件聚焦**伺服 / 地轨运动控制**。

业务场景（决定架构）：
- 上样区有 **2 组孔板**（当前各 4×6=24 孔，**规格可变**，如换 8×12=96 孔板）；点样是 TLC 硅胶板上的**条带**（起点→终点）；拍照是**固定位**。
- 上位机对**每种耗材只维护「类型 + 3 个标定点」**，经**仿射变换**算出全部点位；执行时**按孔/按位把绝对目标值递给 PLC，PLC 执行**。换规格＝换类型定义 + 重采 3 点，零代码改动。
- **无相机**，标定由**人工 jog 对点 + 读 fActPos** 完成。

## 1. 核心架构决策（已对齐）

### 1.1 关键发现：连续伺服自动序列**早已是「PC 给值、PLC 执行」**
交叉核对 PLC 导出（`点样上样.xml` / `拍照刮板.xml` / `机器人PLC侧程序.xml`）确认：连续伺服的运动逻辑、安全联锁（遮光/定位/下压气缸、机器人到位）、MC 调用**全部已在 PLC 既有 step 序列里**，上位机从不碰控制位。当前自动序列的目标值来源：
- **上样 4X/3Y**：读 `HMI_*.position[Sampling_X/Y_coordinate]`；而 `Sampling_X/Y_coordinate` 是 **PC 写的 flat 节点**（[plc_nodes.yaml:66-67](../eit_ptlc/config/plc_nodes.yaml#L66)），且全 PLC 代码对其**只读、无任何 `:=` 赋值** → **逐孔遍历本就由 PC 推进**。
- **点样 6X/7Y**：读 `position[2]起点 / [3]终点 / [1]清洗`。
- **拍照 8Y**：硬编码 `420`（无 HMI 槽）。

→ 所以"上位机不需要拿到伺服控制权"**不是要新建运动引擎**（初稿的 per-axis MoveAbsolute 大派发器被否决），而是把**目标值的来源**从「HMI 示教槽 / 常量」改成「PC 专用目标节点」。

### 1.2 决策：连续伺服目标改由 PC 专用 flat 节点下发（**B 方案，单写者**）
| 方案 | 取舍 | 理由 |
|---|---|---|
| 上位机直驱 `T_servo` 控制位（`xMoveAbs`/`fAbsTarget`） | ❌ 否决 | 抢 `FB_SERVOAXIS`/`FB_Teach`/自动流程的控制位 |
| PC 写 HMI `position[]` 槽（A / 混合） | ❌ 否决 | 与 HMI 共写同一 struct → **双写者** + 整 struct 读改写有竞争窗；槽数有限（96 孔装不下） |
| **PC 写专用 `*_Target` flat 节点，PLC 读它（B）** | ✅ 采用 | **单写者**干净；不碰 HMI；类型安全；无槽数上限；天然支持按孔推送与变规格 |

### 1.3 单写者不变式（核心）
| 变量 | 容器 | 唯一写者 | 读者 | 用途 |
|---|---|---|---|---|
| `position[]` | `HMI_Date`(T_HMI_Servo) | **HMI**(FB_Teach) | HMI 召回 / 固定服务位 | 人工示教/召回；清洗/升降等固定位 —— **PC 永不写** |
| `*_Target`（新, LREAL） | `Host_Computer` | **PC** | PLC 自动序列 | 仿射绝对目标，按孔/按位推送 |
| `*_ActPos`（新, LREAL） | `Host_Computer` | **PLC**（镜像 `fActPos`） | PC | 实际位置**只读**，实时显示 + 标定采点 |

→ 每个变量恰好一个写者；初稿担心的"抢控制位/边沿握手"被消解。**HMI 示教/召回链路完全不动（不破坏 HMI）**。（注：2026-06-23 路径 T 在此基础上更进一步——HMI 显示/召回改读 `*_Target`、`position[]` 对迁移轴退役，达成零代差，见 §6.A。）

### 1.4 本轮只迁「随规格/批次变化或需频繁微调」的目标；服务位暂留 HMI 槽（范围决定，**非**安全约束）
本轮把**会变的目标**改走 PC 节点：①仿射算出的逐孔目标（上样 4X / 打样 3Y）；②按带 / 需手动微调的点样点表（点样 6X 起止、7Y、拍照 8Y，非仿射）。清洗位 / 取板位 / 升降档 / home 等**不随规格变化的服务位本轮继续读 HMI 槽**，以缩小本轮 PLC 改动面。

> **澄清（勿误读为单写者约束）**：服务位留在 HMI 槽**不是**因为"迁了会坏单写者"。干净全迁（PLC 改读 `*_Target`、PC 成为唯一写者、HMI 不再参与该值）**仍然是单写者**。单写者不变式（§1.3）只禁止 §1.2 否决的 A/混合方案（PC 写进 HMI `position[]` struct → 双写 + RMW 竞争）。**是否迁移是一条归属策略选择，不是 affine-vs-fixed 的技术分界**——逐位置判据见 §4.A，方向已由 §6.A 路径 T 定为"点位页统管所有伺服点位"。

### 1.5 读 fActPos 也走 flat 镜像，彻底不碰整 struct
附图（标签通讯配置）证实每伺服轴在 OPC UA 上是**一个 struct 整 tag（length 81，单地址）= ExtensionObject**，逐成员 browse 不可行。与其在 python 侧啃自定义 struct 字节解码，**让 PLC 把要显示/标定的轴 `fActPos` 镜像成 `Host_Computer` 下的 flat LREAL**（每轴一行）。读写全部走自控的 flat 节点，OPC 上**不再触碰 `T_servo`/`T_HMI_Servo` 整 struct**。（此事实也是 §6.A 否决"PC 直写 position[]"路径 P 的硬依据。）

### 3.1 仿射算点（上位机；算法规格，非 PLC 侧）
- **输入**（每种耗材类型 + 每个板实例）：类型=逻辑网格（行列数、行列距、孔序、起止角）；标定=**人工 jog 到 3 个已知孔/角**读 `fActPos` 得 3 个实测 (X,Y)。
- **变换**：3 对（逻辑↔实测）→ 解 **2D 仿射 6 参数** `物理(X,Y) = A·逻辑(行,列) + t`（含旋转/错切，对未对正/换规格鲁棒）。
- **输出**：`well(板,行,列) → (X_4X, Y_3Y)`；点样输出条带 start/end。**执行**：按孔推送。**两组孔板各自 3 点标定**。
- 实现：[plate_affine.py](../eit_ptlc/controller/plate_affine.py) / [plate_catalog.py](../eit_ptlc/controller/plate_catalog.py) / [calibration_service.py](../eit_ptlc/controller/calibration_service.py)。

## 4.A 服务位迁移判据（逐位置裁决；后续批次）

> 分界线不是"仿射 vs 固定"、也不是单写者，而是**归属策略**：哪些点位归上位机点位页拥有/编辑（团队已据此迁了非仿射的点样/拍照）。**2026-06-23 §6.A 路径 T 已把"点位页统管所有伺服点位"定为方向，下表"后续/最后批次"已正式进入 §6.A 待办。**

**判据**：①值会变吗（随规格/批次/需微调 → 越该迁）②是否仅 L2 内读（是 → 冷启 `*_Target`=0 无害；否 → 需安全默认/上电策略）③blast radius（HMI 示教/调试段/legacy 读者越多越要同步处理，避免"一值两源"）。

| 位置 | 值会变？ | blast radius | 裁决 |
|---|---|---|---|
| 各轴归零 `:=0` | — | — | **永不迁**（是 home/参考 0，非点位） |
| 上样 4X/3Y（仿射逐孔） | ✅ | 小 | **已迁** |
| 点样 6X 起止/7Y/拍照 8Y（点表） | ✅ | 小 | **已迁**（非仿射，因"点位页即写者"） |
| 6X 清洗 / 7Y 取板 / 5Z 升降 | ❌ | 中（HMI 示教 + 调试段读） | **后续批次**：迁时须同步示教/调试读；**5Z 已纳入 §6.A** |
| 地轨 11Y `position[1..6]` | ❌ | 大（legacy `Now.xml:64834+` 读最多） | **最后批次**：先维持召回 |

> 怎么做：作为**独立干净批次**（迁 L2 读 + 同步示教/调试读 + 每个 `*_Target` 给安全默认/上电策略），不混进在制交付。一个 pull：机器人取放已原子化为上位机 operation，取板位/地轨值本就需 PC 侧可寻址，是后续最该进 PC 点表的候选。

## 6.A 路径 T：单一真源 + 无代差 + 上位机点位模型统一（2026-06-23 拍板）

> 背景：点位页"PLC 伺服点位全部无法回读/示教"。根因三层：① 真机 24 个新 flat 变量**未进 OPC 符号配置**（[PLC交付:26](PLC交付_伺服B方案_可复制粘贴_20260623.md#L26) 上真机第一项核对）；② 上位机点位模型把每根轴拆成"死 struct 条目 + 另名 target 条目"，用户点到死的那个；③ 5Z/地轨/服务位本就未迁 flat（§4.A 后续批次）。

**决策 1 — 单一真源 = flat `*_Target`，HMI 改读它（路径 T）。** 否决"PC 直接写 HMI `position[]`"（路径 P）：真机伺服轴是单 ExtensionObject（length 81，§1.5），逐成员寻址不可行，需整 struct 字节解码 + RMW 竞争。改为：

| | 写者 | 读者 | 持久真源 |
|---|---|---|---|
| `*_Target`（flat，不 retain） | **PC**（唯一） | PLC step ✅ + **HMI 面板显示/召回（改读）** | PC 端 `plc/<工位>.yaml`，连接后回推 |
| `position[]`（HMI struct） | HMI 示教链（存量） | 迁移轴**退役**（HMI 改读 `*_Target`） | — |

→ PC 示教写 `*_Target`、HMI 读同一 `*_Target` ⇒ **零代差**；不碰 ExtensionObject；单写者不变式保持。仿射轴（上样 4X/3Y）无"示教单点"（真值是 calibration.yaml 3 点解），不存在代差，维持 `push_well`。
