### 5.3 程序体（粘贴到 `Rail_L2` 的 ST 编辑区，照 `Pump_L2` 范式）

> ⚠️ **此为 B 方案初版 `Rail_L2`（读 HMI `position[]`）。真机现状已演进两代**：①地轨双源收编→改读 `Rail_Pos_Target[]`；②0624 防御加固→加 `fTgt` 有效性校验 + `ErrorCode:=102`。**真机当前形态以 [PLC交付_地轨双源同步_Rail_Sync §步骤2+步骤5](PLC交付_地轨双源同步_Rail_Sync_可复制粘贴_20260623.md) 为准**（Now.xml [4715](../eit_ptlc/plc/Now.xml#L4715)/[4760](../eit_ptlc/plc/Now.xml#L4760)）。下方块留作 B 方案派发器骨架记录。

```iecst
(* 地轨 11Y L2 统一动作派发器 (第7通道).
   按位置码移地轨: Rail_L2_ActionCode=10 -> 移到 HMI_地轨轴11Y.position[Rail_Target_Position] (1..6).
   地轨真值仍在 HMI 槽 (legacy 召回不变); 本派发器仅加上位机独立触发通道.
   Start 上升沿接受 -> RUNNING 下发移动 -> bAbMoveDone=DONE. *)
L2_StartTrig(CLK := Rail_L2_Start);

CASE Rail_L2_State OF
	0:  (* IDLE *)
		Rail_L2_Step := 0;
		IF L2_StartTrig.Q THEN
			Rail_L2_AcceptedSeq := Rail_L2_RequestSeq;
			Rail_L2_ActiveCode  := Rail_L2_ActionCode;
			Rail_L2_ErrorCode   := 0;
			Rail_L2_Retryable   := FALSE;
			IF Rail_L2_ActionCode = 10
			   AND Rail_Target_Position >= 1 AND Rail_Target_Position <= 6 THEN
				Rail_L2_SafeState := 0;
				地轨轴11YDATE.fAbsTarget := HMI_地轨轴11Y.position[Rail_Target_Position];
				地轨轴11YDATE.xMoveAbs   := TRUE;
				Rail_L2_State := 10;   (* RUNNING *)
			ELSE
				Rail_L2_ErrorCode    := 101;  (* 未知动作码 / 非法位置码 *)
				Rail_L2_Retryable    := TRUE;
				Rail_L2_CompletedSeq := Rail_L2_AcceptedSeq;
				Rail_L2_State        := 30;   (* REJECTED *)
			END_IF
		END_IF

	10: (* RUNNING *)
		IF Rail_L2_Reset THEN                 (* RUNNING 中 RESET: 中止回 IDLE *)
			地轨轴11YDATE.xMoveAbs := FALSE;
			Rail_L2_State := 0;
		ELSIF 地轨轴11YDATE.bAbMoveDone THEN
			地轨轴11YDATE.xMoveAbs   := FALSE;
			Rail_L2_CompletedSeq := Rail_L2_AcceptedSeq;
			Rail_L2_State        := 20;   (* DONE *)
		END_IF
		(* 如地轨伺服有报警位, 在此 ELSIF <报警> THEN 置 Rail_L2_ErrorCode + State:=40 *)

	20, 30, 40, 50:  (* 终态: 等 Start 落沿或 Reset 回 IDLE *)
		IF (NOT Rail_L2_Start) OR Rail_L2_Reset THEN
			Rail_L2_State := 0;
		END_IF
END_CASE
```

## 上位机写 / PLC 读 时序契约（无新 PLC 代码，仅约定 + 实现保证）

步骤 2 把 `A50/A60/A34` 的目标右值改读 flat 节点（`Sampling_4X/3Y_Target`、`Spot_6X_Start/EndTarget`、`Spot_7Y_Target`、`Photo_8Y_Target`）。**这些 `_Target` 何时被写**由下面契约钉死，PLC 侧无需额外逻辑：

1. **写在触发之前**：上位机把目标写进 `_Target`，发生在对应工位 L2 动作（吸液 50 / 点样 60 / 拍照 34）的 `*_L2_Start` 上升沿**之前**。上位机的 L2 派发器本就是「先 `write_many` 写参数 → 再置 `Start`」的顺序（见 `controller/plc_controller.py`），目标节点作为前置 push 原子写入，排在触发原子之前。
2. **运行期 PLC 单读不写**：`A50/A60/A34` 仅在 `State=RUNNING` 且对应 `ActiveCode` 下被调用，此时 `_Target` 已是稳定值；PLC 在动作内任何 step（含 A60 起↔止往复）读到的都是同一目标。`_Target` 为单写者（仅 PC 写），PLC 不回写。
3. **多带按编排循环**：多带点样 = 上位机「写 `Spot_7Y_Target`(本带) → 触发 spot(60) → 等 DONE → 下一带」的逐带循环；A60 维持「一次往复画一条带」语义不变，PLC **无需为多带改动**。

> 推论：架构文档里「写早被旧值覆盖 / 写晚读到陈旧」的担忧由「写在 Start 之前」这一不变量在设计上消解，不依赖真机逐拍对齐。PLC 工程师只需确认 `A50/A60/A34` 内**不存在**在动作执行中途再次把 `_Target` 覆盖回 HMI 槽 / 常量的残留行（步骤 2 的保留清单已排除固定服务位）。
