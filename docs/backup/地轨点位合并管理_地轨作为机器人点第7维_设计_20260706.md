# 地轨与机器人点位合并管理:地轨作为机器人点的第 7 维 —— 设计

日期:2026-07-06 · 分支:`codex/ui-upper-next` · 状态:**Win A(数据+回填+加载期校验)已落地,离线全套件 446 绿;Win B(运行期 auto-rail)待真机独立里程碑**。本文已归档 `docs/backup/`。实施暴露的三处修正见 §9。

---

## 0. 一句话

把"地轨目标位"从**编排层散落的 `rail_move_safe(槽码)` 字面量**收编成**每个机器人点自带的一个维度**:点 = `(rail, pose6/joint6)`。`move_to_point(P)` 内部自己把地轨开到 `P.rail` 再走臂;编排层再也不写地轨字面量。地轨与点位从**两处真源人肉对账**,变成**一处真源**——本周 `5b55a83 → aa34bf8 → fb91d2b → 4d2c38c` 那串"改一腿崩另一腿"的地鼠,从此在类型层面不可能发生。

---

## 1. 为什么必须做:一个由"解耦"逼出的 bug 类别

暂存A 一块货架,物理上可由**多种 `(地轨, 点位)` 配对**到达:

| 用途 | 点位族 | 正确地轨 | 来源 |
|---|---|---|---|
| 个体小夹爪 取收集器→刮板 | `staging-a.P46-51` | 位2 (168) | 06-19 示教, 用户真机确认 |
| 个体 收集器 return 回暂存A | `staging-a-return.P78-83` | 位3 (350) | 坐标验证 + fb91d2b |
| 整板大夹爪 rack↔暂存A | `group-staging.P37/P39` | 位3 (350) | 用户真机金标准 + 4d2c38c |

地轨是**外部轴**,和臂位姿(tool1/flange 系)是耦合的(经验 `world_X ≈ −rail + armX`,s≈−1)。同一块货架用不同夹爪/不同抓取姿态,**需要不同的地轨槽**——这不是错误,是物理。

但当前架构把"地轨"当**工位级全局标量**散在编排 YAML 里:

```
- rail_move_safe(N)      # 地轨:一处
- robot.move_to_point(P) # 点位:另一处
```

两者的配对**只靠人和注释维护**。于是每次有人动"暂存A 的地轨",就按"暂存A=某个槽"这个**并不存在的全局前提**去改,必然改对一腿、崩掉另一腿:

- `5b55a83`:把 pick 也翻位3 → **pick 崩**(P46-51@350 抓空),return/组@位3 恰对。
- `aa34bf8`:pick 回位2(对),return/组**一起**回位2 → **return/组崩**(P78-83/P37-39 在位2 差 182mm)。
- `fb91d2b` / `4d2c38c`:分别把 return、整板组修回位3。

**根因不是谁粗心,是"地轨"和"点位"没有共同真源。** 只要它们分开填,配对错误就永远可犯。合并成一个维度,编译期/加载期即可判死。

## 2. 现状(已核实,2026-07-06)

- **机器人点真源** `config/points/robot/robot_points.json`:74 点,每点 `{id, name, alias, pose[6], joint[6], tool, user}` —— **无地轨字段**。
- **派生点** `robot_points_meta.json`:`overrides`(逐点微调)、`supplement`(base_point + offset 派生,如 `*.near/.high/.far`)、`grids`(货架仿射网格)。派生点**继承** base 点。
- **地轨真源** `config/points/plc/rail.yaml`:`plc_servo` 6 槽(slot 1-6 → mm),PLC 侧 `Rail_L2` 离散召回派发器,`rail.move(Rail_Target_Position: 1-6)`(`actions/06_rail/plc_rail.yaml`,action_code 10)。
- **安全移轨宏** `operation/08_rail/rail_move_safe.yaml`:先 `robot.require_anchor(P1)`(不在安全位则失败停流程),再 `rail.move(target)`。移轨会拖着整臂平移,故必须先回安全位——**这是地轨区别于普通关节的唯一点**。
- **派发路径**:VM `run_script/call` → `action/executor.py`:`_exec_robot`(move_to_point/require_anchor,`method=="move_to_point"` 合成速度档)、`_exec_plc_l2`(rail.move 走 L2);点位解析走 `controller/points_service.py` 的 `PointRegistry`(含派生点)。
- **既有不变式**([[ptlc-atomics-no-nested-rail]]):原子动作不嵌套地轨,由编排段首拥有一次移轨。现为**注释约定**,无强制。

## 3. 决策脊梁(逐条定案,勿回退)

1. **地轨是机器人点的第 7 维,不是工位属性。** 因为同一工位/同一货架可有多个不同地轨的点(见 §1 表)。故 `rail` 存**在点上**,不存在 station 上。
2. **rail 存槽码(int 1-6),非 mm。** 与 `rail.yaml` 离散召回模型 + PLC `Rail_Target_Position` 一致;槽→mm 的映射仍由 `rail.yaml` 单独持有(mm 是槽的属性,可示教微调)。槽码还自带语义可读性(位1上样 vs 位2刮板 同 168 但意图不同)。
3. **派生点/网格继承 base 点的 rail。** `.near/.high/.far`、货架网格,rail 跟着 base 走,不单独声明。
4. **编排层彻底不出现地轨字面量。** `rail_move_safe(N)` 从所有 operation YAML 移除;地轨随点自动到位。`rail_move_safe` 降为 rail-aware move 原语的**内部实现**(安全门保留)。
5. **rail-aware move 原语内建"缩安全位→移轨→伸"编排。** `move_to_point(P)`:若 `当前槽 ≠ P.rail` → 先回安全位 P1(经 require_anchor 门)→ `rail.move(P.rail)` → 再走臂到 P;若 `当前槽 == P.rail` → 直接走臂(幂等,不移轨)。移轨的碰撞安全从"人记得先回家"变成"原语保证"。
6. **"原子动作内地轨恒定"从注释升为加载期硬校验。** ~~一个原子 operation 内所有引用点的 `rail` 必须相同~~ → **修正(§9-2):共享原子是多态的(按 rack_id/slot 分支含多族点),应为"每条可执行分支内 rail 恒定";校验须分支感知。** 跨点 rail 不一致 → `config.loader --check` 报错。地轨只在**编排接缝**处随点变。
7. **迁移即"最后一次对账"。** 给 74 点回填 `rail` 是一次性动作;填完这辈子不再对账。回填值以**真机金标准**为准(见 §5 表),不靠坐标推断(教训:pose 是 flange 系,跨夹爪货位不能用 pose 直接判同位,真机 > 推断)。
8. **增量迁移,按工位切,不 big-bang。** 先加字段 + 原语 + 校验(关闭态),再逐工位把 operation 从 `rail_move_safe` 切到"点带 rail",每切一工位离线绿 + 真机 dry-run。全切完再删 `rail_move_safe` 的编排级调用。
9. **示教闭环连地轨一起记。** `points_service` teach_* / `TeachVerify.vue` 示教提交时,把当前地轨槽写进点的 `rail`;复核退进近/二次进入全程地轨不动(本就是原子内恒定)。
10. **兼容缺 rail 的旧点:显式 sentinel + 校验拦。** 迁移期未回填的点 `rail=None`;rail-aware move 遇 `None` 则**不自动移轨**(退化为当前行为,依赖编排残留的 rail_move_safe),并由 `--check` 列为"未迁移"待办,杜绝"默默按位1走"。

## 4. 目标数据模型

### 4.1 点 schema 增量(`robot_points.json`)

```jsonc
{
  "name": "P39", "alias": "Area_6_15",
  "pose": [564.13, -48.99, 37.21, ...], "joint": [...],
  "tool": 1, "user": 0,
  "rail": 3            // ← 新增: 示教时所在地轨槽 (1-6); 缺省 null=未迁移
}
```

> **修正(§9-1):`rail` 实际落 `robot_points_meta.json` 的 `overrides`,不在 `robot_points.json`。** 后者是纯示教几何(pose/joint);workstation/role/status 等语义本就在 meta.overrides,rail 同类。上面示意保留以说明"逻辑上在点上"。

派生点(supplement/grid)不写 `rail`,解析时从 base 点继承。

### 4.2 rail-aware move 原语(伪码,落在 executor/robot 层)

```
def move_to_point(P):
    rail = resolve_rail(P)                 # 点自带 or base 继承; None=未迁移
    if rail is not None and current_rail() != rail:
        assert_or_return_safe(P1)          # = rail_move_safe 的安全门
        rail.move(rail)                    # L2 离散召回, 等 DONE
    robot.move_to_point(P.pose, profile)   # 原臂运动
```

### 4.3 编排前后对比(以 `transfer_collector_staging_a_to_rack` 为例)

```yaml
# 之前 (地轨字面量 + 点位, 两处):
- rail_move_safe(target: 3)            # 人肉保证 3 配 P39
- robot_group_staging_pick(collector)  # 内部走 P39
- rail_move_safe(target: 6)
- robot_group_rack_put(collector, slot)

# 之后 (地轨随点, 一处):
- robot_group_staging_pick(collector)  # P39.rail=3, 原语自动移轨到3
- robot_group_rack_put(collector, slot)# P25-36.rail=6, 自动移轨到6
```

## 6. 分阶段实施

- **Phase 0 — 字段与解析(纯增量,零行为变化)**
  `robot_points.json` 加 `rail`(全 null);`PointRegistry` 解析 `rail` + 派生继承;`points_service` 暴露 `point.rail`。离线测试:解析不炸、旧行为不变。
- **Phase 1 — rail-aware move 原语(关闭态)**
  在 robot/executor 层实现 §4.2;`rail=None` 时退化为当前行为(不自动移轨)。加单元测试:`current_rail != P.rail` 触发安全门+移轨;`==` 时幂等不动;`None` 时不动。
- **Phase 2 — 回填 + 逐工位切换**
  按 §5 回填 rail(逐点真机复核);逐个 operation 删 `rail_move_safe` 字面量、依赖点带 rail;每切一工位:`--check` 绿 + 离线套件绿 + 真机 dry-run。**先切暂存A(本周血泪区),再瓶链,再货架,最后各站。**
- **Phase 3 — 硬校验 + 清退**
  加载期校验"原子动作内 rail 恒定"([[ptlc-atomics-no-nested-rail]] 落地);全工位切完后,删 `rail_move_safe` 的编排级调用(保留安全门为原语内部);`contract` 测试从"断言 rail 序列"改为"断言点带正确 rail"。
- **Phase 4 — 示教闭环带地轨**
  `points_service` teach_* / `TeachVerify.vue` 示教提交写 `rail`;新示教的点天然自带地轨,再不产生"点在位X、编排喂位Y"的错配。

## 7. 风险与回滚

- **移轨安全门丢失** → 原语必须内建 require_anchor(P1);Phase 1 单测强制覆盖"移轨前必回安全位"。
- **派生点 rail 继承漏** → Phase 0 测试覆盖 supplement/grid 继承;缺失即 `--check` 报未迁移。
- **增量期两套并存混乱** → `rail=None` sentinel + `--check` 列未迁移清单,禁止默默走位1;每工位切换独立可回滚(git revert 单 op)。
- **rail.yaml 槽→mm 仍是隐真源** → 本设计不动 mm 层(mm 是槽属性,示教微调),只把"点该用哪个槽"收编;槽码稳定。

## 9. 实施回写与验证(2026-07-06 · Win A 落地)

按 **Win A(安全核心:数据 + 回填 + 加载期校验,纯离线可验,近零风险)/ Win B(运行期 auto-rail,真机门控)** 拆分。用户定:**先落 Win A**,Win B 作独立里程碑上真机再切。**Win A 已落地,离线全套件 446 passed / 6 skipped。** 实施暴露三处对本设计的修正:

**§9-1 · rail 落 `meta.overrides`,非 `robot_points.json`(改 §4.1)。** `robot_points.json` 是纯示教几何;`workstation/role/status/acc/vel/cp` 等语义本就在 `overrides`、经 `replace(point,**override)` 并入,rail 同类。放设备导出会把点的语义劈成两半。(Dobot 不再导出该文件、示教改上位机,"被冲掉"顾虑作废,但"一致性 + 示教闭环本就写 overrides"仍成立。)派生点/网格 rail 继承机制不变。

**§9-2 · 决策 #6 改"每分支 rail 恒定",非"原子内恒定"。** 共享原子 `robot_individual_pick/put` **多态**——按 `(rack_id, slot)` 分支,同文件含 collector 点@位2 与 bottle 点@位3 两套分支;原子整体横跨多轨是正常的。硬校验须**分支感知**(绑 `rack_id` + 注入 `slot/tank` 让 `if` guard 求值,只断言被选中路径),否则每个暂存点假报多槽。

**§9-3 · 设槽有两种机制,校验须都追(新增)。** `rail_move_safe`(run_script,含 P1 安全门,转运用)**与直接 `rail.move` action call**(无安全门,**全流程 `ptlc_full_v2` + 各 demo 持板中途移轨专用**)。派生/校验的 `current_rail` 必须两者都追,否则整个全流程被误判。此盲区一度把显影缸误报成 `[2,5]` 冲突;修复后三条 develop 流程(`ptlc_full_v2`/`develop_demo`/`single_sample_demo`)一致 = **位5(展开位)**,无 bug。

**Win B 判据修正(待实施):** auto-rail 判"要不要移轨 / 回 P1"按**目标槽 mm 与实际 mm 之差**(位1=位2=168、位5=位6=600,槽码→mm 不可逆;`plc_controller.read_rail_pose()` 已可读实际 mm + Homed,尚未进运动路径)。**内部判据用 mm,暴露业务参数仍是槽码。**

**落地物(足迹 3 文件):**
- `controller/point_registry.py`:`RobotPoint.rail: int|None` + overrides/supplement/grid 继承 + 校验(1-6/null)。
- `config/points/robot/robot_points_meta.json`:回填 46 族 → **210/239 点**带 rail(1:16 / 2:41 / 3:64 / 4:9 / 5:32 / 6:48);仍 null = 占位点 + transit/ready/home/hub + 未在流程中确定到达的闲置点(均正确豁免)。
- `tests/test_rail_point_consistency_offline.py`:分支感知校验(**读 point.rail 断言 == 流程 current_rail**,不靠走图推断 rail);证非空(354+ 断言 / 18 流程)+ 抓得住(翻 P39→位2 抓到 `aa34bf8` 那条腿;翻 tank→位2 抓到)。

## 10. Win B Phase 1 落地(2026-07-07 · 关闭态原语 + 单测,纯离线)

按 §6 Phase 1「rail-aware move 原语(关闭态)」落地,**默认关 ⇒ 真机现行为冻结,一个 `rail_move_safe` 字面量都没删**。开关式增量切换的**机制现已离线建好并验证**,只剩「到真机翻开关 + 逐工位删字面量 + dry-run」(Phase 2/3,§6)。

**关键设计定案(与用户对齐):**
- **原语落 executor 的 `_exec_robot`,不改 `move_to_point` 签名。** 因 `move_to_point` 在 `robot_controller` 是同步,`rail.move` 走异步 plc;executor 是唯一同时握 `self._robot`(sync via run_in_executor)与 `self._plc`(async)的 async 落点。移轨**复用 `rail.move` 动作管线**(含 `_exec_plc_l2` 的 `sync_group` 单写者回读确认 + L2 派发),不重造。
- **地轨归属仍只在点位层(`meta.overrides.rail`)。** 链路 = `action → 点位 → rail`;action/operation 都不持有地轨。管理靠点位层:逐个示教(Phase 4 写 `rail`)/ 直接改 override 单值 / base·grid 继承批量改。
- **判据用 mm(§9-4 兑现)。** `PointsService.rail_slot_mm(slot)` 给目标槽 mm,`plc.read_rail_pose()` 给实际 mm+Homed;差 <= `_RAIL_MM_TOL`(5mm)即幂等不动(**含同 mm 异槽:位1↔位2=168、位5↔位6=600 不无谓移轨**);超差先 `require_anchor(P1)` 安全门再移轨。未回零 → ERROR 拒判(不拿脏位)。

**落地物(足迹 5 文件,全离线):**
- `config/models.py` + `config/loader.py` + `config/app.yaml`:`PLCCfg.auto_rail: bool=False`(开关,默认关)。
- `controller/points_service.py`:`rail_slot_mm(slot)->mm|None`(槽→mm 真源查询)。
- `action/executor.py`:`ActionExecutor(auto_rail=...)` + `_ensure_rail_for_point()` 原语 + `_exec_robot` 的 move_to_point 分支前插桩(**关/rail=None/plc缺失/无mm映射 → 放行零行为变化**)。
- `runtime/bootstrap.py`:`auto_rail=config.plc.auto_rail` 注入。
- `tests/test_auto_rail_move_offline.py`(**新增**):6 例确定性覆盖 —— 开关关零行为 / 未收编 sentinel 放行 / 同 mm 异槽幂等 / 异 mm「安全门→移轨→走臂」时序 / 不在安全位 UNSAFE 拦截(不移轨不走臂)/ 未回零 ERROR。

**验证:** 新单测 6/6 绿;离线全套件 **454 passed / 537 subtests passed**(exit 0,无 skip 无失败),证 `auto_rail` 关时 move_to_point 路径零回归。

**待真机(Phase 2/3):** 翻 `auto_rail: true` → 逐工位(先暂存A)删 `rail_move_safe` 字面量 + dry-run 连跑;全切完删编排级字面量、加载期校验从"断言 rail 序列"改"断言点带正确 rail"。**运行期移轨时序、`read_rail_pose` 节点在真机的可读性 仍须真机验。**
