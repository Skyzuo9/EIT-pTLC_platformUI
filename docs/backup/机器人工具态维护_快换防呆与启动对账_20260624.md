# 机器人工具态维护 — 快换防呆与启动对账

> 文档定位: **已实施 (as-built)**。机器人运动层 (上位机直驱 Dobot) 的工具态承重墙; 设计已落地为 driver/executor/operation 实现 + 离线测试。
> 日期: 2026-06-24 规划 · 2026-06-24 实施  ·  来源: 2026-06-24 grilling 对齐 (operation 复刻旧 lua 核对)
> 关联: [eit_ptlc active architecture]、operation 复刻缺口核对 (缺口C = 快换未编排)
> 范围: 本轮做了 待办项1-3 (驱动承重墙 / 启动对账 / 缺口C 换刀编排) + 缺口A (翻面)。缺口B (上样2D纠偏)、显影完成门仍占位。

---

## 1. 背景与结论

operation 复刻旧机器人 lua 时发现: 新流程把硅胶板/展缸用 `suction-*`、收集器/瓶/夹具用 `gripper-*`，但**顶层 `ptlc_full_v2` 从不调 `robot_tool_pick/put`，工具态无人维护**。这是个安全隐患，不是并行调度问题，必须现在解决。

**核心结论 (承重墙)**: 待守护的不变量 =

> "DO2/DO6 这两个手腕输出位的物理含义，取决于当前挂载的是哪个工具；任何与当前工具不符的 `tool_action` 都不许发出。"

这是关于**机器人末端硬件**的不变量，应放在**所有 DO 写入的唯一收口 = 驱动/transport 层**。编排层只决定"何时换刀"，驱动负责"挂错就拒发"。

## 2. 现状事实 (已查证, 带行号)

### 2.1 三个快换工具，DO2/DO6 双义
真机有 **3 个快换工具**: slot1 = 旋转吸附工具 (硅胶板/展缸)、slot2 = 大夹持、slot3 = 小夹持 (收集器/瓶/夹具/货架组)。

末端 DO 位 ([dobot_tcp_driver.py:202-208](../eit_ptlc/driver/dobot_tcp_driver.py#L202-L208), [:532-553](../eit_ptlc/driver/dobot_tcp_driver.py#L532-L553)):
- `DO1` = 快换锁(0)/松(1)
- `DO3` = 真空吸(1)/放(0)
- **`DO2`/`DO6` 含义随挂载工具而变**:
  - 挂吸盘工具 → 翻转气缸: `DO2=1` 翻上 (旧 lua 等 `DI(1)`)、`DO6=1` 翻下 (等 `DI(2)`) — 见旧 [global.lua:292/324/402](../机器人程序/机器人程序v0.11/HHWS_tjcx2/global.lua#L292)
  - 挂夹爪工具 → 夹爪: `DO2=1` 合、`DO6=1` 开
- 驱动里 `ROTARY_UP/DOWN` 与 `GRIPPER_CLOSE/OPEN` 是**同一组 DO 位、两套语义**——**都要保留**，不是冗余别名。差异: gripper 版有可选 DI 确认，rotary 版当前无 (补翻面时需补 DI 反馈)。

### 2.2 无工具挂载 DI 反馈
机器人**没有**"当前挂了哪个工具"的 DI 反馈 → 驱动无法自证当前工具，必须靠显式来源。

### 2.3 裸 DO 旁路
维护页 `set_do` ([dobot_tcp_driver.py:572](../eit_ptlc/driver/dobot_tcp_driver.py#L572)) 直写 DO，通道白名单 `{1,2,3,6}`，**不走语义白名单**——是工具态的旁路点。

## 3. 设计决策

### 3.1 驱动持权威工具态
- 驱动持 `current_tool ∈ {UNKNOWN, NONE, 1, 2, 3}` (UNKNOWN=未声明, NONE=裸腕)。
- `tool_action` 进来先校验"动作 ∈ 当前工具允许集"，不符**直接报错** (`PermissionError` → executor 归一为 REJECT/UNSAFE):
  - slot1 (吸盘): `{suction-on, suction-off, rotary-up, rotary-down}`
  - slot2/3 (夹爪): `{gripper-open, gripper-close}`
  - `quick-change-lock/release`、**`tool-change-aux-on/off`**、`get-state`: **永远放行** (与工具无关)。
    *(实施修正: aux 物理上也写 DO6/DO2, 但属换刀联轴语义, 发生在"工具尚未声明"窗口, 必须放行才能完成挂/卸刀。原讨论稿 §3.1 漏列, 已补。)*
- 把 DO2/DO6 双义隐患在唯一收口物理掐死。
- **实施落点**: `MountedTool` 枚举 + `TOOL_ALLOWED_ACTIONS` / `TOOL_AGNOSTIC_ACTIONS` 表 (`driver/robot_transport.py`); 门控 `_assert_tool_allows` 在 `tool_action` 入口先于动作锁执行 (`driver/dobot_tcp_driver.py`)。

### 3.2 工具身份来源 (无 DI)
身份不来自 DO (快换只锁联轴器、不带身份)，三个来源:
1. **`robot_tool_pick(tool_id)`** 快换锁定后**显式通知** `set_mounted_tool(tool_id)`；`robot_tool_put` → `set_mounted_tool(0=NONE)`。
2. **启动显式声明** (见 §3.3)。
3. **裸 DO 标脏** (见 §3.4)。
- **实施落点 (方案A)**: 新增 VM 动作 `robot.set_mounted_tool(tool_id)` (`config/actions/07_robot/robot.yaml` → `RobotController.set_mounted_tool` → `transport.set_mounted_tool`)。它不是 DO 写、不是 `ToolAction`, 是纯权威态赋值。流程引擎加 `set_mounted_tool` 步类型 (`robot_flow.py`/`robot_plan.py`/`gen_robot_point_operations.py`)；`tool.pick` 模板锁定+辅助后插 `from_selector` 声明 (生成各分支 lit 1/2/3)，`tool.put` 释放+辅助关后插声明 0。**不让驱动反向解析编排语义** (否决方案B)。

### 3.3 启动对账 (无 DI 版)
- 上电/上位机启动 `current_tool = UNKNOWN`，**不臆测默认值**。未声明前任何语义 `tool_action` 报错。
- 维护页 **「工具态对账」区** (`RobotJogPanel.vue`): 回显当前挂载 (未声明标红) + 声明下拉 {无 / 吸盘 / 大夹持 / 小夹持} + 「声明」按钮 (调 `robot.set_mounted_tool`)。
- 上次声明值**持久化磁盘**，下次启动作**预填建议但永不自动应用** (断电期间可能被手动换过，无 DI 无法自证，确认即安全门)。
- **实施落点 (持久化定论)**: 真源 = `config/robot_tool_state.json` (跟随 `water_level_calib.json` 先例)。持久化与权威态**同层 (驱动)**: `set_mounted_tool` 写盘、构造时读盘入 `_tool_suggestion`，`_mounted_tool` 永远从 UNKNOWN 起。`ToolState` 透出 `mounted_tool` / `mounted_tool_suggestion`，executor `_feedback_to_dict` 序列化给 UI。
  *(对 §4 表的偏离: 持久化挂在驱动而非 executor —— 因 `set_mounted_tool` 是 pick/put 编排与 UI 声明的共同收口下方唯一单点, 同层持久最内聚; "上位机/executor" 仅指声明入口 UI。)*

### 3.4 裸 DO 旁路处理
- 维护页裸 `set_do` 保留为**显式越权** (操作员自负责)。
- 但一旦裸口动了手腕定义位 `DO1`/`DO2`/`DO6`，将 `current_tool` 标记 **UNKNOWN(脏)**，强制下次重新声明对账。(`DO3` 真空不影响工具身份，不标脏。)
- **实施落点**: `set_do` 命中 `{1,2,6}` → `_mounted_tool = UNKNOWN` (`dobot_tcp_driver.py`)。

### 3.5 换刀编排 (缺口C, 编排层职责) — 已实施
- 在工具边界插 `robot_tool_put(当前) + robot_tool_pick(目标)`，由**下一个动作所需工具**驱动。
- 注意 3 工具 ⇒ 不止"吸↔夹"，**大夹持↔小夹持之间也是一次快换**。
- **工具映射 (0624 确认)**: 收集器 / 收集瓶 = **小夹持 (slot3)**；耗材板 = **大夹持 (slot2)**；硅胶板 = 吸盘 (slot1)。
- **`ptlc_full_v2` 实施**: 工具序列 吸盘(步1-4) → 小夹持(步5 收集器) → 吸盘(步6)。已插两处过渡: 步4↔5 `put(1)+pick(3)`、步5↔6 `put(3)+pick(1)`。**前提**: 入口须已挂吸盘并声明 (启动对账)，收尾停在吸盘 → 周期自洽 (无需开头多余 pick)。本 demo 流程不含耗材板, 故未触发大夹持; 大/小夹持切换待真机含耗材板的流程再按上表编排。

## 5. 缺口A 翻面 (rotary) — 已实施

旧 lua 翻面语义 (核实, 带行号 [global.lua:292/324/366](../机器人程序/机器人程序v0.11/HHWS_tjcx2/global.lua#L292)):

| 站 | 翻面时机 | DO 序列 | DI 等待 |
|---|---|---|---|
| 展缸 tank (put/pick) | 进缸前 **下翻** | `DO(6,1)` | DI2 |
| 点样 spotting **放板** (suction.put) | 置板前 **上翻**、释板后 **下翻** | 上 `DO(2,1)`/下 `DO(6,1)` | 上 DI1 / 下 DI2 |
| 点样 spotting **取板** (suction.pick) | 取板前 **上翻** | `DO(2,1)` | DI1 |
| 刮板 scrape / 废料 waste | **不翻** | — | — |

- **驱动层 (A1)**: `rotary-up` 等 **DI1**、`rotary-down` 等 **DI2** (与 gripper 的 DI 映射相反 ⇒ 证两套语义)，沿用 `tool_di_feedback_enabled` 开关；切位间补 **200ms 互锁** (先清反向 DO 再给正向 DO，旧 lua `Wait(200)`)。落点 `dobot_tcp_driver.py` `tool_action`。
- **编排层 (A2)**: tank.pick/put 模板首步直插 `rotary-down` (模板仅服务 tank，安全)；spotting 用 **route-group extension** (`flip_before_pick` / `flip_before_put` / `flip_after_put` 仅在 `spotting-*` point_set 定义，scrape/waste 解析为空) ⇒ 翻面只对 tank/spotting 生效。落点 `config/backup/robot_flows_v2.yaml` + 重生成。
