# PLC 完整下载启动安全修复与首次真机验收（2026-07-21）

## 目标

- 解决汇川 PLC 完整下载启动窗口内 EtherCAT、11 轴伺服及未回原点瞬时报警。
- 完整下载前安全停机、下载后等待总线稳定，并按 5Z→4X 顺序自动回零。
- 保留已实现的 `sampling.rinse_mix` 原子动作，不修改现有 Operation。
- 首次真机安装后，后续完整下载统一从上位机安全入口执行；不增加物理 HMI 下载按钮。

## 改动

- PLC 增加下载握手、启动状态、Ready、11 轴通信与首故障诊断通道。
- EtherCAT OP、13 个从站及 11 轴通信连续稳定 2 秒后才允许复位、使能和回零。
- `MC_Reset` 改为 ErrorStop 轴单次上升沿；修复 4X/5Z `bHomed` 被持续清除的问题。
- 自动启动顺序固定为 5Z 退让/回零，再执行 4X 退让/回零；状态 20 仅在所有轴断使能且静止后成立。
- 启动期间门控普通运动、手轮、示教、L2、泵及辅助执行器，并抑制启动瞬态报警。
- 上位机增加维护门、忙碌拒绝、PLC 安全握手、七阶段进度、下载后 Ready 核对和非幂等禁止重试语义。
- CODESYS IPC 增加协议/worker 指纹、一次性授权、目标 IP 回读、物理下载锁、防重放及崩溃对账。
- 修复 InoProShop 每次 `project.save()` 都改写二进制容器元数据导致授权 SHA 永远变化的问题：Host 在授权前编译并保存，worker 在守卫内只复核磁盘 SHA，不再二次保存。

## 验证结果

- CODESYS 编译：0 错误、49 警告；符号 XML 导出：0 错误、80 警告。

- 全量离线基线：800 passed、564 subtests；7 个失败为缺少 `pytest-asyncio` 和 headless OpenCV，和本改动无关。
- 第一次部署请求在 PLC 登录前因保存后 SHA 变化被安全拦截，返回 `deployed=false`，确认真机未修改。

## 已知问题

- 现场其他 EtherCAT/伺服报警已消除，但物理 HMI 仍显示 4X、5Z“未回零”两条报警。
- PLC 启动状态机已经确认 5Z、4X 回零完成并进入 Ready；当前 OPC 导出的轴故障数组也全部为 0。
- 物理 HMI 工程不在仓库，暂未确认这两条报警读取的是原始 `bHomed`、HMI 自身锁存位，还是历史报警未复位。本次按现场决定暂不继续处理。
