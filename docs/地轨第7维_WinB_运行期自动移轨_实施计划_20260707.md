## 0. 一句话

Win A 把"该用哪个槽"变成**点的属性 + 加载期校验**(字面量还得写,但写错立刻红)。
Win B 把它变成**运行期行为**:地轨随点自动到位,编排层**删掉 `rail_move_safe(N)` 字面量**——
人连写错的机会都没有(设计 §0 的终态)。**这是热路径 + 物理动作的改动,必须逐工位真机 dry-run。**

## 1. 使能事实(已在 Win A 期间核实)

1. **mm 是判据,不是槽码。** `rail.yaml` 位1=位2=168、位5=位6=600,槽码→mm 不可逆。判"要不要移轨"
   的本质是"臂会不会被物理平移",只能看 **目标槽 mm 与当前实际 mm 之差**。
2. **实际 mm 已可读。** `plc_controller.read_rail_pose() -> (mm, homed)` 已存在,现仅喂监控节点
   (`node_registry`),**尚未进运动路径**。`Rail_Homed=False` 时实际位不可信(门控)。
3. **移轨走现成 L2 安全路径。** `rail.move`(action_code 10)经 `_exec_plc_l2`,已含收编工位
   `ensure_target_confirmed` 单写者兜底(PC 真源回读确认后才下发)。
4. **幂等是关键杠杆。** "当前 mm == 目标 mm 就跳过"使原语可以**先全局开启、后逐步删字面量**:
   开启时所有字面量仍在 → 原语每次都看到"已在位"→ 纯空操作 → 零行为变化(关闭态测试)。
5. **设槽有两种机制(Win A 挖出)。** `rail_move_safe`(run_script,含 P1 安全门,空手接缝用)
   与直接 `rail.move`(无门,**持板中途**移轨用,如全流程入显影缸)。二者物理语义不同,不能一刀切。

---

## 2. 核心设计决策(逐条定案)

### 2.1 判据:mm 差,非槽码

`需要移轨 ⟺ |实际mm − 目标槽mm| > 容差(如 5mm) 且 Rail_Homed`。
位1↔位2、位5↔位6 之间是零平移 → 不移、不触发安全门。业务参数对用户仍是槽码(1-6)。

### 2.2 触发时机:**原子进入处(seam),不是每个 move_to_point**

"`move_to_point` 逐个自动移轨"**行不通**,两个硬伤:
- **共享 waypoint 无单一 rail**:原子首步常是 `move_to_point(P4=ready)`,而 P4 是多轨过渡点
  (rail=null,豁免)。真正带 rail 的 work 点(如 `staging.far`)排在几步之后;若在它身上才触发移轨,
  **臂早已离开 P1**(移到 P4 了)→ 安全门 `require_anchor(P1)` 失败。
- **移轨本就是接缝操作**:物理上地轨只在**取放相邻的接缝**处变(臂在安全锚、两段操作之间),
  不在原子内途中变(决策 #6:每分支 rail 恒定)。

**定案:地轨在原子进入处随点到位。** 每个 work 原子在其 `require_anchor(enter_anchor)` 之后、
首个动作之前,`ensure_rail(本原子·本分支的 rail)`;rail 目标**从原子的 work 点派生**(单真源)。
此刻臂在 enter_anchor(空手接缝 = P1),安全门天然满足。

### 2.3 安全锚:空手接缝自动化,持板中途保留 explicit

| 情形 | enter_anchor | Win B 处置 |
|---|---|---|
| 空手接缝(转运取/放:staging/rack/collect/tool…) | P1(home) | **`ensure_rail` 自动化 + 删 `rail_move_safe` 字面量** |
| 同槽 hub 交接(P52/P70,持板同轨接力) | P52/P70 | mm 相同 → `ensure_rail` 跳过,不动、不回家(hub 优化保留) |
| **持板中途换区**(全流程入显影缸:位2→位5) | 持板高位 | **保留 explicit `rail.move`**;`ensure_rail` 幂等与之共存(见 §2.4) |

**理由**:`rail_move_safe`(P1 门)那类**一定是空手在 P1**,`ensure_rail(require_anchor P1)` 是它的
忠实机械替身。而直接 `rail.move`(持板、故意不回 P1)编码了**不可机械复制的作者安全判断**
("这个持板高位可以就地平移地轨")——Win B **初期不自动化它们**,保留 explicit。这也正好呼应
Win A 的"两种机制"发现:只有 P1 门那类可安全自动替换。

> 注:`清退 rail_move_safe 字面量` = 删掉所有 `rail_move_safe(N)`(即用户关心的、易错的、bug 高发那批);
> 少量 `rail.move`(持板中途)仍保留 explicit。若未来要连它们也收编,需给点补 `rail_safe_anchor`
> 元数据(该点可就地平移的安全锚)+ 逐个真机确认,属 Win B 的可选延伸,不在首里程碑。

### 2.4 幂等共存:`ensure_rail` 与残留字面量不打架

`ensure_rail(R)` 只在 `实际mm != mm(R)` 时动作。开启原语时:
- 转运里 `rail_move_safe(3)` 仍在 → 先把轨设到 3 → 原子 enter 处 `ensure_rail(3)` 看到"已在位"→ 跳过。
- 全流程 `rail.move(5)` 仍在 → 入显影原子(若有 ensure_rail)看到已在 5 → 跳过。

→ **开启即零行为变化**;删字面量是逐工位的独立动作,原语随时接管,可单点 git revert。

## 3. 原语规格

### 3.1 `ensure_rail(target_slot)` 伪码(落在 executor 协调层)

```
async def ensure_rail(target_slot):            # target_slot: 1-6 (原子·分支 rail; None=豁免直接返回)
    if target_slot is None: return
    mm_target = rail_yaml.value(target_slot)    # 槽→mm
    mm_actual, homed = await plc.read_rail_pose()
    if not homed:
        raise Unsafe("地轨未回零, 实际位不可信, 拒绝自动移轨")   # 保守: 未回零不猜
    if abs(mm_actual - mm_target) <= RAIL_TOL_MM:
        return                                  # 幂等: 已在位(含同 mm 异槽), 不动不回家
    robot.require_anchor(P1, ...)               # = rail_move_safe 的安全门; 不在 P1 则失败停流程
    await plc.execute("rail", RAIL_L2_CODE, {"Rail_Target_Position": target_slot})  # L2 安全路径, 等 DONE
```

### 3.2 落点:**executor 协调层**(不是 RobotController)

`move_to_point` 走 `_exec_robot → RobotController`(同步、无 PLC 句柄);`rail.move` 走
`_exec_plc_l2 → PlcController`(异步)。二者不共栈。`ensure_rail` 需**同时握 robot + plc + points**
—— 正是 `ActionExecutor`(已有 `self._robot/_plc/_points`)。故 `ensure_rail` 作为 executor
协调的一个动作(VM 以 `op: call action: rail.ensure` 触发),内部串起 read_rail_pose + require_anchor + rail.move。

> 备选:VM 运行期在执行任一 work 原子前,查该原子·分支 rail(用传入 rack_id/slot 求值)并注入 ensure_rail。
> 更"隐形"但 VM 逻辑更重。**推荐先做显式 `rail.ensure` 动作 + 生成器/编排在原子 enter 注入**,MVP 清晰可测。

### 3.3 rail 目标的派生(单真源)

原子·分支 rail = Win A 校验器已在算的东西:绑 rack_id + slot,走该原子被选中分支的 work 点,取其
(唯一)`point.rail`。把这段从"校验"复用为"求值",即 `atomic_branch_rail(atomic, rack_id, slot)`。
生成器(`gen_robot_point_operations.py`)在原子 enter 注入 `rail.ensure(该值)`;或 VM 运行期求值。

## 4. 分阶段实施(每阶段离线绿 + 指定真机 dry-run)

- **B0 · 读位进运动路径(纯增量)**:executor 暴露 `ensure_rail`;`read_rail_pose` 接入。
  离线单测:mm 差→门+移;mm 同(含 168/168、600/600)→跳;未回零→拒。**不改任何编排**,零行为变化。
- **B1 · 原语关闭态全局开启**:各 work 原子 enter 注入 `rail.ensure(派生 rail)`,**字面量全保留**。
  幂等 → 每次"已在位"跳过 → 离线全套件应仍绿(关闭态验证)。真机:空跑一条转运,确认 ensure 每次跳过、无多余移轨。
- **B2 · 逐工位删 `rail_move_safe` 字面量**:一次一个工位删字面量、依赖 ensure 接管;
  每删一个:`--check`/契约测试改判 + 离线绿 + **真机 dry-run 该工位**。**顺序:先转运血泪区
  (暂存A/货架/收集)→ 上样/刮板/换刀 → feedlift**。持板中途 `rail.move`(显影)**不动**。
- **B3 · 契约/校验翻面**:Win A 校验从"`rail_move_safe(N)` == 点 rail"改为"每 work 原子·分支
  有确定 rail + enter 处 ensure 已注入 + 编排层零 `rail_move_safe`(grep 为空)"。`test_transfer_contract`
  的 `expected_targets`(人肉序列)退役。
- **B4(可选延伸)· 持板中途也收编**:给相关点补 `rail_safe_anchor`,`ensure_rail` 支持非 P1 安全锚,
  逐点真机确认后删对应 `rail.move`。**非首里程碑。**

## 6. 风险与回滚

- **未回零误动** → 原语 `homed` 门控硬拒,不猜(B0 单测覆盖)。
- **首步共享 waypoint 触发时机** → 已定案在 **原子 enter**(臂在 P1)触发,非途中(§2.2)。
- **持板中途被误自动化** → 首里程碑**不碰** `rail.move`;ensure 幂等与之共存;B4 才收编且逐点真机。
- **增量期两套并存** → 幂等使"开启原语"与"删字面量"解耦;每工位删除独立 git revert。
- **read_rail_pose 抖动/读失败** → 读失败/超容差按"未确认在位"处理:走门+移(保守多移一次,不漏移),
  或拒并报错(择一,B0 定);绝不"默默按位1走"。
- **mm 容差取值** → 复用监控侧 `RAIL_STATION_TOL_MM=10`?移轨门用更紧(如 5mm)防"差一点没补到位"。真机定。
