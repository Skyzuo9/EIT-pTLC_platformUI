# 液位检测:固定触发线定前沿 + 标定板 px-mm + 单 ch 录制 —— 实施计划

日期:2026-07-06 · 分支:`codex/ui-upper-next` · 状态:设计已定案,待实施

---

## 0. 一句话

把"液位检测"从"尽力实时量前沿"改成"**用一条预设固定触发线把前沿位置定死**":前沿到线 → 触发排液 → 此刻前沿位置 ≡ 触发线位置(已知常量 D)→ Rf 分母变常量,后端 photoscrape 只量斑点、不盲找前沿,**从根上消除大恒相机"把最高条带误判成溶剂前沿"的病**。附带把 **px-mm 标定(标定板 + QR)** 和 **单通道录制(录制先行,给整套当量尺 + 离线调参地基)** 一并落地。

## 1. 现状(已全栈核实,2026-07-06)

### 1.1 两套检测器,平台当年主动砍掉了"重"的那套

| | 下位机遗留(香橙派 payload) | 上位机现役(host) |
|---|---|---|
| 文件 | `eit_ptlc/driver/water_level_payload/water_level_8ch_compress_mqtt.py` | `eit_ptlc/controller/waterlevel_detector.py` |
| 输出 | **cm 绝对高度** | 无量纲 **面积占比 %** + 辅助前沿线 % |
| 前沿 | Sobel/Canny 边沿 + 逐行 argmax+中位数(`_detect_edge_rowwise` :1233+、`calibrate_with_qr` :698-756) | 湿比廓线跌破 `front_ratio_level`(`_front_position_percent` :255-273) |
| 标定 | **QR px→cm**(`cv2.QRCodeDetector` :367,`scale_factor = tl_bl_real_cm / tl_bl_pixel_length` :750) | 仅 ROI/旋转,**无 mm** |
| 时序 | 到达/离开帧状态机 | 纯无状态、无滤波 |
| 现状 | `--no-detect`,只抓帧 | 生产在跑 |

> 现役检测器 docstring 明写"目标量从绝对高度 cm 改为前沿到达 ROI 百分比","无需 QR 绝对标定 / scale_factor / cm 换算";`waterlevel_store.py` 迁移时**静默丢弃** `scale_factor`/`water_sobely_ksize` 等。本计划**不复活**遗留 cm 状态机,只**新增**一个作用域明确的 `mm_per_px` + 触发线。

### 1.2 三需求 ↔ 代码现实

- **需求 1(参数调试盘)已 ~80%**:`WaterLevelChannel.vue:20-28` 已把 6 个检测参数 + `flow_direction` 做成实时滑块 + 存配置。真缺口:① 旋转角无控件(后端 `set_calibration` 存在、UI 从不调)② 无交互式 ROI 画布(只数值 :163-174)③ 分辨率无关的 `roi_frac` 从 UI 不可达(`update_roi` 每次写都清空 :160)④ 死控件 `reference_y`(前端发、后端丢)。
- **需求 2(QR px-mm + 边沿线)**:遗留 payload 里有**可用实现**,`cv2.QRCodeDetector` 是 OpenCV 自带、**无新依赖**。是"搬回来 + 放哪"的决策。
- **需求 3(单 ch 录制)**:全栈**零实现**,纯绿地。上位机只是转发 MJPEG/JPEG(`water_level_routes.py:183-236`),不落盘。

### 1.3 排液链路现状(需求 2 的消费端)

- 现在"展开完成→排液"是 `develop_execute.yaml:21-33` 里**一道纯人工确认门** → `develop.drain`;液位 `percent`/`front_percent` 目前**纯显示、零控制消费**(唯一消费者是 Web UI)。
- 下游全现成:`develop.drain`(code 50,`plc_develop.yaml:95-105`)→ `Tank_Drain_Enable[tank]`(`plc_controller.py:231-240`)→ 等 `Tank_State=99`;**tank N ↔ channel N 一一对应**。
- **现实约束:PLC 里只有展缸 1、2 真接了排液电池阀 + 气泡传感器**;缸 3–8 只是逻辑存在。近期只能在 2 缸上真跑。
- **待修的接线缺口**:`resource_manager.py:99-123` 只把 active channels 推给香橙派,**没有驱动上位机 detect service**;host detect 自初始化为"已标定通道"。P2 要保证展开中的那一缸 channel 在 host 检测 active 集里。

## 2. 决策脊梁(逐轮定案,勿回退)

1. **mm 是补丁,不替换 %**;% 仍是检测内核(到达判据的原始量)。
2. 溶剂前沿位置由**预设固定触发线**(**帧相对**、一次标定)**定死**,不靠实时找前沿。选帧相对的依据:展缸无硬件限位,板位靠机器人点位复现,用户判断复现性"基本可观"。
3. **D(Rf 前沿距离)= 触发线标定常量(mm)**;photoscrape 只量斑点、在**窄搜索带**里复核前沿当 QC/漂移告警。→ band 误判从根上消失。
4. **band 误判发生在 photoscrape 大恒(展开后整板)**,不在展缸活体——展缸活体阶段板头尚未显影出斑点,判"到没到线"撞不上此病。这正是触发线方案成立的物理前提。
5. px-mm 用**标定板**(一次性插板、**与板面共面**,天然规避贴窗视差);板上 **QR**(尺度 + 4 角单应矫斜视 + 编码**通道号**,治 8 相机同序列号插错)+ mm 网格(肉眼核对触发线 mm)。
6. 展缸相机角色 = **① 前沿到线触发排液 ② 提供 D**;它看不到点样原点/斑点,**算不了整条 Rf**。斑点半边归 photoscrape。
7. **排液自主度:视觉建议 + 人确认 + 超时兜底**(把现有人工门升级成"视觉预判 + 人监督");**达标后逐缸转全自动**(生产形态)。自主权靠 P0 录像 + P2 整定 + photoscrape QC 连续 N 次证明 D 稳来挣。
8. **排期:录制翻到 Phase 0**。理由三叠加:①抢实验时间窗(没录下的展开永远回放不了)②它是 Q4 精度预算(速度/过冲/U 形)的量尺 ③它是离线调参地基(录像喂回检测器,不重跑实验就整定判据)。录**上位机侧、单 ch、640×480@10fps、原始帧 + 每帧时间戳 + 标定 sidecar、为回放而生**。
9. P0 录制触发 = **手动按钮(甲)**;start/stop 抽成内部接口,P3 的自动 per-run(乙)可直接挂。
10. 到达判据对 U 形前沿 = **化成一个旋钮 `f_cross`**:触发线窄带内"湿比 ≥ f_cross"即到达(f→0 首触、0.5 半跨、→1 全跨),取舍变成数据整定;用**局部窄带湿比**(非全局找前沿)本身就绕开误判。

## 3. 目标数据流

```
展缸相机(板头, 640×480@10fps, MJPG) ──/stream/chN──▶ 上位机
   ├─ 录制器(P0):  raw帧 + 时间戳 + 标定快照  →  data/water_level_recordings/{sample|adhoc}/chN_<ts>.avi (+sidecar)
   ├─ detect_level(现役 %)  +  到达判据(P2: 触发带湿比 ≥ f_cross)  →  snapshot.arrived[ch]
   └─ 标定仪式(P1):  插标定板 → QR → mm_per_px + 触发线 row_frac (+可选单应)  →  持久化 per-channel

到达(arrived) ──▶ develop_execute:  [视觉建议 + 人确认(超时兜底)]  ──▶  develop.drain(code50)
                                                              └▶ Tank_Drain_Enable[tank] ─ 等 ─▶ Tank_State=99

photoscrape 大恒(展开后整板) ──▶ 斑点距原点(mm, 现有 plate-width px-mm, vision_quality.py:462-468)
   +  D(触发线标定常量, mm)  +  窄带前沿复核(实测≈D 放行 / 超阈报警)
   ──▶  Rf = 斑点距原点 / D
```

## 4. 分阶段实施

### Phase 0 —— 上位机侧单 ch 原始录制器(现在,赶实验前)

**目标**:实验开始前上线一个能用的手动录制器,采下这批展开过程,并**为回放而生**。

**落点**
- 新增 `eit_ptlc/controller/waterlevel_recorder.py`:内部接口 `start(channel, sample_id=None)` / `stop(channel)` / `status()`。开一条 `http://{orangepi_ip}:{stream_port}/stream/ch{N}?raw=1` 连接(或复用 `water_level_routes.py:207-236` 代理),解 multipart JPEG。
- **落盘免重编码**:帧本就是 MJPG,直写 MJPG-AVI(`cv2.VideoWriter` fourcc `MJPG`,名义 fps 用 `cap_fps`)+ 旁挂 `*.jsonl`(逐帧真实时间戳,因实际 fps 抖动)+ `meta.json`(通道 / sample_id / 分辨率 / **当时标定快照**)。
- 存储:`data/water_level_recordings/{sample_id or 'adhoc'}/ch{N}_{ts}.avi`(可寻址,照 photoscrape case_dir 范式)。
- 新 host cmd(挂到 `_UPPER_CMDS` `water_level_routes.py:37-40` 同款分发):`record_start` / `record_stop` / `record_status`。
- 前端 `WaterLevelChannel.vue`:加"● 录制"开关按钮 + 录制中指示 + 计时;`api.js` 加 `wlRecord*`。

**注意**
- 录制器持流占 `MAX_ACTIVE=8` 一名额(单 ch 无压力),且会重置 grace 计时(反而保活流,符合预期,`mjpeg_streamer.py:69-71`)。
- 10fps 量慢前沿绰绰有余;精度升级(单路 bump 1080p)留 P2/后续,需补"单通道重启换分辨率"(带宽笔记 TODO)。
- **回放地基**:录制输出必须能被一个 `replay(path) -> yield (frame_bgr, ts)` 重新打开,喂进 `detect_level`。

**验收**
- UI 点录制 → 落一个可播放 AVI;能被 OpenCV 重开且逐帧读出;`jsonl` 时间戳齐、`meta.json` 含标定快照;在一次真实展开 run 中录制**不扰动**现有检测/推流/其他通道。

### Phase 1 —— 标定板 px-mm + 触发线可视化设定(顺带补 req1 缺口)

**目标**:一次性标定仪式,得到每通道 `mm_per_px` + 固定触发线,并补齐参数盘的旋转/ROI 画布缺口。

**落点**
- 扩 `ChannelCalibration`(`waterlevel_detector.py:59-91`)新增:`mm_per_px: Optional[float]`、`trigger_row_frac: Optional[float]`(分辨率无关)、可选 `homography`(斜视再启用)。**命名用 `mm_per_px` 与遗留 `scale_factor`(cm/px)显式区隔**。
- 扩 `waterlevel_store.py` `_calib_to_dict`(:52)持久化上述新字段(present-only,兼容旧 JSON);`water_level_calib.json` 无痛加载。
- 移植 `calibrate_with_qr`(遗留 :698-756)到 host:新增 `eit_ptlc/controller/waterlevel_calibrate.py`:`detectAndDecode → 四角排序 → 已知 QR 边长得 mm_per_px → 可选单应/旋转`;解 QR payload → 通道号自校验。
- 新 host cmd:`calibrate_qr`(channel,拍当前帧跑标定、回 mm_per_px + 通道号 + 预览)、`set_trigger_line`(channel,row_frac 或目标 mm)。
- 前端 `WaterLevelChannel.vue`:
  - **标定仪式面板**:插标定板 → 点『识别标定板』→ 显示 `mm_per_px` + 通道号校验 → **拖触发线到目标 mm** → 保存。
  - **最小交互画布(③ 默认)**:live `<img>` 上叠一条**可拖水平触发线** + 显示其 mm(经 mm_per_px)+ 画 ROI 框 + QR 框;**不做自由多边形**。
  - **顺带修 req1 缺口**:加旋转角控件(调既有 `set_calibration`);让 `roi_frac` 可达(改 `update_roi` 不再无脑清 frac,或加 frac 版 ROI 写端);删死控件 `reference_y`。

**注意**
- **共面是生死线**:标定板必须插到**真板位置/景深**(插件天然满足);若日后改回固定标定物,`Δ景深/相机距` 会带来 2–13% 尺度错,直接废 (i)。
- 斜视明显 → 用 QR 四角**单应**,而非单一标量 mm_per_px。

**验收**
- 插标定板 → 标定 → `mm_per_px` 持久化 + 通道号匹配;拖触发线 → mm 读数正确;重载后持久;旋转控件生效;`roi_frac` 往返不丢。

### Phase 2 —— 鲁棒到达判据 + 接排液(用 P0 录像离线整定)

**目标**:把"到线"做鲁棒并接上排液,按"视觉建议 + 人确认 + 超时兜底"落地。

**落点**
- 检测器加**到达判据**:在 `waterlevel_detector.py` 算触发线 `trigger_row_frac` 附近**窄带**(半宽 `trigger_band_halfwidth_frac`)湿比;`arrived = 带湿比 ≥ f_cross`。`LevelResult` 加 `arrived: bool` + `trigger_wet_frac`;`snapshot()`(:223-245)透出 `arrived`。
- **触发区提节拍**:`waterlevel_service.py` `_loop`(:248-260)按前沿逼近程度动态缩短该通道检测周期(0.5fps → 2–5fps),压过冲(带宽笔记的 cadence-boost TODO)。
- **修 RM 接线缺口**:确保展开中的缸 channel 在 host detect active 集(`resource_manager.py:99-123` 现只推香橙派)。
- **消费端接线**:新 VM op/action `develop.wait_front(target_tank, timeout)`,轮询 `snapshot()[tank].arrived`。改 `develop_execute.yaml:21-33`:`develop.wait_front(tank)` → **`human confirm`(带超时自动放行)** → `develop.drain`。
  - **待核/可能扩展**:VM `op: human kind: confirm`(`operation/vm/schema.py`)是否支持 timeout 自动放行;vision 工作曾加过 `reanalyze` human kind,加 `timeout` 属性同理可行。
- **离线整定闭环**:用 P0 录像建 `replay → detect_level(params)` 工具/路由,输出到达帧/过冲量;UI 回放面板或离线脚本调 `f_cross`/带宽/节拍。

**验收**
- sim/replay 中前沿跨触发带 → `arrived` 置位;`develop_execute` 等到它 → 弹超时确认 → 排液;回放一段 P0 录像能复现到达判定并允许改参重跑;缸 1、2 干跑联调通过。

---

### Phase 3 —— photoscrape 窄带前沿 QC + Rf + 面板收尾 +(可选)自动录制/边沿哨兵

**目标**:闭合 Rf,给 D 上 QC/漂移告警,并把 req1 收尾。

**落点**
- photoscrape(`vision_quality.py` / analyze):在**期望 D 附近窄带**测展开后整板前沿(复用现有 plate-width `mm_per_px` :462-468),输出 `D_actual` + 与常量 D 偏差 → 漂移标志。
- Rf 计算:`Rf = 斑点距原点 / D`(D = 触发线标定常量),接进 photoscrape 分析产物。**待核**:Rf 目前是否已在别处计算。
- 面板收尾:清理疑似过时的 passthrough 按钮(`save_calibration`/`restart_camera`/`reload_config`,真源已在上位机);补齐 req1 剩余缺口。
- **可选**:自动 per-run 录制(乙)—— 经 P0 内部接口挂 develop run 生命周期;板头边沿线哨兵作 per-run 漂移预警。
- **自主度晋级**:攒 N 次 D 稳定报告,逐缸把"人确认"提为"全自动 + 人 override"。

**验收**
- 展开后整板前沿 QC 出 `D_actual` + 漂移告警;Rf 用常量 D + 斑点距算出;产出 N-run 稳定性报告以支撑逐缸转全自动。

## 5. 风险与未决

| 项 | 说明 | 归属 |
|---|---|---|
| 速度/过冲/U 形无数据 | 精度预算(D 误差 vs Rf 容差)是这批实验的产出物;P0 就是为此采数 | P0→P2 |
| 只有缸 1、2 有硬件 | 排液电池阀 + 气泡传感器仅展缸 1、2;近期真跑限 2 缸 | 全程 |
| 共面/视差 | 标定板必须插到真板景深;贴窗会带 2–13% 尺度错 | P1 |
| 斜视 | 若板头非正对,单标量 mm_per_px 不够 → 用 QR 四角单应 | P1 |
| human timeout | VM confirm 超时自动放行可能需扩 schema | P2 |
| RM 未驱动 detect service | host detect 自初始化 active 集,未随缸占用被 RM 再驱动;需在 P2 保证展开缸 channel 在检测 active 集 | P2 |
| 单通道换分辨率未建 | 录制/检测想单路上 1080p 需补 `restart_capture(w,h)` + per-channel 分辨率 | 后续 |
| Rf 落点 | Rf 是否已在别处算、放哪合适 | P3 待核 |
