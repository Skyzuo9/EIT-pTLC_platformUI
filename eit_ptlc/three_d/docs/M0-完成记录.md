## 过程中解决的四个关键问题

1. **OCCT 打不开中文路径** —— 报 `Cannot open input file`. C++ 层在 Windows 上按
   ANSI 代码页解析路径. 解决: 中间产物文件名一律 slug 化为 ASCII.

2. **STEP 里的中文是裸 cp936 字节**, 不是标准的 `\X2\` 转义, OCCT 解析成乱码.
   解决: 01 步解码后转拼音, 中文原名存入 names.csv.

3. **GLB 节点全叫 `NAUO1234`(最关键)** —— SolidWorks 写出的装配实例 name 字段是空白,
   OCCT 只好退回用 id 命名, 2270 个节点 100% 无语义, 删减/材质/绑定规则会全部失效.
   解决: 01 步顺着 `NAUO.related → PRODUCT_DEFINITION → ..._FORMATION → PRODUCT`
   把真实零件名回填到 name 字段. 整机回填 1605 个实例, 0 个未解析,
   语义命名占比从 0% 升到 80.9%(剩余 19.1% 是供应商目录件, 原图纸里就没名字).

4. **前端包围盒被量化压缩撑大** —— `Box3.setFromObject` 默认快速模式把量化立方体
   当作几何体范围, 把整机报成 4.01×3.64×3.98 m, 相机被迫拉远近一倍.
   解决: 改用精确模式(逐顶点), 只在加载时算一次.

另修复一处自造 bug: 删减的尺寸阈值单位换算写反, 曾把 6 mm 当成 6 m,
一次性删掉 94% 的网格.
