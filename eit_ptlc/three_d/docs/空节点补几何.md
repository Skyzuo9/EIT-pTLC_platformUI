# 空节点补几何(装配导出丢件的通用修法)

2026-08-02 立档。起因:用户发现孪生里上样模块少了两个"轴承"(同步带惰轮),
而 SolidWorks 里那两个件并不缺。

## 现象与根因

SolidWorks XR(glTF)导出器在**装配**上下文对个别零件只写出带变换的空节点、
不给网格;同一个零件**单件导出**却完全正常。空节点一路传到 04 步,被当作无几何
节点剪掉,零件就在孪生里彻底消失了。

实测证据(EBF41-S3M150-25-B-P-d5,上样抽液机构两条同步带的惰轮):

| 导出方式 | 结果 |
|---|---|
| 单件导出该 SLDPRT | 完整轮子:1 mesh / 4844 面 / 28×29×28 mm |
| 子装配 `抽液机构总装` 导出 | 该件是空节点;同装配的 EVD21 正常有 mesh |
| 整机 `TLC设备总装` 导出 | 同样空节点 |

该零件是 **0 实体 + 3 曲面体**(STEP 导入遗留,特征树三条"曲面-输入"),
而导出正常的对照件 EVD21 是 1 实体。曾尝试用 `InsertSewRefSurface` 把曲面缝成
实体(真实签名是 5 参:`UseGapFilters, TryToFormSolid, MergeEntities,
KnitTolerance, MaxValueForGapRange`),三组参数都没能形成实体,故走"单件素材补回"。

**排查时的三个坑**,再遇到同类问题可直接跳过:
1. 别一看到"0 实体 + N 曲面"就断定是零件坏了 —— 单件导出证明几何完好,
   改零件是南辕北辙(本案差点就去缝合并保存用户 CAD)。而且"纯曲面"也不是判据:
   后来批量体检发现有实体的零件同样会在装配导出里变空节点。
2. XR 导出器插件接口(`ISWXRExporter`)没有任何导出选项属性,
   没有"导出曲面体"之类的开关可调。
3. **单件导出的输出路径含非 ASCII 字符时,`SaveAs` 会静默失败** ——
   返回 `ok=True`、`errors=0`,却根本不写文件,耗时只有 0.1~0.6 秒
   (成功时 2~3 秒)。2026-08-02 批量导出 24 个素材,20 个栽在这上面,
   一度误判成"这些零件本身没有几何";换成 ASCII 名后 24 个全部成功。
   `export_part_assets.py` 已加断言拦截。素材名走拼音 slug,`node_prefix`
   仍用原始中文节点名,两者解耦互不影响。

## 修法

`03_clean_model` 在 prune/赋材质/合并**之前**跑 `restore_missing_geometry`:
用单件导出的 GLB 素材,把几何补回空节点位置。

对位天然成立:素材几何在零件原点坐标系(单件 GLB 根变换是单位阵),
空节点保留着完整的装配变换;把素材挂到空节点下、局部变换取单位阵,
世界位姿就与零件正常导出时一致。

补进来的对象**继承空节点的名字并取代它**(不是做成子节点),
所以下游按名字工作的一切(materials 规则 / part_overrides / rig_map 滑车成员)
与"零件本来就导出成功"时完全同构,不需要开特例。

### 加一个件的步骤

1. 在 `pipeline.yaml` 的 `restore_geometry` 加一条(三个字段都必填):
   ```yaml
   - node_prefix: "零件名-1"              # 匹配 GLB 里的空节点名(会剥掉 .001 后缀)
     part_glb: "exports/parts/xxx.glb"    # 相对 three_d 根, **必须纯 ASCII**
     source_part: "E:/…/xxx.SLDPRT"       # 素材由谁导出, 保证可复现
     note: "为什么补它"
   ```
   `node_prefix` 要写到能唯一区分的长度 —— 供应商件名极易互为前缀
   (`…133.1.1.1.1-1` vs `…133.1.1.1.10-1`),带上实例号 `-N` 即可。
   写串了会给零件套上别人的几何,`restore_missing_geometry` 有冲突预检会直接报错。
2. `python export_part_assets.py` 生成素材(已存在的跳过,`--force` 强制重导)。
   它会校验素材里确实有网格,没有就报错(单件导出也拿不到几何 = 该零件另有问题)。
3. 重跑 `03 → 04`,按六文件清单部署。

## 防复发

`00_export_gltf` 每次导出后扫描空叶节点(无 mesh 且无子节点的具名节点),
与 `pipeline.yaml` 的 `export_gate.expected_empty_nodes` 白名单做差集,
有白名单外的就**报错退出**并把完整名单写进 `work/00_export_gltf.report.json`。
白名单只放"确认有意隐藏/压缩"的件。临时放行用 `--no-gate`。
